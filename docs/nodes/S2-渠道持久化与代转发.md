## 一、目标（需求四问）

① 谁用：注册登录后的画布用户——在配置页录入自己的渠道 key，换设备/换浏览器登录后配置还在。
② 痛点卡在哪：现在渠道配置存浏览器 localStorage，换设备即丢、清缓存即丢。
③ 做成的判据：换设备登录→渠道配置完整出现；盘上/接口零明文 key；生成请求走服务端代转发成功。
④ 与现状关系：替代「localStorage 持久化」这一步，store 结构与 action 签名不动。

## 二、改点清单

### B1 后端：渠道存储 + 加密（wanrepro/ui/）
1. 新模块 `channel_store.py`：SQLite 表 `user_channels(id TEXT PRIMARY KEY, user_id INTEGER NOT NULL REFERENCES users(id), name TEXT NOT NULL, base_url TEXT NOT NULL, api_key_enc BLOB, api_format TEXT NOT NULL, models_json TEXT, updated_at INTEGER, UNIQUE(user_id, name))`；WAL+busy_timeout+foreign_keys=ON（沿用 multiuser 惯例）。id 由**客户端生成原样保存**（审计 B-11：nanoid 已嵌进模型引用串 `channelId::model`，服务端不得重发自己的 id）。user_id 解析：`_session_user` 只回 username，需补 username→user_id 助手（审计 IF-1）。PUT 全量替换包 `BEGIN IMMEDIATE` 事务（IF-2）。
2. AES-GCM 加密（`cryptography` 库）：主密钥从 env `WANREPRO_CHANNEL_KEY`（base64 32 字节，systemd EnvironmentFile 注入）读取；**校验时机（审计 B-03）：`MULTI_USER=1` 且首次访问渠道路由时校验，缺失→503+明确报错文案；`MULTI_USER=0` 不 import cryptography、不读该 env**（单人包/S0 生产位零依赖）。密文格式 `[1字节版本=1][12B nonce][ciphertext+16B tag]`（版本=密钥版本，轮换语义后置）。读接口零回显（GET channels 返回 masked `***last4`）。
3. CRUD 路由：`GET/PUT/DELETE /api/user/channels`（登录态必需，未登录 401）。**HTTP verb 基建（审计 B-02 实证）：server.py 现无 do_PUT、dispatch 非 GET 一律进 route_post（L2173-2184）——B1 必须新增 `do_PUT` + dispatch 加 PUT 分支 + do_OPTIONS Allow-Methods 补 PUT**；未登录 PUT/DELETE 一律 401 非 404/405。`PUT` 全量替换该用户渠道集（与前端 store 整体保存语义对齐）。**masked 回写护栏（路B BL-1=路A B-01 同雷）**：PUT 时某渠道 `api_key` 为空或缺省或等于本用户当前 masked 值 → 按 id+name+baseUrl 匹配保留原密文不覆盖；不匹配且非新明文 → 该渠道 422「请重新输入完整 API Key」。判据 V1 补反向断言：只改渠道名保存→服务端密文不变。
4. SSRF 校验（审计 B-04 收严）：**删除 localhost 例外**——服务端代转发渠道一律 https 且解析 IP 拒绝 loopback/私网/link-local/保留段（含 IPv6）；`wan` 型渠道（万相 CLI bridge，本就零 key 同源）**不入服务端渠道表**，CRUD 拒绝保存（标 localOnly）；**解析一次→按该 IP 连接**（DNS rebinding TOCTOU，IF-7）；代转发前重验按最小实现（单实例形态，IF-11）。
5. 单人回归（审计 B-12 收紧）：`MULTI_USER=0` 时 `GET/PUT/DELETE /api/user/channels`、`POST/GET /api/proxy/*` 全部 404——**扩展现有探针 `test_multiuser_s1.py` 断言清单**（现只覆盖 /api/auth/*，不扩则 V8 恒真）；bootstrap-config 断言用 schema/行为等价（逐字节不可测，方案 v2 §〇 已判定）；**无 WANREPRO_CHANNEL_KEY 时 MULTI_USER=0 启动成功**（B-03 回归断言）。

### B2 后端：代转发端点
1. `POST/GET /api/proxy/<channelId>/<path>`：登录态校验 → 查**该用户**渠道表（他人 channelId=404，不泄露存在性）→ 取 baseUrl 拼 path → 注入 `Authorization: Bearer <key>`（gemini 型注入 `?key=`）→ 转发。**请求头白名单（审计 B-05 防会话外泄）：只透传 Content-Type/Accept/Accept-Encoding/自定义业务头；强制剥离 Cookie/Origin/Referer/Host/X-Forwarded-*/X-Real-IP**（wan_session 是 HttpOnly 但仍随请求头外发，剥头才能保 S1 会话令牌不外泄给第三方渠道）。禁重定向用显式 no-redirect opener（3xx 原样透传）。
2. SSE 保真：不设 Content-Length、按块 read+write+flush、剥 hop-by-hop 头、客户端断连时关闭上游连接；HTTP/1.1 keep-alive 下必须 `Transfer-Encoding: chunked` 或 `Connection: close`（IF-4：send_body 恒发 Content-Length 会挂死流）。
3. 防护（初值，B4 实测调）：请求体 8MB、上游超时 120s、单用户并发 2；服务 socket 加读超时（IF-8：daemon_threads 无超时，慢客户端堆线程）。
4. 日志（审计 IF-5+B-05）：override `log_request/log_message`（基线 log_message 打完整 self.path 含 query，不覆写 V10 恒假）；只记 时间/方法/channelId/上游状态/耗时；**不记 URL query、不记任何 key/Authorization**。

### B3 前端：persist 层改造（store 结构/action 签名不动）
1. `channelMode` **复用既有 `"remote"` 语义**承载服务端模式（审计 B-08 实证：类型是 `"remote" | "local"`，`"server"` 不存在；新建枚举值=改结构违反本批承诺）；连带改消费点 `model-picker.tsx:36/59` 的 `=== "local"` 判断；单人模式 model-picker 行为与基线 diff 为空。登录态来源：bootstrap 期先查 `/api/auth/me`。
2. **启动门（审计 B-07）：main.tsx 渲染前先 await `/api/auth/me` + 服务端 channels，再 hydrate**（persist merge 是同步函数，网络是异步，无门必闪现）——判据：首帧即为 remote 模式、无本地渠道闪现。已登录时 channels 变更 → subscribe+debounce PUT；beforeunload flush。
3. 一次性迁移（审计 B-09 补 bootstrap 踩踏 + 路B BL-2 冲突规则）：登录成功后先 GET——服务端非空 → 丢弃本地缓存不迁移；服务端为空 → 才迁移，**且只迁移用户本地已有、带非空 key 的渠道项**（bootstrap 预置灌入的无 key 渠道不得上服务端）；server 模式登出态不拉 bootstrap；迁移完成后本地键永久降级缓存。V6 断言补：预置渠道不得出现在服务端 GET 结果里。
4. 渲染门控：迁移/首次 GET 完成前，配置页不得以本地陈旧数据完成首次可交互渲染（loading 态挂起）。
5. 请求层改造（审计 B-06 扩面）：①生成请求 4 文件（image/video/audio/model-plugin）改发 channelId+模型名到 `/api/proxy/...`；②**模型列表拉取 `fetchImageModels`（image.ts:859-884 key 直连上游）改走 `GET /api/proxy/<channelId>/models`**；③**自定义脚本渠道（model-plugin.ts 脚本执行器把 apiKey 交给用户脚本自行 fetch，约 30 处模板）服务端模式明确不支持**：配置页提示「自定义脚本渠道仅本地模式可用」，服务端模式下该渠道置灰（降级形态 B4 验收清单列明）；④`isAiConfigReady` key 非空检查按模式豁免；⑤非渠道请求（image-storage/file-storage）不得误路由。

## 五、边界（不做）

- 积分计费/平台统一渠道（B 阶段）
- 渠道密钥轮换 UI（密文版本字段已预留，语义后置：版本 1=当前主密钥）
- Agent 多租户（一期砍掉）
- bootstrap 预置升级（方案 v2 line 68）→ 本批不做，S3 或 S4 另立；server 模式登出态不拉 bootstrap（B3.3 已定）
- :8780 转 systemd（S2 部署批次顺手做，不算独立批）
- **S1 既有进程内状态（限速/FAILURES 字典）不参与本批**：实现者不得顺手改 multiuser.py 的 S1 逻辑（防 S1 回归）
