# S2.5 任务书 · UI 门控收尾（本地代理隐藏 + Agent 入口门控）

> 状态：v1.0（2026-11-16 所有者 Notion 需求页拍板后落盘）
> 上游依据：`docs/方案-画布多用户SaaS一期-20261116-v2.md`（Agent 一期砍掉）+ 所有者 2026-11-16 拍板四条
> 适配包红线：不可验收的禁交；说明与界面逐条一致

## 一、目标

S2 请求层已把登录用户的生成请求全部接管到服务端代转发（`/api/proxy/<channelId>`），但 UI 上两个**单机时代的门**还挂在那里，造成语义混乱：

1. 配置页「本地代理」开关（canvas-proxy :23210）——登录态下开了它也没用（key 不在浏览器，直连不通），纯误导；
2. 侧边「连接本地 Agent」面板（canvas-agent :17371）——一期范围明确砍掉 Agent，登录用户不应看到这个入口。

本批只做 **UI 门控**，零请求层逻辑改动。

## 二、改动点（B1 单批）

> 依据核实（2026-11-16）：方案 v2 §38/§104「Agent 多租户一期砍掉（canvas-agent 保持本地单人形态）」；multiuser.py 现有 `users` 表**无 role 列**、`/api/auth/me`（L126-129）只返回 username/expiresAt——is_admin 需加列+改 me 返回，属 S1 文件最小扩展。

### B1.1 本地代理开关登录态门控

- 位置：配置页「本地代理」tab（设置弹窗内，tab 名含「本地代理」）。
- 行为：**已登录（remote 模式）** 时——
  - 开关整体不可用（置灰或隐藏整个 tab 内容），替换为一条提示：「已登录用户由服务器代理接管网络请求，无需本地代理。」
  - i18n：zh-CN / en-US 各加一条文案。
- **未登录/单人模式（local 模式）**：行为与现状逐字节一致，零改动。

### B1.2 侧边 Agent 入口登录态门控

- 位置：画布右侧 Agent 面板入口（顶栏 Agent 按钮及「连接本地 Agent」面板）。
- 行为：
  - 普通登录用户 + 未登录访客：**隐藏入口**（按钮不渲染，而非渲染后禁用）。
  - **管理员账号可见**（保留 owner 自用通道）：判定方式复用 S1 会话机制——`/api/auth/me` 返回中增加 `is_admin` 字段（owner / owner2 两个种子账号为 admin，见 multiuser.py 现有 users 表 role 字段；若表无 role 列则加列+默认 0，属 S1 文件的最小扩展，须在报告里单独列出）。
- **单人模式（MULTI_USER=0）**：Agent 入口行为与现状完全一致，零改动（单人模式 Agent 是原有功能）。

### B1.3 探针

- 后端探针（tests/test_multiuser_s1.py）扩展：
  - `/api/auth/me` 对 admin 账号返回 `is_admin:true`、普通账号 `is_admin:false`、未登录 401；
  - 既有 29 条不破坏。
- 前端探针（probe-s2-b3-channel-sync.mjs 或新文件）扩展：
  - remote 模式下本地代理开关渲染为不可用态 + 提示文案存在；
  - local 模式下开关结构与基线一致；
  - Agent 入口按 is_admin 三态（admin 可见/普通用户隐藏/未登录隐藏）。
- vite build EXIT=0、既有测试全绿。
