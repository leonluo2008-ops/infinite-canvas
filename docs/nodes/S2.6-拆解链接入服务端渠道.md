# S2.6 任务书 · 拆解/SDGF 链接入服务端渠道（消灭服务器单租户密钥体系）

> 状态：v1.0（2026-11-16 所有者拍板立项：拆解拉片必须与画布同管线、用户用自己渠道；服务端直连不经 /api/proxy 自环——所有者原话「基本上所有的后端服务都在服务器上处理」）
> 上游排查：2026-11-16 拉片「缺密钥 JXIN_API_KEY」事故复盘（见 Hindsight + 适配包）
> 红线：单人模式零改动；零兜底（FAIL 如实）；写/审分离

## 一、问题定义

服务器侧吃密钥的链路有两套来源，多租户下语义分裂：

| 链路 | 现状来源 | 问题 |
|---|---|---|
| 拆解/拉片（`/api/lapian/run` → analyze.py 子进程链） | 前端带 `channel{baseUrl,key,model}`（lapian-model.ts:94）**或**服务器 env `JXIN_API_KEY`（extract.py load_api_key 四级回退） | remote 模式前端 apiKey 只有 masked `***last4`：带上去上游必失败→前端防御分支丢弃→回落 env 单租户 key；:8780 无该 env 时直接「缺密钥」退出 2 |
| SDGF 视频提交（server.py:1235 `sdgf_create`） | 前端请求体 `channel.apiKey` | 同一 masked 问题：remote 用户提交必失败 |

目标语义：**登录用户的一切 AI 调用（画布生成/拆解/SDGF 视频）都用自己渠道的 key**；服务器 env 密钥降级为未登录单人模式的默认。前端零 key（连 masked 都不带），服务端解密。

## 二、改动点

### B1.1 拆解链渠道解析服务端化

- `/api/lapian/run` 请求体：前端改传 `channelId`（+可选 `model`），**不再传 key/baseUrl**（保留旧字段解析以兼容单人模式？→ 不：单人模式前端根本不登录、走的是 localStorage 明文渠道，请求体形状不变；remote 模式才传 channelId。服务端按「有无 channelId」分流）。
- server.py `_analyze` 渠道提取（L3345 `_analyze_channel_args`）：新增分支——payload 带 `channelId` 且 MULTI_USER=1 且登录态 → `channel_store` 查**该用户**渠道（他人 channelId=404 同形，复用 B2 的查询函数）→ 解密 key（复用 `decrypt`）→ 组装子进程 env `{JXIN_API_KEY: key}` + argv（baseUrl/model）。channelId 查不到/未登录带 channelId → 404/401，**零兜底**（不静默回落 env）。
- env fallback 语义保持：无 channelId（单人模式/旧客户端）→ 现行为逐字节一致（前端带 key 用带 key 的，否则 env）。

### B1.2 SDGF 提交链同构改造

- `/api/sdgf/video/run`（server.py:1235 一带）：payload 带 `channelId` → 服务端解密注入 `sdgf_create/sdgf_query`；key 不回显不落日志（复用 V10 遮蔽口径）。
- preflight（server.py:1225 preflight 函数）同改：channelId 分支下 key 校验改为「渠道存在且有密文」，不再要求前端带明文。

### B1.3 前端

- `lapian-model.ts buildLapianRunBody`：remote 模式（channelMode==='remote' 或渠道项 key 为 masked/空）→ 请求体改 `{channelId, model}`；local 模式保持现状（带明文 key）逐字节不变。
- SDGF 提交点（video.ts 或其调用方）：同规则。
- 防御分支更新：remote 下不再因「无 key」丢渠道。

### B1.4 探针

后端（test_multiuser_s1.py 扩展，33 条不破）：
- 登录用户带 channelId 拆解：解密 key 注入子进程（echo 上游夹具回显收到的 key 与录入一致）、baseUrl/model 透传；
- 他人 channelId → 404 同形；未登录带 channelId → 401；
- 无 channelId 单人请求 → 现行为一致（env key 生效路径不回归）；
- SDGF：channelId 分支 preflight 通过/提交成功；日志零 key（V10 口径）。

前端（新 probe 或扩 ui-gating）：remote/local 双态请求体形状断言；masked 防御不再误丢。

## 四、边界与红线

- **不动**：automation 引擎本体（analyze.py/pipeline/reverse/* 只认环境变量，天然兼容——key 注入点在 server.py 侧）、channel_store 的加密/CRUD、S2.5 门控。
- **单人模式**：无 channelId 请求路径与基线逐字节一致（判据 W3 硬门）。
- 服务器 env `JXIN_API_KEY` **保留**（单人模式默认 + 运维兜底），但从多用户链路中消失。
- 不 commit 不 push，改动留工作区待主 agent 亲验后统一提交。
- 完成后部署 :8780，所有者验收动线：owner 登录→选自己渠道的模型跑拉片→成功；渠道页删掉 key 再跑→明确报错（零兜底）。
