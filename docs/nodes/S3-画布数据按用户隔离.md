> v1.0 双路审计：路A（安全/数据完整性，6 BLOCKING）+ 路B（前端可执行性，4 BLOCKING），合并后核心定调：**传输合同从「整集 PUT + 服务端权威」改判「逐项目 PUT + 合并墓碑 + 本地缓存无条件优先」**——v1.0 的「服务端非空即丢弃本地」在画布场景=设计级数据丢失（离线一小时白画），路A 判「照 v1.0 开工即不可行」。

## 一、问题定义（现状，已亲验）

登录用户画布项目（projects/deletedProjects）在各设备浏览器 localForage，键 `infinite-canvas:canvas_store`，400ms 防抖全量序列化 + flushProjects（canvas-persist-queue.ts）。换设备/清浏览器即丢。一期目标：登录用户画布项目服务端持久化、按 user_id 隔离、换设备还在。**不做**：协同/共享/实时合并（接受 last-write-wins per project）；任务产物（analysis/uploads）一期不做隔离（共享区，读取端点已有归属校验——路A 澄清：归属校验只做 user_id 维度，不做 project_id 维度）。

## 二、核心合同（v1.1 重写，吸收 BL-1/BL-2/BL-3/BL-6/路B BL-B1~B3）

### 2.1 传输合同：逐项目增量 + 墓碑（推翻 v1.0 整集 PUT）

- `GET /api/user/projects` → **清单**（id/name/updatedAt/deleted/bytes 元数据，不含 content——首屏 KB 级）
- `GET /api/user/projects/<id>` → 单项目 content（打开项目时按需拉）
- `PUT /api/user/projects/<id>` → 单项目 upsert（body=content+updatedAt），服务端单行 `INSERT ... ON CONFLICT(id,user_id) DO UPDATE`
- `DELETE /api/user/projects/<id>` → 写**墓碑行**（deleted=1 + deletedAt），不物理删
- 归属校验：全部单语句 `WHERE id=? AND user_id=?`，他人 id 与不存在**逐字节同形 404**（禁先查存在再判归属——时序侧信道硬约束）
- 并发：请求带 `baseUpdatedAt`，服务端 updated_at 更新 → 409 + 返回服务端版本；前端复用 **`app-sync.ts mergeCanvasData` 既有语义**（逐项目 updatedAt 取新 + 墓碑 deletedAt 优先，project.updatedAt > deletedAt 可复活）——**不新造合并逻辑（红线 25）**
- 体积上限：单项目 content 8MB（超 413 + 前端可见错误走 lastFlush 通道）；每用户配额一期不定（写明「不做，风险为磁盘」+ SQLite VACUUM 策略一期不做）
- **时间戳域（v1.2 补，B1 审计 BL1/BL2 定案）**：updatedAt / baseUpdatedAt / deletedAt / version / maxUpdatedAt / serverTime 统一 **int epoch 毫秒**；服务端拒收 <1e11（秒级）或 >4e15（越界）的值 → 422，**不做单位归一猜测**（零兜底）；DELETE 必带客户端 deletedAt（ms），缺失/非法 422，服务端不代填；前端 B2 负责 ISO↔ms 转换（store 既有模型是 ISO 字符串）；GET 清单回 `unit:"ms"` 供前端自证
- **删除时序 clamp（v1.2 补，复审 residual 定案）**：「旧设备 PUT 不复活」只在 deletedAt ≥ updatedAt 时成立，窗口宽度=两设备时钟差。B2 侧发起删除时 clamp `deletedAt = max(Date.now(), project.updatedAt)`；服务端规则不动

### 2.2 写路径：本地缓存无条件优先 + dirty 补推（推翻「服务端权威丢弃本地」）

- **写穿双写**：storage.setItem → ① localForage 立写（key 与信封不变，崩溃保护语义保持）→ ② 防抖后逐项目 PUT（按 project.id 分桶计时器，400ms 不变）
- **dirty 持久化**：缓存载荷增 `dirtyIds`（待推项目 id + updatedAt），落盘；PUT 失败保留 dirty，`online` 事件 + 启动时补推
- **启动合并顺序**（禁「非空即丢弃」）：读缓存 → GET 服务端清单 → 逐项目合并（dirty 本地优先补推；非 dirty 服务端为准；墓碑按 mergeCanvasData 语义）
- **卸载兜底**（keepalive 64KB 上限对 MB 级不可用，禁 keepalive PUT）：`visibilitychange:hidden`/`pagehide` 同步写 localForage 缓存 + 标 dirty，下次启动补推；**删除 beforeunload PUT 交付项**
- 断网判据 **V8**：断网画 10 分钟→关标签→重连开页，改动必须还在

### 2.3 时序合同（吸收路A BL-3：store 先于启动门 import 的双 hydrate 问题）

- persistQueue storage 变可变 indirection：`setTransport(storage)` + `rehydrate(mode)`
- 启动门内完成：GET 清单 → setTransport(remote) → 用合并结果 prime 基线 → 才开启 debounce PUT
- 硬约束：启动门返回前 store 不接受任何远端 setItem；判据加「首帧前零 PUT」（探针抓请求序）
- 启动门超时（共享总预算 8s，projects 与 channels **并行** Promise.all 非串行）：超时**不退 local 模式**（那是 BL-2 丢失路径）——进入「离线态」：本地缓存可写+dirty 补推+顶栏可见「离线，改动将在联网后同步」

### 2.4 迁移与跨账号（吸收路A BL-4）

- 本地缓存载荷加 `owner`（服务端下发的 username）+ `migratedAt`
- 迁移仅当「本地无 owner 标记」；owner 不一致**绝不自动迁**——登录后弹「检测到本机 N 个项目来自其他账号，导入到当前账号？」显式确认
- logout 清空 localForage 键（或改键 `canvas_store:guest`）
- 迁移载荷含 deletedProjects（墓碑一并上服务端，防软删复活）
- 判据 **V9**：A 登录画项目→退出→B 注册登录→B 账号项目数 0

### 2.5 单人模式零改动（三处不可动 + 探针口径）

1. persistQueue 400ms 防抖与引用级去重不动
2. flushProjects 返回契约 `{ok,written,bytes,error}` 不动（workflow-instance-run.ts:505 依赖）
3. localForage key `infinite-canvas:canvas_store` 与 `{state,version}` 信封不动（6 个既有 ego 探针直接读写该键，V7 依赖不红）
- channelMode 判定用模块级注入 getter，单人/探活失败恒 'local'——local 分支逐字节一致
- localforage 的 localStorage 兜底（5MB 配额）在 remote 模式跳过
- WebDAV 同步（app-sync applyData replaceProjects）与 S3 并存时：**remote 模式禁用 WebDAV 项目同步**（两真源冲突），方案明示
