# 小看板 · S3.11-B3 成片下载 `__abs=1`（非 wan 视频链）

> 父方案：`docs/方案-S3.11-视频链单机版移植-20261118.md` v1.2 §九
> 基准：单机版 v1.2.0「同源素材走本机代理、异源素材直连」
> 前置：W0（wan 在 MULTI_USER=1 下 404、sdgf 鉴权）已落地并验证

## 要修的真缺陷

渠道 baseUrl 自带路径（最常见 `https://host/v1`）时，上游返回的成片直链是 `https://host/files/a.mp4`（路径**不含** `/v1`）：

1. 前端 `channelMediaUrl` → `channelProxyUrl` → `stripBasePath` 只裁「pathname 以 basePath 开头」的情况 → subpath 原样 `/files/a.mp4`；
2. 服务端 `channel_store.py:738`（`_forward`）**无条件** `target = (base.path.rstrip("/") + "/" + subpath.lstrip("/")) or "/"` → 上游收到 `/v1/files/a.mp4` → **404**（行号会随改动漂移，认函数 + 这条表达式）；
3. 前端拿不到 blob → 回落同一代理地址给 `<video>` → 播放同样 404 → 用户看到「视频生成失败」。

单机版没有此问题（直连裸地址 / 本机通用代理）。

## 四个原子步

| # | 文件 | 改动 |
|---|---|---|
| 1 | `web/src/services/api/channel-proxy.ts` | `channelMediaUrl` 三分法定版：**同 host**（成片 host == baseUrl host）→ 产出 `/api/proxy/<cid>/<完整 pathname>?__abs=1`（保留原 query 中非凭据参数）；**异 host** → 裸 URL 直连、不经代理；**自含凭据**（`?key=` 等）→ 先剥凭据再按上两条走 |
| 2 | `wanrepro/ui/channel_store.py` `_forward` | 读 query 里的 `__abs`：为 `1` 且方法为 GET → `target = subpath`（**跳过** `base.path` 拼接）；其余情况保持现状（逐字节不变）；转发上游前把 `__abs` 从 query 剔除；`__abs` 只对 GET 生效（POST/PUT 一律忽略，避免借此写任意路径） |
| 3 | `web/scripts/probe-s3-11-media.mjs`（新建） | 至少 5 条断言：① baseUrl `https://h/v1` + 成片 `https://h/files/a.mp4` → `/api/proxy/<cid>/files/a.mp4?__abs=1`；② 同 host 带 `?key=xxx` → 凭据被剥且仍带 `__abs=1`；③ 异 host `https://cdn.x/a.mp4` → 原样直连、无 `/api/proxy`；④ 无 channelId → 抛错；⑤ 既有非媒体调用（`channelApiUrl(config,"/models")`）产出不含 `__abs` |
| 4 | `wanrepro/tests/test_multiuser_s1.py` | 新增后端断言：渠道 baseUrl = `PUB_IP + "/v1"`，`GET /api/proxy/<cid>/files/a.mp4?__abs=1` → `_Echo` 收到 **`/files/a.mp4`**（非 `/v1/files/a.mp4`），且收到的 query 不含 `__abs`；再补一条 `POST ...?__abs=1` → 仍按 `base.path` 拼（flag 对非 GET 无效） |

## 判据

- V1 上游收到 `/files/a.mp4`（探针 + 后端 echo 双侧）
- V2 异 host 直连
- V3 `probe-s3-7-proxy-url` 9/9、后端全量（W0 后基线 77/77 + 本批 +2 = 79/79）、web tests 15/15、solo-diff 484B 一致
- V4 部署 `:8780` 后，用一个 `baseUrl` 带 `/v1` 的自建渠道（假 key）打 `GET /api/proxy/<cid>/anything?__abs=1`，上游 401/404 由上游自己返回（证明路径没被改写成 `/v1/anything`）

## 风险

1. `__abs` 让登录用户可在**自己渠道 host** 上访问 `base.path` 之外的路径（如 `/admin`）——host 本就是用户自己的渠道，且仍走 https-only + SSRF + IP pin，风险可接受；仅 GET 生效进一步收口。
2. 异 host 直连会遇到 CORS：拿不到 blob 时按单机版行为回落 URL 播放，不算失败。
3. 不改 `/api/proxy` 的既有相对路径合同，S3.7 九条断言必须保持全绿。
