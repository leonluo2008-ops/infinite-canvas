## 4. 嫌疑回归清单（按可能性排序）

1. **wan（万相 bridge）视频在 SaaS 登录态整链被禁死**
   - 代码：dev use-config-store.ts:225-227 `if (config.channelMode === "remote") return match.channel.apiFormat !== "wan" && ...`；channel_store.py:363-367 对 wan 渠道 PUT 直接 422「只能在本地模式使用」；channel-sync.ts:178-183 `isLocalOnlyChannel` 把 wan 挡出候选。
   - 单机版：wan 是零 key 同源 bridge，v1.2.0 完整可用（video.ts:327-443）。
   - dev 破坏方式：登录态（remote）下 wan 渠道模型永不就绪、也无法保存到服务端渠道表；未登录单机态不受影响。
   - 判定：若 SaaS 要求「登录用户也能用服务器本机 wan bridge 生成视频」，这是最高优先回归；若所有者接受 wan 仅限本地模式，则为设计决策。
   - 最小验证（不花钱）：登录 SaaS → 选 wan 渠道视频模型 → 点生成，预期被 ensureReady 拦（「请先配置」类错误）；或 `curl -X PUT .../api/user/channels -d '{"channels":[{"id":"w1","name":"wan","baseUrl":"http://127.0.0.1:8779","apiFormat":"wan","models":[]}]}'` 预期 422。

2. ~~:8780 未监听~~ **已驳回（主 agent 复核实测）**：`:8780` 在**远端** `100.126.167.88`（Surface Ubuntu），不在本机。主 agent 实测：注册 200、`GET /api/specs` 200、`GET /api/videos` 200、`POST /api/wan/video/run`（confirm=false）200 `{job,taskId}`。子代理的「curl 000」是打了本机 localhost，结论作废。

3. **channelMediaUrl 对「同 host、路径不含 baseUrl 前缀」的成片直链会拼错路径**
   - 代码：channel-proxy.ts:48-63 `stripBasePath` 只裁「pathname 以 basePath 开头」的情况；channel_store.py:689 `target = base.path.rstrip("/")+"/"+subpath` **无条件把 baseUrl 路径拼回去**。
   - 场景：渠道 baseUrl=`https://host/v1`，上游成片 url=`https://host/files/abc`（同 host、无凭据、路径不含 /v1）→ stripBasePath 原样 `/files/abc` → 服务端拼成 `/v1/files/abc` → 上游 404 → videoResultFromUrl 拿不到 blob 回落 `{url:/api/proxy/...}`，`<video>` 播放同样 404。
   - 单机版：直接裸直链下载，无此问题。
   - 最小验证（不花钱）：node 单测 `channelProxyUrl({channelId:"c",baseUrl:"https://h/v1"},"https://h/files/a.mp4")` → 若产出 `/api/proxy/c/files/a.mp4`，再对照 channel_store.py:689 语义确证上游会收到 `/v1/files/a.mp4`；无需真实渠道。

4. **代转发 8MB 请求体上限 / 120s 读超时 / 每用户 2 并发对视频链的隐性截断**
   - 代码：channel_store.py:54/56/57；openai 型视频创建是 FormData（含参考图/参考视频字节，referenceMediaToFile 拉本地 blob）——**参考视频稍大即 413**；wan run 前端 timeout 300000ms 但代转发 120s 就断（wan 不走代转发，不受影响；openai/sdggf create 前端 timeout 90s < 120s，勉强安全）。
   - 单机版：直连上游无此限制。
   - 差异性质：偏「必要改造」（安全收口），但 8MB 对带参考视频的 FormData 是实际回归风险。
   - 最小验证：登录态经 /api/proxy 发一个 >8MB body 预期 413（curl 本地即可，不触上游）。

5. **gemini 格式渠道经代转发拉成片依赖 api_format=="gemini" 才注 ?key=**
   - channel_store.py:700-702：只有渠道 api_format=gemini 才拼 `?key=`，否则一律 Bearer。若用户用 openai 格式中转渠道跑 gemini 系模型（常见用法），gemini 成片 uri 同 host 无凭据 → 走代转发 → 服务端注 Bearer 而非 key → 上游 401。v1.2.0 前端自己拼 key 无此问题。
   - 最小验证：不花钱手段有限——可查渠道表 api_format 与实际模型家族是否错配（sqlite 读 user_channels）；完整复现需一次真实生成（留待付费窗口）。

### 7.3 结论

「视频生成失败」在 SaaS 侧有**两层**独立成因，缺一都不会通：
1. **代码层**：remote 模式下 wan 渠道存不进（422）、不显示为就绪、不上送 → 界面直接拦住；
2. **引擎层**：服务器没有 `wan` CLI 与 `~/.wan` 凭据 → 即使代码放开，服务端起子进程也找不到命令。
