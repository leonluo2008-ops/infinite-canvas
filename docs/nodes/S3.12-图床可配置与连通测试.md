## 二、裁决（已定，交审计复核误判风险；不留悬空二选一）

| # | 裁决点 | 定论 | 理由 |
|---|---|---|---|
| C1 | 首选存哪 | **服务端按用户**：新表 `user_media_prefs(user_id INTEGER PRIMARY KEY, media_host TEXT NOT NULL, updated_at INTEGER NOT NULL)`；**不设 FK**（无删号功能，风险≈0），建表注释写「用户删除功能上线时需级联清理」 | 所有者口径「后端都在服务器上处理」；存浏览器换设备即丢，且与「渠道本地不存」既有裁定冲突 |
| C2 | 界面落点 | **应用设置 modal 新增一个 tab**，键 `"media-host"`（与既有 kebab-case 一致），`ConfigTabKey` 追加该值 | 复用既有 tab 的面板与 i18n 机制，不新增入口；命名与既有 7 键同风格 |
| C3 | 首选语义 | **「先试它」，失败照旧回落**（红线 11 的回落不算违规） | 若做成「只用它」，首选源一挂整条参考图链路即死，等于把今天的可用性往下砍 |
| C4 | 单人模式（**第 1 轮审计后简化**） | `MULTI_USER=0` 时**整条路由不注册**：`handle()` 首行 `if not multiuser.enabled(): return False`（与 `channel_store.handle` **完全一致，零偏离**）→ 三条路由在单人模式一律 404；前端按 remote/local 判定**不渲染该 tab** | 红线 4「单机版不回归」：单人包不新增任何可达路由、不新增鉴权分支 |
| C5 | 测试接口防刷 | 每用户 **5 秒冷却**（进程内 dict，键 = username）；命中 → 429 + 剩余秒数；**dict 用 `multiuser._cap(COOLDOWN, 4096)` 同款封顶**并惰性清理过期项 | 每次测试真打外部图床，双击连点会连续外呼；不引入更重的限流设施，也不新增无界内存风险 |
| C6 | 测试探针不写本地备份 | `test` 走独立函数：**不写 `uploads/vc/`**，十位随机 key 直接上传并在结束时只清理自己刚写的临时落点（local 源除外，local 必须落盘才能校验） | `uploads/vc/` 是 M4 直链路由的生产目录，测试垃圾不得进 |
| C7 | 枚举值 | `"tencent" | "local" | "litterbox" | "uguu"`；`selected=null` 表示「按默认顺序」（不写 `"auto"` 字符串） | 与代码里 `source` 字段同名同值，前后端零翻译层 |

## 三、接口合同（定死）

### GET `/api/user/media-host`（登录态）

```json
{"mode":"remote","selected":"tencent"|null,
 "sources":[{"id":"tencent","label":"腾讯云图床","configured":true,"default":true},
            {"id":"local","label":"自托管直链","configured":true,"default":false},
            {"id":"litterbox","label":"litterbox(72h)","configured":true,"default":false},
            {"id":"uguu","label":"uguu(3h)","configured":true,"default":false}]}
```

- `configured` 判定与 F2/F3 完全同源：tencent 看双 env、local 看 `WANREPRO_PUBLIC_BASE`、litterbox/uguu 恒 `true`。
- `default:true` 标在 tencent 上（默认顺序里的第一源），供界面说明「未选则按此顺序」。
- 单人模式（`MULTI_USER=0`）下本接口**不存在**：`handle()` 首行 `if not multiuser.enabled(): return False` → 404。故响应体不含 `mode` 字段，`remote` 即「路由存在」的唯一形态（第 1 轮审计 #1 的简化结论）。

### PUT `/api/user/media-host`

body `{"selected": "tencent"|"local"|"litterbox"|"uguu"|null}`

| 情形 | 返回 |
|---|---|
| 合法且该源 `configured=true` | `200 {"ok":true,"selected":"..."}`，upsert 一行 |
| `null` | `200 {"ok":true,"selected":null}`，删除该行（= 恢复默认顺序） |
| 枚举外 / 类型错 | `400 {"error":"可选值：tencent / local / litterbox / uguu / null"}` |
| 该源 `configured=false` | `400 {"error":"该图床源未配置，无法设为默认：<label>（<缺哪个环境变量>）"}` |
| `MULTI_USER=0` | **路由不存在 → 404**（`handle()` 首行 `enabled()` 门拦下，与 `channel_store` 同款；不返回 409） |

### POST `/api/user/media-host/test`

body `{"id":"tencent"}`（缺省 = 当前 `selected`，`selected=null` 时 = `tencent`）

- 探针内容：**1×1 PNG（67 字节，硬编码常量）** 真上传，**验活口径与生产分支逐一相同**（不新增第三套判定）：
  - `tencent`：PUT 受理 2xx 即 `ok:true`（**不回取**，与 F2 生产口径一致）；
  - `local`：落盘后磁盘字节校验（存在且恰 67 字节）并回读一次自己写的公网直链；
  - `litterbox` / `uguu`：上传后 `image_url_alive()` 回取（与 `accept()` 同口径）。
- `200` 成功：`{"ok":true,"id":"tencent","url":"https://...","bytes":67,"ms":123}`
- `200` 失败：`{"ok":false,"id":"uguu","reason":"上传失败（HTTP 502）","ms":88}` ← **失败也是 200**，`ok` 字段承载结果（界面不需要区分 HTTP 层）
- `429`：冷却中，`{"error":"测试过于频繁，请 4 秒后再试"}`
- `400`：`id` 枚举外 / `configured=false`
- 单人模式（`MULTI_USER=0`）：**404**（路由不注册，见 C4）

## 五、验收判据（每条都能 FAIL）

| # | 判据 | 手段 |
|---|---|---|
| V1 | 未登录访问三条路由 → 401（不是 200、不是 302 到页面） | curl 实跑 |
| V2 | 登录 GET → 恰 4 源，`tencent.configured=true`、`local.configured=true`，`selected=null` | curl 实跑 |
