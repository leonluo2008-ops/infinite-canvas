# S3.5 任务书 · 预置模板版本化更新（存量浏览器无感拿到新模板）

> 状态：**v1.1（双路审计合并修订版，冻结待派）** · 2026-11-17
> v1.0 双路审计：路A（可行性 3 BLOCKING）+ 路B（可执行性 2 BLOCKING），修订清单见 §六 审计收敛表。
> 上游拍板（2026-11-17，clarify 表单原文答复）：①客户端展示层叠加；②填过 key 的渠道永不动（BYOK 红线）；③单人/登录同一套逻辑
> 背景：s1-test 预置文件已换成真实模板（聚鑫/SDGF/Ollama Cloud，无 key），但 bootstrap-config.ts:39 只在 CONFIG_STORE_KEY 不存在时拉一次——存量浏览器永远停在旧「默认渠道」。
> 基线：feat/saas-multiuser `cf31119`。红线：单人模式零改动语义不破坏；BYOK（用户 key 永不被模板覆盖）；零兜底。

## 一、问题定义

- 现状：`maybeImportBootstrapConfig()`（bootstrap-config.ts:39）在 `localStorage[CONFIG_STORE_KEY]` 存在时直接 return——预置只拉一次，之后服务端换模板存量浏览器无感知。
- 目标：**服务端模板更新后，所有浏览器（含存量）下次启动无感拿到新模板**；用户自建渠道与已填 key 的渠道永不被碰。
- 不做：模板合进服务端渠道表（拍板①否决）；渠道共享/admin 用户管理（已取消）；用量配额；按账号差异化模板（预置端点无登录校验，全员同一份——正式放量前如需差异化再立项）。

## 二、核心设计（v1.1 修订）

### 2.1 版本化协议

- 服务端：`/api/bootstrap-config` 响应**加 body 字段 `presetVersion`（字符串，= 模板文件 sha1 前 8 位 hex，服务端每次响应时对 `preset.read_bytes()` 现算）**——改模板即变，零维护。不 HEAD、不 ETag（send_body 恒发 Cache-Control: no-store 且从不读 If-None-Match，304 管道不存在，路B-BLOCK1 定案）。
- 请求口径：**每次启动全量 GET（KB 级）→ 客户端比对 → 版本相同=零写入（不是零请求）**。
- 客户端：`preset_meta`（localStorage 新键 `infinite-canvas:preset_meta`，**不进 config store persist 信封**——既有探针 probe-bootstrap-config 断言信封顶层键严格等于 ["state","version"]，此约束点名保持）记 `{ lastPresetVersion, tombstones:[] }`。
- **lastPresetVersion 必须「合并真正落地后才写」**：登录态下服务端渠道读取失败会退回 local 模式（channel-sync.ts:465-471），此时记版本 = 该浏览器永久错过本次模板，静默失败——禁止。
- presetVersion 字符串直接做字符串比较（不做 int/hex 换算）。

### 2.2 合并规则（拍板② BYOK 红线为最高优先）

对模板文件中的每个渠道（按 id 匹配本地渠道视图）：

| 本地状态 | 动作 |
|---|---|
| tombstone 命中（用户删过该模板 id） | 跳过 |
| 本地不存在该 id（且不在服务端视图/localOnly） | **合入队尾**（新模板渠道，无 key） |
| 本地有、且 apiKey 为空（含空串） | **跟随更新**（name/baseUrl/apiFormat/models 全按服务端模板刷） |
| 本地有、且 apiKey 非空（**masked *** 开头也算非空**——登录模式服务端视图全是 masked，自动跳过=不覆盖服务端权威渠道） | **永不动**（BYOK：key/name/baseUrl/models 全保留） |

用户自建渠道（id 不在模板中）：零接触。
**同名策略（路A-BL2）**：模板 id 本地不存在但 name 与某本地/服务端渠道同名（**strip 后**比较，大小写不敏感；预检顺带挡 trim 后为空的名字——服务端 422 整批回滚）→ 该模板跳过合入，计入 notice 点名（复用 localOnlyNotice 通道，channel-sync.ts:217-221），不做 name+baseUrl 认领。同时 splitSavableChannels 补一条与 selectMigratableChannels 同口径的重名预检：本地要 PUT 的渠道集内出现重名 → 重名者单条不提交并 notice（把「整批 422 整批回滚」降级成单条跳过）。

### 2.3 升格派生 id（路A-BL1 + 复审 BL1/BL2/BL3 定案：随机 mint + alias 表，时机锚点重定）

**问题**：user_channels.id 是**全局 PRIMARY KEY**（channel_store.py:85-96，非 (user_id,id)），模板 id 是跨用户共享常量。用户 A 给模板「聚鑫」填 key 升格落库后，用户 B 同模板填 key → PUT INSERT 撞 A 的 id → 409 整批回滚 → 死循环。

**定案（采纳复审路A三条）**：
- **mint 时机锚点重定（复审BL1）**：splitSavableChannels 不是唯一 PUT 入口（迁移分支 channel-sync.ts:488-509 走 selectMigratableChannels→putServerChannels 绕开它；单人模式无 flush）。mint 锚点改为「**apiKey 由空变非空的 store 写入边界**（persist merge/订阅层）+ 启动 normalize（templateId ∧ hasKey → 立即 mint）」；另在两个 PUT 入口（flushChannelSync/迁移 putServerChannels 调用前）加防御断言「待提交渠道 id ∉ 模板 id 集合」，触发即先 mint 再提交（兜底）。
- **幂等（复审BL2）**：mint 恰好一次并落盘——preset_meta 记 alias `{templateId → mintedId}`，此后该渠道不再属于模板 id 集合；alias 命中即不再 mint。探针断言连续两次 flush 服务端行 id 不变。
- **mint 后同步重写 config 全部引用串**：channelId::model 嵌在 model/imageModel/videoModel/textModel/audioModel/lapianModels/lapianDefaultModel（use-config-store.ts:411-456 七处）。

**画布/项目侧引用（复审BL3 新雷）**：画布节点 metadata.model / lapianModel 也是 channelId::model 编码（types/canvas.ts:119-123、lapian-model.ts:14-29），项目整包 content_json 存服务端——只重写 config 会让存量项目引用悬空（normalizeModelOptionValue:444-446 解出 channelId 找不到返回 ''→节点静默回落默认模型）。定案：**decode 处 lazy 自愈（方案 b）**——normalize/decode 解出的 channelId 命中 preset_meta alias（templateId→mintedId）时按映射换新 id 解析成功即用；项目下次保存自然携带新 id。**不做全量项目遍历重写**（不碰项目同步链路）；悬空窗口=该项目下次保存前（期间模型选择可能回落一次），属已知边界。

### 2.4 模式覆盖与启动门（路B-BLOCK2 定案）

- **单人模式**：版本更新合并**沿用首拉路径（写 localStorage 信封 → reload），但只重写渠道域**（channels/models/默认模型引用/lapian 两项），用户非渠道设置（videoSeconds/audioVoice/proxyUrl 等）与 webdav 原样保留——禁止复用首拉的 defaultConfig 整包拼装（抹用户设置，V10）。reload 前的 setItem 抛异常（配额）必须进 catch 不 reload（写入失败=不写 lastPresetVersion 不 reload，防 reload 死循环）（channel-sync.ts:456 的 void 不 await 时序保持，loading 门零改动，探针断言 calls.reload+fetch 序列）。首启（localStorage 全空）由同一条 merge 路径落库并同次写入 lastPresetVersion，**去掉首拉的独立 reload 分叉**（否则「fetch 两次+写两次+reload 一次」，V6 首启永不成立）。
- **登录（remote）模式**：合并点在 mergeLocalOnlyChannels 之后追加 mergePresetChannels（纯函数，三层顺序：服务端视图 → localOnly → preset 队尾追加），**必须经 applyChannels**（内含 suspendAutoSave=true，防合并触发 subscribe→scheduleSave→PUT 破 V6）→ setSync ready。登录模式合并在 await 门内，天然满足渲染门，**不需要 reload**。
- 登出态：不拉 bootstrap（B-09 既有判定不变）。
- 预置拉取失败降级为「本地缓存照常起」，**不得塞进 withTimeout 的失败路径**（channel-sync.ts:444-452 整段放弃退 local 是渠道链路语义，不是预置的）。

### 2.5 tombstone（仅本浏览器记忆）

- 存储：preset_meta.tombstones（localStorage，**不进服务端**）。
- 写入时机：用户在展示层删除一个 id ∈ 当前模板 id 集合的渠道时记录。
- 已知边界（如实接受）：换设备/清 localStorage tombstone 丢失 → 被删模板渠道会重新出现一次（等于新浏览器首见，可接受）；config-modal 删除无二次确认是既有行为，模板渠道误删可通过「再次合入」自然恢复——**不新增确认弹窗、不新增恢复入口**（禁发散）。
- 与画布项目墓碑（project_store deleted 行）是两套机制，无任何共享。

### 2.6 模板文件入库

- 模板真源从服务器盘上文件改为**仓库文件 wanrepro/config/channel-config.json**（随 commit 走，有 diff/回滚/探针可断言真 id）——s1-test 部署位现文件与仓库同步一份（内容即现有 3 模板，部署时 copy2 同步）。presetVersion 探针用仓库文件 hash 断言。

## 四、批次（执行顺序：B1 → B2）

- **B1 服务端**：/api/bootstrap-config 响应 body 加 presetVersion（现算 sha1 前 8 位）+ 模板文件入库——server.py 一处改动 + config 文件
- **B2 前端**：preset_meta 键 + 版本比对 + mergePresetChannels（含同名跳过/masked 判空/tombstone）+ 升格换 id 全套引用重写 + splitSavableChannels 重名预检 + 单人 reload 路径归一 + 探针（含 V1-V8 与两处白名单期望更新）
- 验收：部署 ：8780 → verifyuser 存量浏览器无感拿到 3 模板 → 填 key 升格（换 id 后模型引用不断）→ 改模板 → key 渠道不动

## 五、不做（审计判定出队项）

- 按账号差异化模板（端点无登录校验是现状，预置无 key 不算泄密；要差异化=新功能另立项）
- 删除确认弹窗 / 恢复预置渠道入口（禁发散，误删靠再次合入自然恢复）
- 304/ETag 条件请求管道（no-store 下不成立，全量 GET KB 级成本可忽略）
