## 3. ★核心遗留问题：渠道配置架构（新会话第一任务）

### 3.1 所有者的规则（原话，最高优先级）

1. 「所有的新用户登录上来，默认就是预置的这三个渠道必须要有。」
2. 「本地持久化的渠道数据**登录后一律以服务端为准**。」
3. 「我一再强调，渠道的配置方式是**保存在服务器上的用户级隔离**。他妈的，那怎么还会在用户本地的 local store 里面保存？**完全就不需要保存的呀**，为什么还要保存到用户的本地？」
4. 「还有『合并』这种说法、这种操作，我他妈真没搞明白你是怎么想的？」
5. 新会话指令：「你要把之前遗留的渠道配置问题清楚地写到项目交接书里面，因为**新会话的第一件事就是要去做那个问题的排除**。」

### 3.2 现象（用户亲历，同一浏览器两个账号）

- 登录 `verifyuser`：显示 3 个预置渠道（修复生效），随后登出。
- 登录 `owner`：弹「本机已登录过某账户，是否导入渠道」→ 用户点**不导入**。
- 结果：渠道页出现 **6 张卡** = 3 张真渠道 + 3 张重复的「未填 Key」卡。
- 用户判定：这是「本地保存 + 合并」造成的，架构错误，不接受任何补丁式解释。

### 3.3 根因链（已取证到代码级，但修复只做了半程）

1. **预置模板 id ≠ owner 服务端渠道 id**：
   - `config/channel-config.json` 模板 id = `default` / `kXPsFLhz0hadRynalZN3E` / `dlzkV3SjmTmlBwaFXVFGM`；
   - owner 服务端行 id = `ZELhIA0KHKXU6wMA9gaAE` / `LKnQAnVP-Zz0qAIsa1NJV` / `50--DBD7FQn4P1t4x-a7E`（历史迁移时 mint 过）。
   → **任何前端「按模板 id 判在场」的合并/完整性逻辑，对 owner 永远判「不在场」**，于是每次登录都追加一份无 key 模板副本。
2. **版本守卫记在浏览器级 localStorage** `infinite-canvas:preset_meta`（`lastPresetVersion` / `tombstones` / `aliases`，**跨账号共享**）：owner 消费掉 `presetVersion=18300a9e` 后，同浏览器换账号登录 → 守卫命中 → 跳过预置合并 → 只剩占位卡（这就是第一次事故）。
3. **渠道随整份 config 存在单一 IDB key** `infinite-canvas:canvas_store`，登出不删而是「隔离」到 `infinite-canvas:canvas_store:foreign:<owner>`，登录时还原。旧存档里已经混进了无 key 模板副本 → 还原后进入显示层。
4. **前端缝合层整体多余**：`mergeLocalOnlyChannels` 只按 id 去重、把「无 key/非 https/wan 格式」一律当本地渠道保留 → 无 key 模板副本全部被保留并显示。

### 3.5 目标形态（验收判据，必须可机器或真机判定）

- **R1 单一权威源**：登录态渠道列表 = `GET /api/user/channels` 返回值原样渲染；本地持久化中的渠道数据**不参与显示、不参与合并、不参与任何决策**。
