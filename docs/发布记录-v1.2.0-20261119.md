## 八、发布当日追加：删除画布「跨账号导入」机制（X1 结案）

所有者第三次就此发火后定调：「这是第三次来做这个事情了……删除他妈的……围绕这个解决掉它」。判据不是文案，是**机制在 SaaS 下不成立**：项目与渠道都以服务端为唯一真源，本机只是缓存，不该出现「本机有别的账号的数据，是否导入到当前账号」。

| 层 | 改动 |
|---|---|
| 核心 | `canvas-project-sync.ts`：删 `CanvasImportPrompt` / `importPrompt` 状态 / `acceptForeignCanvasImport` / `declineForeignCanvasImport` / `listPendingForeign` / `quarantineForeign` / `foreign_ignore` 整套；新增 `purgeForeignArchivesExcept(ownerName)`——登录时把本机**其他账号**的缓存与留档直接删除；本账号自己的断网草稿留档仍自动并回（删的是跨账号导入，不是断网恢复） |
| 计数 | 清理后重算 `brokenArchiveCount`，不让已删的别人坏档把计数撑高 |
| 界面 | `canvas-project-sync-status.tsx` 删弹窗与相关 import；i18n 中英各删 4 键 |
| 验收 | 探针 `probe-s3-b2-project-sync.mjs` 按新裁定重写第 7/13/19 节 → **151 passed / 0 failed**；web **15/15**；typecheck 仅剩既有无关错（`model-script-editor.tsx`）；真机 A→B 换账号：**无弹窗、无「检测到本机…」文案、IDB 无 foreign 残留**（截图 `docs/证据-X1-换账号无弹窗-20261119.png`） |
| 部署 | `web-dist` 重建替换（备份 `web-dist.old12`），服务 active，`:8780` 302；产物内旧文案 0 命中、新清理日志 1 命中 |
