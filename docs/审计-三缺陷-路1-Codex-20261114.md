## ① 逐卡判定

### 卡 D · 拉片能力边界契约 — **部分覆盖，验收不闭环**

**已覆盖的部分**

1. 现有 agent 工具集确实没有单独 `lapian` op：
   - 证据：`canvas-agent/src/canvas/schemas.ts:20-43` 的工具名单中只有 `canvas_generate_video`、`run_workflow_batch` 等，没有 `lapian`。
   - 证据：拉片节点主要是画布 UI 类型定义：`web/src/components/canvas/nodes/builtin-nodes.tsx:30`，且 `showInCreateMenu:false`。
2. SDGF 视频参考能力缺失属实：
   - `web/src/services/api/video.ts:201-203` 明确 SDGF mode 与 2026-10-22 后能力边界。
   - SDGF 请求体只组装图片：`web/src/services/api/video.ts:215`、`:230`、`:235`；没有把 video reference 放入 body。
3. 方案要求“不得静默用 text 模拟拉片”，能覆盖“静默降级”痛点。

**未覆盖 / 阻塞点**

1. 方案遗漏仓库已有的 agent 真拉片入口：`run_workflow_batch`。
   - 证据：`canvas-agent/src/canvas/schemas.ts:40`、`:144` 已定义 `run_workflow_batch`。
   - 证据：`canvas-agent/src/canvas/schemas.ts:184-185` 明确“视频拆解工作流是系统内置”且用户说跑视频拆解时应直接调用 `run_workflow_batch`。
   - 证据：前端 agent site tool 也有实际分发：`web/src/lib/agent/agent-site-tools.ts:36`、`:86-87`。
   - 证据：内置模板包含 source video → lapian → prompt config 链：`web/src/lib/canvas/workflow-builtin-template.ts:26-27`、`:57`、`:151-152`。
   - 证据：批次结果返回拉片任务标识：`web/src/lib/canvas/workflow-batch-entry.ts:355`、`:503`。
2. 因此，卡 D 当前的验收只检查“回复中出现能力边界说明”，可能通过验收但仍没有触发真拉片。它覆盖了“明示边界”，没有覆盖“真拉片 or 用户确认降级后仍能走已有真拉片入口”的完整需求。
3. 方案原文说“真拉片需用户手动拉线……（或走已跑通的拉片链）”，但未点名已有 `run_workflow_batch`，也未把“成功建立 lapian 任务/批次”写进验收。

**判定：未完全覆盖真实痛点；卡 D 验收存在 BLOCKING 缺口。**
