- **BLOCKING**：验收没有明确要求“三种不同角色替换、三条成片”。源实例加两个变体可以满足数量，但必须明确源实例属于第三种替换且最终出片，否则目前只证明两个替换结果。
- **BLOCKING**：Agent 派生和资产绑定能力超出“Agent 只做提交”的字面授权。应明确派生、替换由人工操作；若希望 Agent 接收人工指令执行这些动作，需要所有者确认需求边界。

- **MAJOR**：缺少明确验收：实际只拆一次、始终使用同一原片、派生及修改变体后源成果不变、各变体资产与审核互不污染、缺槽不得绕过人工核验。
- **MINOR**：B 的启用条件应统一为所有者决策口径；画布膨胀可作为评估证据，不应自行成为启动 B 的授权。

1. 同一画布、同一原片，仅拆解一次，完成三种不同角色替换并得到三条成片。
2. 三个结果生成前均经过人工资产核验与审批；派生后无自动提交。
3. 修改任一变体，源实例及其他变体成果保持不变；fork 失败无半套画布节点。
4. 使用现有 Agent 提交、成片自动落节点能力完成回归，不新增提交或下载通道。
5. 删除或确认新增上限，并统一 A/B 决策条件。
