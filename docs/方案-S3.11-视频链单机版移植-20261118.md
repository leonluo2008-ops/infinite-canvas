# 方案 S3.11 · 视频生成链按单机版（v1.2.0）权威移植

> **v1.2 范围变更（所有者裁定 2026-11-18）**：「wan渠道直接取消，早就说过了」「服务器版，不做wan」。→ **wan 链路整体移出本期范围**：不在服务器装 `@wan-ai/cli`、不放开 wan 渠道、不做 wan 的 owner 隔离；改为「多用户模式下 wan 视频路由一律 404（功能不提供）」。本方案主线收敛为**非 wan 视频链（SDGF / OpenAI 兼容 / Gemini）在 SaaS 下的正确性**。

> 所有者插单原话（2026-11-18）：「视频生成失败。这个视频生成链路之前在单机版已经完整跑通了，包括模型调用还有渠道配置这些，你务必从以前的单机版里面去做核实，做权威的抽取，移植到服务器 SaaS 版来。你不要全新地自己去摸索、去探索，那就是重复造轮子了。」
> 权威基准：`standalone-v1.2.0`（tag `v1.2.0`）。取证：`docs/nodes/S3.11-单机版视频链对照.md`（含主 agent 复核 §7）。
> 原则：**SaaS 侧与单机版不同的地方，必须能说清「为什么必须不同」；说不清的一律按单机版回填。**

## 一、已核实的根因（两层，缺一不通）

| 层 | 事实 | 证据 |
|---|---|---|
| 代码层 | remote 模式下 wan 渠道**存不进**（服务端 422）、**不就绪**（`isAiConfigReady` 恒 false）、**不上送**（`isLocalOnlyChannel` 拦） | `channel_store.py:363-367`；`use-config-store.ts:222-228`；`channel-sync.ts:178-183` |
| 引擎层 | 服务器**没有 `wan` CLI**（`which wan` → not found），也没有 `~/.wan` 凭据；`wan_submit.cli_prefix()` 在 Linux 上直接 `[which("wan") or "wan"]` → 建任务即 `FileNotFoundError` | 服务器实测；`wanrepro/pipeline/gen/wan_submit.py:72-76` |
| 引擎脚本 | **在**（服务器有 `wanrepro/pipeline/gen/wan_video.py` 19816B，service `WorkingDirectory=…/wanrepro`，路径可解析） | 服务器实测 |
| 成片下载 | 媒体请求经 `/api/proxy` 时，服务端**无条件**把 `base.path` 拼回（`channel_store.py:695`），而 `stripBasePath` 只裁「pathname 以 basePath 开头」的情况 → 同 host、路径不含 baseUrl 前缀的成片直链（如 `…/files/a.mp4` + baseUrl `…/v1`）会被拼成 `…/v1/files/a.mp4` 404 | `channel_store.py:695`；`channel-proxy.ts` `stripBasePath`；对照表 §4-3 |

> 单机版之所以能跑：wan 是**同源零 key** bridge（前端相对 `/api/wan/video/*` → 本机 `:8779`），渠道存本地、免 key 即就绪，`wan` CLI 与 `~/.wan` 就在那台机器上。

### 一.1 线上实锤（2026-11-18 免费探针，未花钱）

登录态（自注册账号）调 `:8780`：

```text
POST /api/wan/video/run  {prompt, duration:6, ratio:16:9, resolution:720, confirm:false}
→ 200 {"job":"653905304e166a63","taskId":"wan-1795003528"}
GET  /api/wan/video/job/653905304e166a63
→ 200 {"status":"failed","stage":"计划","elapsed":2.1,
        "error":"找不到 wan CLI 的 node 入口（重装 @wan-ai/cli；不回退 wan.cmd——cmd.exe 会在提示词的第一个换行处切断整条命令）"}
```

即：**登录态下 wan 的路由、登录门、任务调度都是通的**，失败点就在「服务器没有 `wan` CLI」这一层——与 §7.2 的静态推断逐字对上（错误文案就是 `wan_submit.py` 的 `CLI_ENTRY_MSG`）。
补充：`systemd` 未自定义 PATH → 服务进程 PATH 含 `/usr/bin`；`luo` 的 `npm config get prefix` = `/usr` 且 `sudo -n` 可用 → `sudo npm i -g @wan-ai/cli` 会落到 `/usr/bin/wan`，服务能直接找到（不需要额外改 unit）。

## 二、单机版权威行为（移植靶子，逐条来自 v1.2.0 实码）

1. wan 渠道**免 API Key**：`isAiConfigReady` = `apiFormat === "wan" || Boolean(apiKey)`。
2. wan 请求**同源相对路径**：`wanVideoUrl` 对回环 baseUrl 产出 `/api/wan/video/{run,job/<job>,file/<taskId>}`（不带协议主机）。
3. wan 渠道**可保存、可显示、可选中**（无 422、无 localOnly 概念）。
4. 成片下载：`videoResultFromUrl` 拉不到 blob 时**回落 URL 播放**（单机版回落的也是上游裸地址；SaaS 出于零 key 泄漏考虑回落代理地址）。
5. 其余协议（openai / sdgf / gemini）的 create/poll/方言/等待循环/错误文案，两版**逐字节一致**，不动。

### B3 成片下载路径（候选，交双路审计裁决）

| 候选 | 做法 | 优点 | 缺点 |

## 六、风险

1. **wan 放开后 SSRF 面**：wan 渠道 baseUrl 由服务端固定、客户端传入值丢弃 → 不引入新的可被用户控制的出站目标。
2. **服务器无 GPU/CLI 版本差**：`@wan-ai/cli` 版本需与单机版对齐（0.0.3），否则参数名漂移。
3. **付费动作**：A5 是免费计划调用；真实生成属付费，按红线需批次审批。
4. **B3 选 A 时**：同 host 直连成片若上游要求 Referer/Authorization，会 403 —— 由 A6 探针与一次真实成片下载（付费窗口）兜底。

### B3 定版（v1.2 细化，替代 §三 B3 的三候选）

判据来自单机版行为：**同源素材走本机代理、异源素材直连**。落成规则：

| 场景 | 处理 |
|---|---|
| 成片 URL 的 host == 渠道 baseUrl 的 host | 走代转发，但带 **`__abs=1`** 语义：前端把**完整 pathname** 当 subpath 传，服务端见 `__abs=1` 时 `target = subpath`（**不拼 `base.path`**），并从转发 query 里剔除 `__abs` |
| 成片 URL host != 渠道 host（CDN / 第三方存储） | **直连**（服务端连不到那个 host，代理无意义），失败回落 URL 播放 |
| URL 自含凭据（`?key=` 等） | 前端剥掉凭据后按上面两条走，真 key 由服务端按 `api_format` 注入（gemini → `?key=`，其余 → Bearer） |

影响面：`channel-proxy.ts`（`channelMediaUrl` 产出带 `__abs=1`）、`channel_store.py:_forward`（识别 `__abs=1` 跳过 `base.path` 拼接）、`video.ts`（透传不变）。既有 `/api/proxy/<cid>/<subpath>`（相对 baseUrl）合同**不变**，`probe-s3-7-proxy-url` 9 条断言应保持全绿。
