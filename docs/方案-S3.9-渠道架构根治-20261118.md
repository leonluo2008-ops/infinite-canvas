# 方案 · S3.9 渠道架构根治（登录态单一权威源 + 本地不存渠道）【v1.5】

> 节点：S3.9（大看板 `docs/开发计划书.md`）｜实施仓 `infinite-canvas` `dev`（基线 `79768c6`）
> 需求出处：所有者原话（§0）+ L2 `docs/项目适配包.md` 红线 1/3/8
> 审计状态：v1.4 两路审计 BLOCKING=0（路 1 独立子代理 793s / 路 2 脚本）；本版按所有者「不发散」收窄为最小改动，并吸收两路全部 IMPL-FIXABLE/POLISH。

## 0. 所有者裁定（最高优先级，逐字）

| # | 原话 | 落成什么 |
|---|---|---|
| 1 | 「渠道配置数据都存放在服务器上，本地是用户的，不存放渠道」 | 登录态 `channels` 不写 `localStorage`（persist `partialize` 在 remote 下写 `[]`）；显示只来自 `GET /api/user/channels` |
| 2 | 「系统预置了的名称就要保留，用户新建的时候就不能新建重名的」 | 模板名 = 保留名：预置行**不可删、名称不可改**；用户新建/改名撞保留名一律阻止（服务端 `UNIQUE(user_id,name)` 兜底） |
| 3 | 「不要有导入渠道了，渠道唯一保留的就是在服务器上保留用户级隔离」 | 删除一切本地渠道→服务端的搬运/合并/迁移语义 |
| 4 | 「系统预制的渠道不能删除就行了嘛」 | **界面层禁止删除**（不做服务端每次 GET 强制补齐——那是发散，且会打坏既有后端断言） |

**前提对齐**：产品形态 = 打开 `:8780` → 登录 → 渠道页；交付物 = 渠道页内容严格等于服务端该账号的行；成功判据 = 换账号零重复、零复活、本地无渠道数据。

## 1. 做 / 不做

**做**
1. 登录态渠道显示 = `GET /api/user/channels` 原样渲染（不合并本地、不合并模板、不迁移）。
2. 登录态 `channels` 不落本地（persist 层排除）；首帧 `force` 覆盖 store。
3. 服务端在渠道视图下发 `isPreset`（按名称），前端据此禁删 + 名称只读。
4. 删除因此成为死代码的合并/迁移/预置层函数（B2）。

**不做（显式）**
- **不做服务端 top-up**：`channel_seed.seed_if_empty` 保持原样（新用户 0 渠道 → 种三条）。若有人用 API 把三条全删，下次 GET 会自愈回三条（既有语义），属可接受兜底；不为此新增每-GET 写库逻辑。
- 单人版（`channelMode === "local"`）零改动：本地渠道照旧落盘、预置合并照旧。
- 不动 `canvas_store` / 项目跨账号弹窗（节点 X1）；不改 S3.6/S3.7；不动部署与主密钥。
- `GET` 失败退本地模式的降级窗口（`channel-sync.ts:947-953`）保留，登记为已知残留（故障降级，非合并语义）。
- 「导出配置文件」类功能不在本节点处理（现状不动）。

## 2. 根因（代码级）

1. `channel-sync.ts:963` `mergeLocalOnlyChannels` 把本地「无 key / 非 https / wan」渠道附在服务端视图后 → 存量本地缓存里的无 key 模板副本进入显示层。
2. `channel-sync.ts:966` `applyPresetLayer` 再合一次模板层（版本守卫记在浏览器级 `preset_meta`，跨账号共享）。
3. `channel-sync.ts:975-1012` 服务端为空时的一次性迁移块。
4. **存储层（根因实体）**：`use-config-store.ts` persist `partialize`(:263) 把整份 `config`（含 `channels`）写进 `infinite-canvas:ai_config_store`；登出只清画布项目域 → 同一浏览器换账号时上一个账号的渠道被水合回内存再被合并显示。

## 6. 风险与回滚

| 风险 | 处置 |
|---|---|
| 登录态不写渠道后刷新瞬间无渠道 | 启动门 `await` 前不渲染渠道页（`main.tsx:32`）；GET 失败走既有降级窗口 |

| 场景边界：API 直删预置渠道 | **明确不补偿**：前端只原样渲染 `GET` 返回值；`seed_if_empty` 仅在「该用户 0 条渠道」时补三条（既有语义）。API 删掉 1–2 条预置 → 那几条就不在，直到用户把渠道清空才会自愈。属非 UI 支持的高级操作，登记为已知边界 |

### 8.5 B0 实现期发现（2026-11-18，已修并验证）

1. **S4 播种在测试里从未生效**：HEAD 的 `import channel_seed` 是裸导入，包形态下 `ModuleNotFoundError` 被 `except Exception: pass` 吞掉 → 68/68 基线里没有任何一条真正走过播种。修成双形态导入后既有断言 `DELETE must clear the channel set`（期望 `[]`）变红——因为它编码的是「播种不存在」时代的语义。
2. **PUT 会删掉预置**：`isLocalOnlyChannel`(:217) 把「无 key」判为仅本地 → 无 key 渠道永不进 PUT；而 PUT 是整集全量替换 → 用户每存一次自己的渠道，三条预置就被删掉（这正是所有者反复看到的渠道异常的一类）。已在服务端做「保留 payload 未带的预置行」。
3. **空 key 行不能回写**：`keep` 分支原本要求旧行有非空密文，而预置出厂密文是 `b""` → 预置行一旦被前端带上就会整批 422。已放宽为「旧行存在即沿用（含空密文）」，新增无 key 渠道仍 422。
4. 既有断言 :1482 按新语义**改写并加强**：DELETE 后 GET 必须只剩 3 条 `isPreset=true` 预置，且原用户渠道 id 物理消失。
5. 验证：`py -3 wanrepro/tests/test_multiuser_s1.py` → **70/70 PASS**（基线 68 + 新增 2 条 isPreset 探针）；部署 `:8780` 后 `s39_api_probe.py` → **15/15 PASS**；DB 实查 owner(1)/verifyuser(4) 各 3 行不变、探针账号无重复。
