## 0. 前提对齐（先答「这份方案解的真是那个问题吗」）

| 项 | 内容 | 对应需求行 |
|---|---|---|
| 产品形态 | 所有者打开 `:8780` → 登录任一账号 → 渠道页 | L2 红线 8（交付形态） |
| 交付物 | 渠道页张数与内容严格等于该账号服务端渠道；换账号零重复、零复活 | L2 红线 1/3；交接书 §3.5 R1–R4 |
| 成功判据 | 同一浏览器 owner ↔ verifyuser 换登两次，各自渠道数与 DB 行数逐一相符；新账号首次登录恰 3 张「未填 Key」卡 | 同上 |

**要废除的语义**（所有者原话，最高优先级）：「渠道只保存在服务端」「不要有导入渠道了，渠道唯一保留的就是在服务器上保留用户级隔离」「本地怎么还会保存，完全就不需要保存」。
→ 登录态下：本地持久化中的渠道数据**不参与显示、不参与合并、不参与迁移决策**。

## 1. 目标与不做

**做**：
1. 登录态渠道读取链 = `GET /api/user/channels` 原样渲染，中间不插任何本地/模板合成。
2. 服务端种子改为**一次性**（修 S3.8 的「删光即回灌」缺陷）。
3. 删除因此变为死代码的合并/迁移/预置层函数与调用点。

**不做（禁发散）**：
- 不动单机版路径（`maybeImportBootstrapConfig`、`startPresetWatch` 墓碑分支、`preset-layer-complete`、`preset-meta` 全文件保留）。
- 不动 `canvas_store` / `foreign:<owner>` 项目域隔离与跨账号项目弹窗（属节点 X1）。
- 不改 S3.6/S3.7 内容；不新增加密/鉴权/限速；不动部署与主密钥注入。
- **显式不做的残留窗口**：`GET /api/user/channels` **失败**时现行逻辑退本地模式显示本地缓存（`channel-sync.ts:947-953`）。这是故障降级不是合并语义，本节点不动；严格读红线 1 它是「本地参与显示」的残留窗口，登记待定，不在本批处理。

## 2. 根因（代码级，两半）

**前半（已修）**：预置模板 id ≠ 服务端渠道 id（owner 行 id 是历史 mint 的），任何「按模板 id 判在场」的逻辑对 owner 永远判「不在场」→ 每次登录追加无 key 模板副本。

**后半（本节点）**：
1. `channel-sync.ts:963` `mergeLocalOnlyChannels` 把「无 key / 非 https / wan 格式」的本地渠道一律保留并附在服务端视图后面 → 存量本地缓存里的无 key 模板副本全部进显示层。
2. `channel-sync.ts:966` `applyPresetLayer` → `mergePresetLayer`(版本守卫在浏览器级 `preset_meta`) + `mintPromotedOnBoot`，再合一次模板层。
3. `channel-sync.ts:976-1003` 服务端为空时的一次性迁移块（`selectMigratableChannels` → `putServerChannels`）。
4. `applyChannels`(:746) 经 `channelDomainEqual`(:737) 做「零写入」判定；一旦被判相等就**跳过覆盖**，上一个账号的本地 persist 缓存原样留在 `ai_config_store` 里 → 换账号后重复卡/无 key 卡的另一半根因。
5. 登出只清画布项目域（`prepareCanvasLogout`，`canvas-project-sync.ts:1329` 附近），**从不清** `ai_config_store` 与 `preset_meta`。

**外加（本轮新发现，服务端）**：`channel_seed.seed_if_empty(uid)` 按「该用户名下行数 == 0」触发。用户把三渠道全删（PUT 全量替换成 `[]`）后，下一次 GET 命中 `count==0` → **重新种回三渠道**，直接违反 R4「删掉的渠道不得被任何机制复活」。

## 3. 改点（文件 : 行号，锚点以核查表实读为准）

### B0 服务端：种子只播一次
| 文件 | 改法 |
|---|---|
| `wanrepro/ui/channel_seed.py` | 新增一次性标记表 `channel_seed_state(user_id INTEGER PRIMARY KEY, seeded_at INTEGER)`，随 `_connect()` 的 DDL 落（`CREATE TABLE IF NOT EXISTS`；连接走 `multiuser.db_path()`，即 `WANREPRO_MULTIUSER_DB`，不另起相对路径）。`seed_if_empty` 事务内四分支——① 有标记 → `COMMIT; return`（永不回灌）；② **无标记且 `count>0` → 只写标记、不播种**（存量账号视为「已服务过」，封死「删光回灌」洞且绝不给非空账号重复播种）；③ 无标记且 `count==0` → 写标记 + 种入三渠道；④ 异常 → `ROLLBACK`（不写标记，下次 GET 重试）。标记与种子同事务，无中间态。 |
| `wanrepro/tests/test_multiuser_s1.py` | 五态探针：① 新用户（无标记、空）GET → 3 条 + 写标记；② 用户 PUT `[]` 后 GET → 0 条（不回灌）；③ 标记存在时并发两次 GET 不重复种；④ **存量非空账号（无标记、有 3 条）GET → 数据不变（仍 3 条，不重复播种）且写入标记**；⑤ 承接④，该账号 PUT `[]` 后再 GET → 0 条（证明存量账号的回灌洞已封）。 |

## 5. 验收判据（每条都必须可能 FAIL）

| # | 判据 | 怎么判定 | 会红的情形 |
|---|---|---|---|
| A1 | `GET /api/user/channels` 返回条数 == 渠道页卡片数（逐账号） | 登录后抓 API JSON 条数 + 页面 DOM 卡片数，两值相等 | 任一账号不等（含重复卡、少卡） |
| A2 | 新账号首次登录恰 3 张卡，`apiKey` 空、徽标「未填 Key」 | 新建测试账号 → 登录 → 逐卡核对名称/地址/徽标 | 出现 4+ 张、或出现第二份同名卡 |
| A3 | 删光后刷新仍是 0 张 | **API 级**：`PUT /api/user/channels {"channels":[]}`（带登录 cookie）→ 刷新页面 → 卡片数 = 0；DB `SELECT COUNT(*) FROM user_channels WHERE user_id=?` = 0。对照组：界面删到剩 1 条（界面有 keepOne 限制 `app-config-modal.tsx:116`，删不到 0）→ 刷新仍是 1 条 | 三渠道复活；或界面出现服务端已删的行 |
| A4 | 换账号零重复：owner ↔ verifyuser 互切两轮，每次卡片数 = 各自 DB 行数 | 两轮四次的 (卡片数, DB 行数) 成对相等 | 任一轮出现别的账号的行，或出现无 key 模板副本 |
| A5 | 登录态不再写预置层 | **纯登录序列内**（清空 `preset_meta` → 登录 → boot 完成，中途不碰单机路径）读 `localStorage["infinite-canvas:preset_meta"]`，两次取值为空/不变；命令：浏览器 console `localStorage.getItem('infinite-canvas:preset_meta')` 前后各一次 | 登录 boot 写入了 `lastPresetVersion`/`aliases`/`tombstones` |
| A6 | 单机版不回归 | **主护栏 = `web/scripts/probe-s3-b2-solo-diff.mjs`（HEAD-vs-工作区逐字节差分）**；辅以 `web/scripts/run-web-tests.mjs` ≥15/15。**口径如实降级**：run-web-tests 的 15 个用例对 channel-sync 零覆盖（审计实测），它是「没打坏别的模块」的弱证据，不得当渠道行为证据 | solo-diff 出现字节差异（单机落盘结构变了），或 web tests 低于 15 |
| A7 | 服务端种子一次性 | B0 探针四态 | 删光后 GET 又出现 3 条 |

真机动线（所有者可用自己眼睛走一遍）：`http://100.126.167.88:8780` → 登录 verifyuser → 渠道页数卡 → 登出 → 登录 owner → 再数卡 → 登出再切回。

## 6. 风险与回滚

| 风险 | 处置 |
|---|---|
| 强制覆盖写盘（`force`）导致每次 boot 都写 localStorage | `force` 只在登录分支首帧用一次；后续 autoSave 仍走原路径 |
| 存量用户本地还留着无 key 模板副本 | 登录态不再读本地，副本自然不再显示；不主动清键（清键会碰用户资产），等 X1 项目迁移链统一处理 |
| 客户端 `***` masked 回写护栏 | 不动 `toPutPayload`(:129)：空/masked 值仍沿用服务端原密文 |
| 回滚 | B0 回滚 = `git revert` 该 commit + 重启 unit（`channel_seed_state` 表留存无害）；B1/B2 回滚 = revert 前端 commit + 重 build 换 `web-dist` |
