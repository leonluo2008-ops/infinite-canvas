## 一、需求（所有者原话口径）

同一视频拆解一次，以同样原片为基底在同一画布生成 3 个视频：原视频里的角色/产品做 3 个不同替换。现状拆解工作流的资产替换位是绑死的，复用之前的拆解过程没有办法。缺少的是「自动化提交」之上的**复用拆解成果**能力。中间过程（拆解/资产替换/核验）保持人工，变体只省「拆解这一次」。

## 三、设计（拍板项）

**D1 派生语义**：变体=源实例的完整子图副本（新 instanceIndex），拉片产物**引用复用**（不重跑），生成侧全新。派生入口两处（所有者 2026-11-15 拍板）：agent 工具 `derive_workflow_variant`（仅显式指令触发，禁自主派生）+ 源实例悬浮栏「派生变体」人工入口（extraTools 通道）；两处结果都停待批等人核验资产。

**D2 hub 挂靠**：每个变体调 `hub_api.fork_task(源localId)` 产新任务号（awaiting_assets 出生态）——审批/渲染/生成全部挂新任务自身，拆解产物按 F1 共享引用（fork 实际复制源视频/资产图字节与私有清单副本，零复制的只是拆解产物目录——口径如实）。**不重实现 fork**，只消费。
**D2b 变体直绑通道（路2 N1 BLOCKING 修正）**：变体**禁走 `bindInstanceToHub.ingest`**（幂等键=视频 sha，同源视频会命中源任务，正文/自检写穿到源任务，击穿「源实例零改动」边界（D7③））。派生改持 fork 返回的 localId/bridgeId **直绑**：跳过 ingest 段，直接消费「awaiting_assets→awaiting_approval」推进动作（确认置换→渲染→待批），后续 save_prompt_text/审批/生成按新任务号走。

**D2-依赖边界（所有者 2026-11-15 口令后补记）**：/hub 工作台页面可能废弃（被画布+Agent 承接替代）——**本方案零依赖 hub 页面**，只依赖 bridge automation 引擎（fork.py/render/state 属引擎层，是画布工作流实例的既有后端：实例挂靠 automation 任务号、审批与渲染本就走它）。若未来连 automation 引擎都要退役，画布工作流的审批/渲染挂靠需整体迁移设计——那是独立架构课题，不在本卡范围；本卡按「引擎保留、hub 页废弃」的口径实施。

**D3 画布子图**：复制源实例子图（该 templateId+instanceIndex 全节点+连线闭包），id 按 F2 重写为新 index；定向剥离——生成侧运行痕迹剥（videoTaskId/成片/自检结果，复用 P2 剥离表裁剪），**拉片产物保留**（taskId 换成 fork 新任务号、正文侧车按 bridge_id 共享照旧读）；拉片节点加标记 `lapianReusedFrom: <源拉片节点id>`（状态派生与排障的可见痕迹）。

**D4 资产槽**：变体槽起手**全空**（不继承源实例绑定——变体的意义就是换不同的）；派生入参 `assetBindings`（与 run_workflow_batch 同 schema：槽名/槽类型+图节点）绑定必换槽；判不准/未提供的槽留空交人工（P7 口径）。源实例绑定一字不动。

**D5 意图**：变体意图文本可传（intentText）；缺省继承源实例意图。意图落在变体自己的意图文本节点。

**D6 组装与终点**：派生完成后自动跑组装（`/api/render/<新taskId>` 投影 + buildNodeGenerationContext，与单实例跑批同一函数路径）→ 自检 → **停在待审批**。不自动提交生成（红线：付费人工闸不变）。

**D7 边界**：①**源实例须已出片（hub 任务 done 态）方可派生**（路2 N2：引擎 FORKABLE_STATES=("done",) 强制，与所有者已选流程「母链先出第一个视频→再派生」天然一致，零引擎改动）；拉片未完成/任务进行中→拒绝派生并明报；②（原拟变体上限 9 经审计打回、所有者拍板删除——不设硬上限）；③派生对源实例零改动（字节不动）；⑤fork 失败（源任务态不允许）→ 如实报错不落半套节点（先 fork 成功再落画布，顺序保证）。④fork 产出的 inbox 会复制源视频字节、资产图字节与私有清单副本（如实入 C2b 验收明细），零复制的只是拆解产物目录。

**D8 回执**：派生回执=变体实例节点 id 清单 + 新 localId + 槽绑定结果（图→槽+理由，P11 同口径）+ 停点状态。画布呈现：新分支向右弹出+连线归属（交互铁律），落位后 focusNode。
