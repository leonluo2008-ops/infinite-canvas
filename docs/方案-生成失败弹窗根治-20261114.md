## 一、背景与根因（已实测；行号经两轮审计复核）

所有者录屏反馈：【配置】弹窗在工作流执行期间反复自动弹出（18s/35s/52s 共 3 次），且「本地代理已配置好还总弹」。诊断结论（2026-11-14 实测）：

1. **localStorage 实读**（ego-browser 读 `localhost:3000` 页面）：`infinite-canvas:ai_config_store` 中 `channels: []`。
2. **就绪判定**（`web/src/stores/use-config-store.ts:217-221`，return 在 220）：`isAiConfigReady` 要求模型匹配到渠道且 `baseUrl` 非空 + `apiKey` 非空（wan 格式豁免 key）。渠道为空 → 恒 false。
3. **弹窗触发路径（v3 定稿全集）**：
   - agent op：agent 后端 `run_generation` op → `use-agent-bridge.ts:63-71`（:68 调用）→ `handleGenerateNode`（project.tsx:3326-3338）→ `!isAiConfigReady` 时 `openConfigDialog(true)`（:3335-3337）。
   - 工作流批次：批次 runGeneration 回调（project.tsx:993-1043，:1000 调用）→ 同上入口。
   - 插件宿主：`ensureReady`（use-plugin-host.tsx:46-51）直接 `openConfigDialog(true)`+throw；`ctx.ai`（含 generateImage/generateVideo/generateText）经 `buildNodeContext` 注入**每一个**插件节点（plugin-node-context.ts:25），toolbar ctx 同样可达（use-plugin-host.tsx:131）；远端动态插件开机即载（:149-152）——**任何插件代码路径都可能是程序化触发方**。
4. **用户误配**：「本地代理」（网络转发）与「渠道凭据」（AI provider）是两套独立配置——用户配了前者，缺的是后者；弹窗从未说明缺什么。（`openConfigDialog` 默认 tab 即 "channels"，use-config-store.ts:252。）
5. **非弹窗异常（不在本方案修）**：`MCP 调用的参数必须是一个纯对象: <nil>`（Go 风格文案，全仓无命中 → Hermes 网关侧，卡 C 归档）；Codex 对话框「允许初始化对话」阻塞态（热更新打断 MCP 连接，另案）。

## 二、需求四问

① 谁用：所有者本人（画布操作者，通过右侧 Agent 面板驱动工作流）。
② 痛点只卡在哪一步：**工作流执行/审批触发生成失败时**——全局模态反复弹出阻断操作；失败原因（缺渠道凭据）从不显性告知。
③ 怎么算做成了：复现反馈视频场景（渠道凭据缺失 + agent/批次/插件驱动生成），程序化触发下弹窗次数 = 0，失败信息落在节点/插件错误上且写明缺什么与入口。
④ 与现有做法的关系：`openConfigDialog` 在**程序化路径**上一律不再触发；主画布用户手动生成/重试路径弹窗行为不变；插件路径统一改为错误+指引（§六 明示此行为变化）。

## 三、改点（三卡，原子拆分）

### 卡 A：程序化生成失败不弹全局模态（根治）
1. **`handleGenerateNode`**（project.tsx:3326-3338）：options 增加可选 `source?: "user" | "programmatic"`（默认 "user"）；`programmatic` 且 `!isAiConfigReady` 时不调 `openConfigDialog`，节点 metadata 置 `NODE_STATUS_ERROR` + `errorDetails`（i18n 双语，含 {{model}} 插值：「模型 {{model}} 未配置渠道凭据，请在【配置→渠道】添加」）。
2. **程序化调用点（穷举定稿）**：`use-agent-bridge.ts:68`（传 source: "programmatic"；同步加宽 `use-agent-bridge.ts:9` 的 GenerateNodeRef 类型）与 `project.tsx:1000`（options 追加 source）。其余调用点默认 "user"（project.tsx:4095 handleNodeRetry 用户重试、onGenerate 直接下传）。
3. **`ensureReady`（use-plugin-host.tsx:46-51）**：移除 `openConfigDialog(true)`，仅 `throw new Error(带指引的错误文案)`（i18n `canvas.plugins.aiConfigRequired` 增强为含 {{model}} 与入口指引，双语齐更）——插件宿主全路径不再弹模态，错误由插件 UI / 节点错误详情承载。
4. **`pollVideoNodeTask` 无需改动**：恢复轮询 silent（project.tsx:577）已落节点错误；非 silent 仅用户重试可达（:3799），保留弹窗。
5. **手动路径不变**：主画布用户点击生成/重试继续弹配置框；插件 Panel 用户点击改为收错误提示+指引（行为变化已在 §二④/§六 声明）。
6. **实施者复核义务**：开工前跑 `grep -rn "generateNodeRef.current" web/src` 与 `grep -rn "openConfigDialog(" web/src`，与 §三 清单比对；有新增调用点即停下上报，不得自行归类。
- **验收判据**：程序化触发（agent op / 批次 / 插件，三路径各验）弹窗 0 次 + 错误显性落盘；手动对照组（主画布）弹窗 1 次；路径①连续 3 次失败弹窗仍 0。

### 卡 B：失败详情显性引导
- 节点错误详情区渲染独立「去配置渠道」按钮，点击 `openConfigDialog(true, "channels")`（能力现成：use-config-store.ts:155/:252）。
- 错误文案结构化：模型名（{{model}}）+ 缺什么 + 入口。
- **验收判据**：错误详情含模型名与入口文案；点按钮打开配置弹窗且「渠道」页签激活。
- 依赖：卡 A 落地后验收。

**B3 探针规格（钉死）**：
- **触发机制**：① dev-only `window.__probeApplyOps(ops)` 钩子（仅探针用、生产构建剔除）——验 :68 路径；② 批次队列 UI（seed 待跑批次→运行）——验 :1000 路径；③ 插件宿主负向探针（**必跑**）：构造 ctx.ai.generate* 调用（借现有插件节点或最小测试插件）→ 断言无 modal 且错误可观测——验 ensureReady 改点。
- **种子**：seed 渠道凭据缺失配置；不得断言 `channels.length===0`（normalizeChannels 会重建 default 渠道，use-config-store.ts:472-483）。
- **判定**：可见 modal 计数 = `querySelectorAll` 后过滤 `getBoundingClientRect().width>0 && height>0`（antd Modal 用 `[role="dialog"]`+标题定位）；断言前**轮询至 modal 计数与节点状态连续 2 次采样（间隔 500ms）不变**；节点断言读 `metadata.status === NODE_STATUS_ERROR` 且 `errorDetails` 等于**当前语言的 i18n 期望串**（探针先取 i18n 展开结果再比对，zh 断「渠道」、en 断 en 文案关键词——不写死单一语言）。
- **用例集（必跑）**：路径①×3 次重复、路径②×1、路径③（插件）×1、手动对照组×1（弹窗=1）、**卡 B 用例×1**（点「去配置渠道」→ 断言 `[role="tab"][aria-selected="true"]` 为 channels 页签）、i18n 双语各一遍。
- **隔离**：独立 profile/独立 localStorage 种子，不污染真实配置；跑后恢复。

## 六、验收口径声明

本方案验收的是：**「配置凭据缺失时，程序化生成触发的全局弹窗归零 + 失败信息显性落盘」**。行为变化明示：插件 Panel 用户点击生成从「自动弹配置框」改为「错误提示 + 去配置渠道指引」（代价已被收敛表 #15 评估并接受）；主画布手动路径不变。网关侧 MCP nil 失败不在本方案范围（卡 C 另线移交）；反馈视频场景修复后仍会看到生成失败（网关侧），但不再有弹窗轰炸，且失败原因可见。
