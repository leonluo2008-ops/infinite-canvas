## 一、目标与范围

**目标**：画布从单人自用升级为对外多用户 SaaS（对标聚创形态）：注册登录 → 打开网页即用。一期路线 **C（BYOK）**：每用户自带渠道 key，服务端加密自管+代转发；预留升级 B（平台统一渠道+积分计费）的存储与网关接口。

**一期范围（四件套 + 前置）**：

|---|---|---|---|

**明确不做（一期）**：Agent 多租户（所有者拍板砍掉，canvas-agent 保持本地单人形态，与「Surface 服务器 Agent」另行立项）；积分/计费/支付（B 阶段，一期只埋用量审计埋点）；平台统一渠道（NewAPI 网关留 B 阶段）；协作/共享画布（远期）。

## 二、核心设计原则

1. **单人模式零改动（可测判据）**：`MULTI_USER=0`（默认）时——既有单人验收探针清单全绿；关键 API 响应 schema 与基线 diff 为空；文件路径/目录树 diff 为空；副作用（外呼/落盘）等价。排除时间戳、随机 ID 等非确定字段。固定测试夹具，快照比对。
2. **复用优先**：bootstrap-config 链路升级为服务端配置存储；canvas-proxy 转发语义（原样转发/SSE 透传/不落盘）为 bridge 代转发端点参考；config-store action 签名为前端唯一入口（铁律 7：参数合同指回引擎）。
3. **回归硬判据**：单人链路探针（入口 200/传图/拆解/生成结构核对）原样进每批次验收，全绿才算过；单人链路坏=FAIL 不打折。
4. **部署可回滚**：git 化部署位（S0）后回滚=`git checkout <旧commit> + build + restart`，分钟级。
5. **生产隔离**：多用户测试一律独立实例（独立端口+独立数据根），生产 :3001 只在批次验收通过后切换。

## 三、技术设计（一期 BYOK）

### 3.1 账号体系（D1）
- bridge 新增：SQLite 用户表（标准库 `sqlite3`）、注册/登录端点、session token。
- 密码：`hashlib.scrypt`（注意 `maxmem`，n=2^15 时默认 32MiB 上限会抛错）；SQLite 每线程独立连接（ThreadingHTTPServer 每请求一线程），WAL + busy_timeout。
- **开关语义**：`MULTI_USER=0`（默认）→ 全部新端点关闭、gate 走现 WAN_TOKEN 逻辑，单人部署零感知；`MULTI_USER=1` → **WAN_TOKEN gate 整体旁路**（两套口令不并存）。
- session：opaque 随机 token（可撤销），HttpOnly + SameSite=Lax + Secure（HTTPS 时）；过期/轮换/登出；CSRF 靠 SameSite=Lax + 关键写操作 Origin 校验。
- **邀请码（Q3 定稿：可管理邀请码）**：SQLite 邀请码表——高熵随机、限量/单次、可过期、可撤销；注册与登录限速 + 审计日志。拒绝单个环境变量共享口令形态。
- 部署拓扑与 cookie：生产形态浏览器→:3001（vite preview）→同源 /api 代理→bridge，cookie 同域天然可达；验收含「登录后经代理链调 API」冒烟；若未来直连 bridge 端口，补 `Access-Control-Allow-Credentials` + 精确 origin。

### 3.2 渠道配置服务端持久化 + 代转发（D2）
- 存储：SQLite `user_channels`（user_id, name, baseUrl, apiKey_encrypted, apiFormat, models_json）。key 加密 **AES-GCM（`cryptography` 库，Q4 拍板）**：主密钥=独立随机 secret 文件（权限 600、不入库、不在 DB、不进 git）；密文带算法/密钥版本字段；主密钥丢失=密文不可恢复，用户重新录入（产品文案明示）。依赖增加如实记入部署手册（Surface pip install cryptography）。
- **读接口零回显**：渠道配置读端点只返回 `hasKey`/脱敏尾号；任何端点（含错误信息与日志）不回明文 key。
- **前端改造（persist 层必改，store 结构/action 签名不动）**：
  - `merge()`/`useEffectiveConfig` 的 `channelMode:"local"` 硬编码（use-config-store.ts:275/309）改为模式感知；
  - `partialize` 只同步 channels 子集到服务端，**webdav 密码等敏感偏好不上传**（保持浏览器本地）；
  - **localStorage→服务端一次性迁移**：登录成功后读本地 `ai_config_store` channels → POST 服务端 → 本地键降级为缓存；登出反向恢复；迁移是 S2 硬验收项；
  - bootstrap-config 触发条件跟随模式（服务端模式登出态不再拉全站预置覆盖个人配置）。
- **请求层改造（4 文件列入工作量）**：image.ts/video.ts/audio.ts/model-plugin.ts 的 key 头/URL 拼 key 构造，服务端模式改发「channelId + 模型名」到代转发端点，bridge 注入 key；`isAiConfigReady` 的 key 非空检查按模式豁免；gemini `?key=` 查询串由 bridge 注入；`withLocalProxy` 的非渠道请求（image-storage/file-storage）不误路由进 `/api/proxy`。
- **代转发端点：`POST /api/proxy/<channelId>/<path>`**（定稿形态）：前端只传渠道引用+路径，bridge 查该用户渠道表取 baseUrl 拼目标——SSRF 面自动收敛。防护：注册渠道时+每次连接校验 scheme/端口/解析 IP（拒绝 loopback/私网/link-local/保留段含 IPv6 对应）；禁重定向或逐跳重验；方法白名单；请求体/超时/并发上限；SSE 流式：不设 Content-Length、按块 write+flush、剥 hop-by-hop 头、客户端断开处理。日志只记时间/方法/渠道 id/上游状态/耗时——**不记完整 URL query、不记任何 key/Authorization**。
- bootstrap 预置保留：站点管理员预置只下发非敏感元数据（无 key），用户 BYOK key 自行录入。

### 3.3 数据按用户隔离（D3）
- **路径规则（修正 v1 矛盾）**：`MULTI_USER=0` 时沿用既有根路径常量原值（`UPLOADS=ROOT/uploads` 等，代码路径不拼 user 段）；`MULTI_USER=1` 时按 `uploads/<uid>/` 分目录。建立 **API→数据路径清单**（上传/分析/资产/生成/项目/下载全部端点），逐端点属主校验——覆盖子进程读取路径与共享目录。
- **旧数据归属（R8）**：启用多用户时现存数据归属管理员账号（`local` legacy 归属映射），不迁移不动盘；管理端点可见，普通用户不可见。
- 并发：进程内信号量前提=单实例部署（明示约束）；每用户限额（拆解/生成各 1）+ 全局上限（Surface 4核16G，数值实施时实测定）；超限 429/503 带预期等待；daemon_threads + socket 超时 + 线程上限；崩溃占槽回收。

### 3.4 CORS 与部署（D4）
- `CANVAS_ORIGINS` 环境变量化（默认值不变）；CORS 白名单/可信反代/CSRF 三者独立控制，可信 Origin 不豁免认证。
- 部署：systemd 双 unit 不变；新增环境变量进同一 `EnvironmentFile`；多用户测试实例独立端口+独立数据根。
