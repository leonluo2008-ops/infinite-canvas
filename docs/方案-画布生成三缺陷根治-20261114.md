## 一、需求四问

① 谁用：所有者本人，画布 agent 面板驱动的视频拆解→置换生成工作流。
② 痛点卡在哪：agent 承接「拆解并按原视频重拍」任务时——a) 拉片被 text 模拟、成片不看原视频却**不告知**；b) 音频开关静默回落全局 false，成片无声；c) 出片后画布长时间卡 90% 无解释。
③ 做成的标准：agent 承接同类任务时——真拉片或明确告知「站方不支持视频参考，改用首帧/逐镜方案」；成片音频与用户配置一致且**节点上可见**；出片等待期有阶段态（生成中→下载中），不再无限停在 90%。
④ 与现有做法的关系：不改 V3/V6/V7 声音合同与 SDGF 提交体结构；不动拉片链 UI 既有路径；agent 侧是补契约与可见性，不是重写生成链。

## 二、改点（三卡）

### 卡 D：真拉片链 agent 承接（根治①·原子化拆分）
**机器现状（代码实锤，全部已存在，缺的是 agent 侧接线）**：
- 真拉片受控入口：`lapian-execute.ts` `executeLapianChain`（storageKey → /api/video/upload → /api/lapian/run → waitLapianContent 等正文；React-free，行为与手工路径逐字节同源）。
- 全链编排器：`workflow-instance.ts` `materializeWorkflowInstance` = 槽①真拉片 → 五槽代入 → 提示词组装 → 自检 → **停在待批**（P0b 付费红线：不自动发起视频付费，`workflow-instance-run.ts` 头注释）。
- agent 工具面（canvas-agent MCP，schemas.ts 已暴露）：`extract_workflow_template`（从当前画布节点抽模板并 saveTemplate 落库，workflow-batch-entry.ts:312-335）、`run_workflow_instance`（material：sourceVideoNodeId/storageKey/title/intentText/optionalSegments）、`run_workflow_batch`（审批后付费批量）。
- 本次事故真因：agent-instructions.md（13 行）只字未提 workflow 工具族与拆解决策路径 → agent 拿 canvas_generate_video 静默降级；空白画布也无模板可抽。

#### D1 · agent 拆解任务路由契约（指令文档，单文件改动）
`canvas-agent/agent-instructions.md` 增补决策树：
1. 用户要求「拆解/拉片/逐镜重拍」→ **首选 `run_workflow_batch`（内置模板 builtin-video-analysis，真拉片、终点=待审批）**；单条素材一次性验证可用 `run_workflow_instance`。material：sourceVideoNodeId/storageKey + 用户意图原话 intentText；替换图走 assetBindings（P11 槽指代）。
2. 仅当内置模板实例化失败（报错明示）或用户明确拒绝时，才声明降级（站方不支持视频参考 + 改用文本拆解需用户确认），**不得静默**。
3. **禁止**用 `canvas_generate_video` 冒充拆解工作流（那是单段文/图生视频）；站方不支持音频/视频参考（video.ts:211 站方 2026-10-22 事实）在承接时告知。
4. 停在待批时，必须向用户明报「拉片+组装+自检已完成，等你审批后批量生成」，**不自动续跑付费**（P0b 红线）。
- 验收（路1 BLOCKING 修正：断言真拉片发生，不断言文字）：真机/探针承接「拆解这个视频」→ 回执必须含 **lapian taskId 或 jobId（真任务建立）** 或明确失败原因；出现 lapian 拆解正文节点；绝不允许仅凭文字说明通过验收。**探针必须用新素材/非 replay 实例**（materializeWorkflowInstance 对已有 taskId 直接返回 already_present，workflow-instance.ts:635-639——命中 replay 拿到旧 taskId 不算证明真拉片发生）。

#### D2 · 内置模板端到端核验（独立可验收；取代 v2 的 seed 方案）
P12 已交付系统预置模板（workflow-builtin-template.ts：`builtin-video-analysis` /「视频拆解（内置）」，源视频→拉片→指令→意图→提示词配置→终稿→视频配置+人物/产品槽，五槽由 P2 在原型上算出，随代码分发零素材依赖）。**本卡不做新资产**，只做核验：探针真跑 `run_workflow_instance`（拉片段可 stub，其余全真）从 material 装配到停在待批全链贯通；真机抽一次小任务全程实跑。
- 验收：探针全链通 + 真机一次真拉片任务成功建立且正文回填。
#### D3 · material 装配核查（agent→工具参数桥）
核查 agent 装配 `run_workflow_instance` 入参的信息可得性：sourceVideoNodeId（canvas_get_state 可得）、storageKey（节点 metadata 可得）、intentText（用户话语）、assetBindings（P11 槽指代 slotNodeId/slotName）。缺口则补工具描述或 canvas_get_state 返回字段；不改 schema 结构。
- 验收：探针（拉片段 stub）——按指令文档装配 material 跑通实例化至组装完成。

### 卡 E：音频配置显性化 + 全局值修复（根治②）
1. **立即可做**：把全局 `videoGenerateAudio` 恢复 "true"（用户在设置页确认/我经探针核验当前值后恢复；恢复动作属于配置数据修正，不改代码）。
2. 代码根治（可见性）：生成节点 metadata 成功后保留 `generateAudio` 字段（现状已有）+ config 节点 UI 显示音频标志（「有声/无声」小徽标，数据源 metadata.generateAudio || 全局值，来源标注「继承全局」/「节点指定」）。
3. agent 契约：`agent-instructions.md` 增补——用 canvas_generate_video 生成时**默认显式传 generateAudio:"true"**（用户明确要求无声除外）。
4. **E4 · 工作台工具全局污染治理（两路审计同发现，音频回归的真复发向量）**：`agent-site-tools.ts:346-348` `workbench_video_generate` 会把 generateAudio **持久化进全局配置**——一次显式 false 即翻掉全局默认。**修法（定点复审裁定·修法B）**：保留全局写入行为（与该工具 model/size/seconds 等参数的既有持久化设计一致，不单独摘一项），但返回值 `note`/`applied` 必须显式含「已修改全局默认 videoGenerateAudio=<值>」；agent 契约（E3 指令）同步要求：工作台显式传 generateAudio 后必须在回复中告知用户全局默认已被改变。传递链扩展（单次生效）不在本期范围，如需要另立项。
- 验收（按模型分档断言，路1/路2 共识）：探针 mock——config 节点无 generateAudio + 全局 true → 成片节点 metadata.generateAudio==="true"，且请求体声音字段按 `sdgfSoundFields(model)` 实际合同断言（满血 GF=顶层 enableSound，ap 系=metadata.enableSound，sdgf-payload.ts:36-38/:53-54）；config 节点 UI 可见音频徽标（落点 canvas-config-node-panel.tsx:160 已有有效值计算）；**回归项（修法B口径）：工作台显式传 false 后，全局默认会改变，但回执必须含全局变更明示**（验收断言 note/applied 字段）。
