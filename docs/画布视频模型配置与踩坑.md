# 画布视频模型配置与踩坑

> 适用：infinite-canvas 及其服务器 SaaS 版（wanrepro）。
> 事实来源：`wanrepro/ui/server.py`（SDGF bridge 合同）、`wanrepro/ui/channel_store.py`（服务端渠道表与代转发）、
> `web/src/services/api/video.ts` + `sdgf-payload.ts`（前端合同）、`web/src/stores/use-config-store.ts`（渠道/模型结构）、
> `wanrepro/config/channel-config.json`（预置渠道）。
> 目标读者：要在这套画布上**从零配好一个能用、能出片的视频模型**的任何人（含其他 Agent）。

---

## 一、总览：视频模型是怎么落进画布的

画布里没有"全局视频模型"这种东西，只有一个三层链条：

```
渠道 ModelChannel  →  模型 ChannelModel  →  节点里选中的模型引用串 "channelId::model"
 (名称/baseUrl/apiFormat/apiKey/models[])
```

- **渠道**（`ModelChannel`）：`{ id, name, baseUrl, apiKey, apiFormat, models: ChannelModel[] }`
- **模型**（`ChannelModel`）：`{ name, capability, script? }`，`capability ∈ image | video | text | audio`
- **引用串**：节点/画布存的是 `encodeChannelModel(channelId, model)` = `"<channelId>::<model>"`；`decodeChannelModel` 反解。
  没有这个前缀的裸模型名只会在单人模式的默认渠道里生效。

**协议族由渠道的 `apiFormat` 决定**，不是由模型名猜：

| apiFormat | 标签 | 视频端点合同 | 服务器 SaaS 版 |
|---|---|---|---|
| `sdgf` | SD GF（聚鑫统一视频） | `POST {base}/v1/videos` / `GET {base}/v1/videos/{id}` / `GET …/content` | ✅ 主力 |
| `openai` | OpenAI 兼容 | `{base}/v1/videos` 一族 | ✅ |
| `gemini` | Gemini | `{base}/v1beta/models/{model}:predictLongRunning` + operations | ✅ |
| `wan` | 万相 CLI bridge | `/api/wan/video/*`（本机 CLI） | ❌ **整链下线，四路由一律 404** |
| 插件脚本 | 模型脚本 | `capability: "video"` 的脚本自己跑 | ✅ |

判定顺序在 `createVideoGenerationTask()` 里写死：**有模型脚本 → `wan` → `sdgf` → `gemini` → 其余按 `openai`**。

## 二、配置一个视频模型的步骤（用户视角）

1. 打开「配置 → 渠道」，点新建（预置渠道可直接用，但预置项**不可删除、名称只读**；新建**不能与预置重名**）。
2. 选 `apiFormat`。选 `sdgf` 时 `baseUrl` 自动预填 `https://sdapi.jxinai.com`（`defaultBaseUrlForApiFormat`）。
   ⚠️ 服务器模式下 `wan` 选项被禁用（服务端渠道表拒收）。
3. 填 `baseUrl`（**必须 https**；http 只放行 `127.0.0.1`/`localhost` 本地 mock）与 `apiKey`。
4. 配模型列表：手动加或「拉取模型」。每个模型必须把 `capability` 打成 **video**，否则节点里选不到。
5. **先保存再拉取模型**：服务器模式下 `apiKey` 只在保存时进服务端，未保存就去拉列表必然 401/空。
6. 到视频节点选模型：列表来源是 `selectableModelsByCapability(config, "video")`，只显示 `capability=video` 的模型。

**服务器（SaaS）模式额外三条**：渠道数据只存服务端（`user_channels` 表），前端零 key；
未配置 API Key 只进**灰色徽标**「未配置 API Key」，不进红色错误位；红色 error 位**写入者必须同为清除者**。

## 三、SDGF（聚鑫统一视频）协议：这是最容易配错的一段

### 3.1 端点与最小请求体

```
POST {base}/v1/videos            Authorization: Bearer <key>
{
  "model": "sd2.5-720p-ap",
  "prompt": "……",
  "duration": 4,                 // 4–30 秒
  "aspect_ratio": "9:16",        // 见 3.2 方言
  "enableSound": "on",           // 见 3.2 方言
  "metadata": { "ratio": "9:16", "enableSound": "on" },   // 仅别名族需要
  "mode": "首帧生视频",           // 见 3.3
  "images": ["https://…jpg"]     // 公网 https 直链，≥300px
}
→ { "id": "<taskId>" }
```

- `baseUrl` 归一：已带 `/v1` 就不重复拼（`sdgf_api_base`）。
- 轮询：`GET {base}/v1/videos/{id}` → `{status: queued|in_progress|completed|failed|cancelled, progress: 0-100, metadata.url}`。
- 成片：`metadata.url` 是完整 `http(s)` 就**直取且不带鉴权头**（可能落在第三方 CDN，别把 key 送出去）；
  是相对路径/空 → `GET {base}/v1/videos/{id}/content`（带 Bearer）。

### 3.2 两族方言（**同一套代码必须兼容，这是最大的坑**）

| | 满血名 `SD2.5-满血-GF-{480P\|720P\|1080P}` | 别名族 `sd2.0-720p-zh` / `sd2.5-720p-ap` 等 |
|---|---|---|
| 比例生效位 | 顶层 `aspect_ratio` | **`metadata.ratio`**（顶层被静默忽略） |
| 声音生效位 | 顶层 `enableSound: "on"` | **`metadata.enableSound: "on"`**（顶层被静默忽略） |
| 进 metadata 的比例白名单 | — | 只有 `16:9 / 9:16 / 1:1`（`4:3`/`3:4` 只发顶层） |
| 时长上限 | 4–30 原样 | `sd2.0-*` 系旧合同**上限 15 秒，超出截断**；`sd2.5-*` 4–30 |

判定函数：`sdgf_full_model()`（正则 `^SD2\.5-满血-GF-(480P|720P|1080P)$`，忽略大小写）、
`sdgf_ratio_fields()`、`sdgf_sound_fields()`、`sdgf_clamp_duration()`。
前端 `sdgf-payload.ts` 与后端 `server.py` 是**同一套规则的两次实现**，改一处必须同步另一处。

症状对照：画面比例不对（该竖屏出横屏）= 比例放错层；成片没声音 = 声音放错层。

### 3.3 mode 由「图片数」推出来，不要自己猜

| 图片数 | mode |
|---|---|
| 0 | `文生视频` |
| 1 | `首帧生视频` |
| 2 | `首尾帧` |
| ≥3 或显式 `reference` | `参考生视频` |

`mode=reference` **至少 1 张参考图**（渠道没有"0 图参考"模式）。

### 3.4 分辨率不发字段，按模型名定档

`resolution` 只用于**参数核对**：若模型名里带 `480P/720P/1080P` 而请求的 `resolution` 与之一致性不符，直接报错
「渠道按模型名定档，请换模型或改 resolution」。**本端点不发 `resolution`/`size` 字段。**

### 3.5 参数与超时（服务端 bridge 常量，改动需同步前端）

| 项 | 值 |
|---|---|
| 创建/查询超时 | 90s（与前端 axios 一致） |
| 成片下载超时 | 600s |
| 轮询间隔 / 上限 | 2.5s × 360 = 15 分钟 |
| 失败复核 | 站方存在瞬态 `failed` 自愈：连败 **3 次**（每次隔 8s）才判死 |
| 并发上限 | **2**（`BoundedSemaphore(2)`，项目红线），第三条 409 |
| 单视频上限 | `WAN_MAX_UPLOAD_MB`，默认 500MB |

**音频恒开**：产品口径（2026-11-15 所有者拍板），视频默认必须有声，界面上不提供无声选项。

## 四、参考图链路（决定"能不能出片"的第二大坑）

顺序（`host_image_detailed`，第一优先即所有者指定的腾讯图床）：

```
tencent(img.boostbite.cn) → local(/vc/ 公网基址) → litterbox → uguu
```

| 约束 | 值 |
|---|---|
| 参考图 URL 形态 | **只收公网 https 直链**；`dataUrl` 在 `confirm=true` 前必须换成公网 URL（dry 只做本地校验、不上传） |
| 单图上限 | 20MB（`sdgf_plan` 校验） |
| 渠道侧要求 | 长宽 **≥300px**（聚鑫文档） |
| 图床有效期 | 腾讯图床每 6 小时清空（所有者设定）→ **长任务要在 6h 内取走成片**，参考图直链也别指望长期存在 |
| 换不到就报错 | `ImageHostError` → 502 + `stage=host_images`，**零渠道请求**（不发起"没有参考图"的提交，那种片子与提示词无关还可能被渠道拒并扣费） |

前端上传侧兜底：>1MB 先瘦身（最长边 1600 / JPEG 0.85）；仅 5xx/无响应重试 3 次（0.9s 指数退避）。

## 五、踩坑清单（现象 → 根因 → 处置）

| # | 现象 | 根因 | 处置 |
|---|---|---|---|
| P1 | 竖屏需求出成横屏 | 比例只发顶层，别名族只认 `metadata.ratio` | 按 3.2 双写 |
| P2 | 成片没有声音 | 声音只发顶层，别名族只认 `metadata.enableSound` | 按 3.2 双写；audio 恒开 |
| P3 | 报「模型上限 15 秒」而请求了 30 | `sd2.0-*` 旧合同上限 15 | 换 `sd2.5-*` 或按 15 秒提交 |
| P4 | 上游 404，路径里出现 `/v1/v1/…` | `baseUrl` 自带 `/v1` 又被拼了一次；或代转发 subpath 没剥 baseUrl 路径前缀 | `sdgf_api_base` 归一；前端 `stripBasePath()` **只读 `config.baseUrl`**（不回落 store） |
| P5 | 上传成功，提交时渠道拒：图片拉不到 | 用了 `dataUrl`/IP/相对路径/被清掉的图床链接 | 一律公网 https；`sdgf_host_images` 换完**验活**再提交 |
| P6 | 生成到一半图床链接 404 | 腾讯图床 6 小时清空（所有者设定，**不要改**） | 长任务当场取走成片；长期留存另存 |
| P7 | 成片下载拿到一段 JSON | 渠道把错误体当 200 回 | 按 Content-Type 判，`json`/`text/` 一律当失败（先脱敏再截断） |
| P8 | 下载被 CDN 403 | 给第三方 CDN 带了 `Authorization` | `metadata.url` 完整 http(s) 时**不带鉴权头** |
| P9 | 进度条乱跳/停住 | 渠道 `progress` 脏数据（字符串、越界） | 只透传 0–100 的数字，其余当没有 |
| P10 | 一次 `failed` 就判死，其实云端还在跑 | 站方瞬态 `failed` 会自愈 | 连败 3 次（间隔 8s）才判死 |
| P11 | 重复提交、重复扣费 | 5xx/断连/2xx 无 taskId 时"状态不明" | 明确 502 报「状态不明，先到控制台核对，勿重提」；**不自动重试**；4xx 才原码透传可改后重提 |
| P12 | 并发两条就 409 | 并发上限 2（防重复扣费） | 串行或排队 |
| P13 | 服务重启后轮询 404 | 任务记录在内存 `JOBS` | 重新发起；成片仍在 `uploads/sdgf/<taskId>/成片.mp4` |
| P14 | 别人能下到我的成片 | 归属隔离缺失 | 成片目录写 `.owner` 侧车；非发起人与不存在**同形 404** |
| P15 | 服务器模式提交 401 | 前端带了 `channelId` 但未登录/会话过期 | 先登录；服务端**绝不回落 env 密钥** |
| P16 | 服务器模式 404「没有这个渠道」 | 传了别人的 channelId（与不存在同形，不泄露存在性） | 只能用自己的渠道 |
| P17 | 409「API Key 无法解密」 | 密文损坏或主密钥轮换了 | 重新录入完整 key |
| P18 | 503「未配置渠道主密钥」 | 服务端缺 `WANREPRO_CHANNEL_KEY`（base64 的 32 字节） | 重启时必须 `WANREPRO_CHANNEL_KEY=$(cat /home/luo/.config/wanrepro-channel-key.env)`——**该文件是裸 key，没有 `KEY=` 前缀，`source` 注入无效** |
| P19 | 参考视频/音频一起传就 413 | 代转发 `BODY_LIMIT = 8MB`（chunked 已支持，超限先于读体判 413，非法编码 411） | 大文件走文件存储/图床，不要把原始字节塞进渠道请求体 |
| P20 | 本机测试通、服务器 502 | 渠道直连走 `ProxyHandler({})` 绕系统代理；或链路回程断 | 服务端日志 200 而客户端 502 ⇒ **链路问题，禁改上传代码** |
| P21 | 新建渠道与预置重名 | 服务端按 `(user_id, name)` 唯一 + 预置名保留 | 换名；预置渠道禁删、名称只读 |
| P22 | 空 key 保存后界面仍报错红条 | 把「未配置 API Key」写进了永不清理的 error 位 | 只进灰色徽标；红色 error 位写入者=清除者 |

## 六、服务器版（SaaS）密钥与转发路径

```
浏览器 ──(channelId, 无 key)──> 服务端
                                 ├─ user_channel_for_request(): 按登录用户查 user_channels，解密 api_key_enc
                                 ├─ 视频提交 /api/sdgf/video/run：覆盖 payload.channel{baseUrl, apiKey}，model 仍由调用方选
                                 └─ 其他渠道请求 /api/proxy/<channelId>/<subpath>：服务端按渠道注入
                                    Authorization: Bearer <key>（gemini 改成 ?key=）
```

硬约束（`channel_store._forward` 与 `user_channel_for_request` 逐条实现）：

- 渠道 base_url **必须 https**，且不接受指向内网/回环的地址（服务端代转发持有 key，不能被打成内网跳板）。
- 代转发拼接是 `baseUrl.path + "/" + subpath`——**服务端不加 `/v1`**，所以前端必须自己剥 baseUrl 路径前缀。
- 无 `channelId` 的旧请求**逐字节不变**（单人模式/旧客户端走原路径）。
- 未登录 401 / 他人或不存在的 channelId 同形 404 / 密文坏 409 / 主密钥缺失 503：**零兜底，绝不静默回落到服务器 env 密钥**。
- 凭证只在请求内存里：不落盘、不进日志、任何响应都不回显（渠道错误文本里出现也抹成 `***`）。

**单人模式默认**才用服务器 env 里的 key（降级为默认值），这是设计里唯一允许 env 生效的场景。

## 七、模型清单与选型

预置渠道（`wanrepro/config/channel-config.json`，仅在新设备首次 bootstrap 时导入）：

| 渠道 | baseUrl | apiFormat | 模型（capability） |
|---|---|---|---|
| 聚鑫 | `https://api.jxinapi.com` | openai | `gpt-4o-mini-tts`(audio)、`deepseek-v4-flash-0731`(text)、`gemini-3.1-flash-lite-image`(image)、`gemini-3.8-flash`(multimodal) |
| SDGF | `https://sdapi.jxinai.com` | sdgf | `SD2.5-满血-GF-1080P`、`SD2.5-满血-GF-720P`、`SD2.5-满血-GF-480P`、`sd2.0-720p-zh`、`sd2.5-720p-ap`（均 video） |
| Ollama Cloud | `https://ollama.com/v1` | openai | `deepseek-v4.1-flash:1017`、`glm-5.3-flash`（text） |

选型建议：

- **要横屏/竖屏自由、要声音、要 1080P** → `SD2.5-满血-GF-1080P`（顶层字段生效，少一半坑）。
- **要 720P 竖屏、省成本** → `sd2.5-720p-ap`（别名族，必须双写 `metadata`）。
- **要短平快 480P 试水** → `SD2.5-满血-GF-480P`。
- **老合同兼容** → `sd2.0-720p-zh`（记得 ≤15 秒）。
- **服务器版不要选 wan**：整链 404。

## 八、部署检查清单（服务器 SaaS 版）

```text
1) 服务端渠道主密钥
   /home/luo/.config/wanrepro-channel-key.env  # 裸 base64(32B)，无 KEY= 前缀
   重启：WANREPRO_CHANNEL_KEY=$(cat 该文件) systemctl restart wanrepro-s1-test
2) 图床（第一优先，缺则回落 local→litterbox→uguu）
   WANREPRO_TENCENT_VC_BASE=https://img.boostbite.cn
   WANREPRO_TENCENT_VC_TOKEN=<agents|owner>
3) 单人公网基址（local 源需要）
   WANREPRO_PUBLIC_BASE=https://img.aistar.work
4) 多用户开关：MULTI_USER=1（关掉则渠道表整体不存在，带 channelId 一律 404）
5) 自检：登录 → 配置里新建/保留 sdgf 渠道 → 保存 → 拉取模型 → 视频节点提交 4s 试跑
```

**改远端配置的铁律**：不要"取回内容 → 本地改 → 写回"（SSH 包装脚本的 banner 会混进文件）；
一律在服务器侧用脚本就地改，改完 `nginx -t` / 重启后逐项回归。

## 九、改动铁律（防止前后端再次漂移）

1. **前端 `web/src/services/api/video.ts` + `sdgf-payload.ts` 与后端 `wanrepro/ui/server.py` 是同一份合同的两次实现**：
   改 ratio/sound/duration/mode/字段名，必须两处同改，并跑 `probe-s2-b3` 与后端 `test_multiuser_s1.py`。
2. 渠道请求只能走 `/api/proxy/<channelId>/<subpath>` 或 `/api/sdgf/video/run`——不要新开绕过密钥注入的直连口子。
3. 新增"事实型状态"（如未配置 key）只进徽标；红色错误位必须自带清除路径。
4. 视频链唯一实现基准是单机版 `standalone-v1.2.0`；SaaS 侧差异必须能说清"为什么必须不同"。
5. `git add` 只带显式路径；一批一验；不跨批混改。
