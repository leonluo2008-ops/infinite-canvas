## 3. 「组装提示词」内置功能：它是什么、能不能当转换承载

### 3.1 它是什么

配置节点的**提示词组装面板**（标题就叫「组装提示词」：`zh-CN.ts:298` `composer.title`，副标题「@ 引用已连接资产，发送前按当前连接重新编号」）。三个部件：

1. **参考位横条**：`canvas-config-composer.tsx:133` → `CanvasNodeReferenceBar`（`canvas-node-reference-bar.tsx:13-28`）：已连资产的缩略图 + 「+」按钮（`:22-24`）进入点选连线模式
2. **contentEditable 编辑器 + @ 弹层**：`canvas-config-composer.tsx:136-185`（@ 触发 `:76-85`，候选过滤 `:46-51`，插入 `:92-113`，键盘导航 `:152-182`）
3. **序列化/反序列化**：token 正则 `CONFIG_REFERENCE_PATTERN = /@\[node:([^\]]+)\]/g`（`:34`）；编辑器 → 文本 `:273-288`（引用 chip 输出 `@[node:${nodeId}]`，`:283`）；文本 → chip `:53-66` + `parseComposerTokens :359-370`

挂载点：配置节点面板走 composer，其它节点走普通提示词面板 —— `project.tsx:3241-3252`（`panelNode.type === Config ? <CanvasConfigComposer/> : <CanvasNodePromptPanel/>`）。

### 3.2 生成期怎么兑现（关键：这就是「转换」的承载）

`canvas-node-generation.ts`：

- 入口 `buildNodeGenerationContext`（`:40-64`）：**只要配置节点有 `composerContent`，就走组装分支**（`:43-45`）
- 组装分支 `buildComposerGenerationContext`（`:66-126`）：
  - 逐 token 扫描（`:76`），命中节点则按类型分配编号标签（`:82-91`）
  - 文本资源 → 以 `【文本N】` 占位（`:90`），正文以 `【文本N】\n<全文>` 追加到提示词末尾（`:87,98`，`textBlock :182-184`）
  - 图片 → `图片N` 编号（`generationLabel :186-191`，标签文案 `zh-CN.ts:40` `imageReferences.label = "图片{{index}}"`），并作为 `referenceImages` 真图送模型（`:99-101`）
  - 未被 @ 的已连资产**不参与**（`selectedInputs` 只装命中项）→ 「连线给全集、组装串给选择」
- 最终消息体：`buildNodeResponseMessages :159-170`（文本 + 图片 image_url 混排）
- 图片真值补全：`hydrateNodeGenerationContext :172-175`

### 3.3 能不能作为「拉片→提示词」的承载

**能，而且是唯一正解。** 拉片节点已被官方声明为文本资源（`builtin-nodes.tsx:31`：`resource: node.metadata.content ? { kind: "text", text } : null`），因此：

```
composerContent = "拉片正文：@[node:<lapianId>]\n任务说明：@[node:<instructionId>]"
```

生成时自动变成「拉片全文以【文本1】整段贴入 + 指令全文贴入」，模型拿到的是**完整 IR 原文**，不是摘要。这条链不需要 bridge `/api/render`，也不需要前端做字符串拼接。

**两个已知缺口（要在 T3-C 里补，不是阻塞）**：

1. 官方标签只出 `图片1`，**不带 2–6 字短说明**（`zh-CN.ts:40` + `canvas-node-generation.ts:90`），而硬约束 17 要求 `@图片1 香水`。补法二选一：① 指令模板里规定「按资产名补短说明」；② 扩 `generationLabel` 把节点标题并进去（一行改动，但影响面在生成期）。
2. 组装串里的 `@[node:]` 是**编辑期 token**，`canvas-node-generation.ts:76` 只认这个格式；手工写 `@图片1` 不会解析。所以模板文案必须用 `@[node:id]` 指向节点，正文里再谈「图片N」。

### 4.5 「资产组」现状判断

**资产库（我的资产）里没有「组」这个概念**——`use-asset-store.ts` 只有平铺 + tags。所以 T3-D 的「组资产一键挂入」有三种落地，官方承载点分别如下：

| 方案 | 承载 | 评价 |
|---|---|---|
| A. 画布 Group 节点当组 | 手动框选 → 右键「编组」→ 连线到配置节点（连上即展开） | **零新代码**，已是官方行为；只差「一键」 |

## 8. 遗留风险 / 待所有者裁定

1. **拉片未跑完就点按钮**：`metadata.content` 为空时派生会得到一个空文本引用。官方反推是硬拦（`project.tsx:2054-2057`），建议同款硬拦 + 文案「拉片还没出结果」。
2. **`# 附注` 剥离**：现有 `lapianPromptPreset` 剥附注（`project.tsx:917-918,927-928`，v4 审计 B-03）。走 composer 内联 `metadata.content` 时**不会剥**——需要在派生时把剥好的文本写进指令/或保留现有预填路径，否则附注会随提示词进生成（这是已知复发点，必须在 T3-B 里决定）。
3. **配置节点组装串 vs prompt 的优先级**：`composerContent ?? prompt`（`canvas-config-node-panel.tsx:35`、`canvas-node-generation.ts:43`）——一旦写了组装串，`prompt` 不再参与。T3-B 要保证组装串一定带上拉片与指令两个 token。
4. **`templates/` 五套模板正文在前端还是后端**：本报告建议前端常量（切换即时、不依赖 bridge）。若坚持「模板唯一真源在 `templates/`」，则切换时需 `GET /api/render/{taskId}/{template}` 取渲染结果（`ui/server.py:1048-1051`），但那是**终稿正文**不是**指令**，语义不符——故仍建议前端保存「指令模板」，`templates/` 保持为「渲染模板」唯一真源，两者不混。
