# 任务交接书：infinite-canvas·wanrepro 服务器化部署（目标机 Surface）

- 日期：2026-11-15（方案定稿，执行在新会话）
- 状态：方案已获所有者拍板（「按照这个方向推进」），**未落正式方案文档、未审计、未动工**
- 目标机：Surface（`luo@100.126.167.88`，Headscale 内网，Ubuntu 24.04，主机名 luo-Surface-Pro）

## 一、任务目标

把 wanrepro 画布工具（web 前端 + bridge）部署为服务器形态，为其他电脑提供服务：
1. 通用、快速部署安装（换机「装依赖→填 .env→一条命令起服务」≤30 分钟出可用入口）。
2. 服务器承载、使用端浏览器访问零安装零密钥。
3. 使用端（尤其拆解端）硬件要求低——已取证，使用端零要求。

## 三、目标机实测事实（2026-11-15 实测，直接可用）

- 4 核 CPU / 16G 内存（空闲 8.7G）/ 无 NVIDIA（核显 HD 620）/ 15 天连续运行 load≈1.2
- ffmpeg 6.1.1 已装（PATH）；Python 3.12.3；Node v22.23.2
- `/`（nvme0n1p5）92G 剩 47G；**`/home`（nvme0n1p7）535G 剩 411G** ← 部署落这里
- 已跑服务：Hindsight API :8888（health 正常）；:3000/:8779 空闲无冲突
- 拆解硬件结论：拆解大脑在云端 Gemini 3.8 Flash（jxinapi），转写 faster-whisper device=auto 无 GPU 自动落 CPU（慢但不出错，旁路不阻塞主链）→ **无 GPU 不影响承载**

## 六、红线与坑（逐条继承，执行会话必读）

1. **红线**（所有者原话）：「基于已完成的开发成果去做后面的事情，不要破坏已有技术基础和成果」——只加部署壳，不改业务代码。
2. **密钥**：交接书/文档/日志里一律不得出现明文密钥；.env 由执行会话从本机 scp/亲自迁移。
3. **文档**：SYNC-GUIDE 类禁硬编码绝对路径，标 must-do/optional/already-done；报告用文档发、只留唯一最新并清中间产物。
4. **验证零兜底**：FAIL 如实记，禁降级静默容忍。
5. **Surface 同机已有 Hindsight :8888 在跑**——部署动作不得影响它；systemd unit 名与端口错开。
6. **SSH 细节**：目标机默认 shell 是 zsh；命令带 `*` 通配符需引号包住（`no matches found` 会翻车）。
7. 图床双源（litterbox 主 72h / uguu 备 3h）是刚转正的配置（commit `a35b459` 已含），服务器出站要能访问 litterbox.catbox.moe / uguu.se / api.jxinapi.com / 视频渠道域名——**B1 时先在 Surface 上 curl 探一遍出站连通性**，国内网络环境可能需代理（Surface 若走 clash，注意 TUN 假 IP 坑：nslookup 见 198.18.x = 出口问题，别误判服务不可用）。
8. `fork` remote 既有：`git push fork dev` + `git push fork dev:auto`；当前 HEAD `a35b459` 与远程一致。
9. 本机开发环境（8776/8779 双 bridge + vite :3000）**不动、不停**——服务器化是并行新增，不是迁移替换。
