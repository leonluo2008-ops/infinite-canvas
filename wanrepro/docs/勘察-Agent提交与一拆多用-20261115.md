## 二、方案方向（拆卡建议，等所有者拍板后按标准流程走：方案落盘→双路审计→实施→亲验）

### 卡 A：提交通道（已取消——通用通道现成）
- 真机证伪：agent 用 config 节点 + `run_generation` 即完成提交（2026-11-15 无限画布 4，两个生成节点带资产图进入生成中）。
- 降级为契约条目（agent-instructions.md）：「提交待批实例 = 对实例的视频生成配置节点 run_generation；仅凭所有者显式提交指令执行，禁止自主批量提交」。另规范：优先复用实例**自带的**视频生成配置/组装链（本次 agent 绕过实例组装、自建提示词生成配置走 deepseek-v4 重写提示词——能用但偏离了拆解成果复用的设计意图，批量场景应在契约里定死「有实例组装链就用实例的」）。

### 卡 B：下载通道（已取消——2026-11-15 所有者指正）
- 成片本来就走「生成完成自动下载落节点」链路（poll→blob→节点内容，F3 修复即此链），画布即验收面。无缺口，不做任何新方案。

### 卡 C：一拆多用（变体实例化，设计卡）
- 目标形态：同一拉片节点（lapianSourceId 复用）+ N 个变体实例（各自独立 instanceIndex/资产槽/组装/生成节点），只跑一次拉片。
- 与 hub 侧 AT21 派生复用设计（设计-派生复用-20261112.md：共享 bridge_id 拆解产物、独立资产图）概念同源，画布线落地要单独出设计文档（含与 AT21 的概念对齐、批内 index 撞车问题并入）。
- 注意：不破坏已有人工链路——变体是「叠加新增」，已有单实例行为零改动。
