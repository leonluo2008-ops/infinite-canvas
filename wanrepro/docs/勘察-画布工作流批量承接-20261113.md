### 2.2 用户口中「确认做好、可以执行的工作流」最接近现状的什么

**= 某个画布项目里那条已经跑通的链路实例本身**（节点 + 连线 + metadata 快照，含 `taskId/jobId/intent/lapianModel/content/videoTaskProvider`）。理由：

1. 画布持久化的粒度就是项目（`use-canvas-store.ts:42-66`），链路只是项目内的一个连通子图，代码里没有任何"链路实体"。
2. 所有"参数"都以节点 metadata 形式散在链路上（`types/canvas.ts:50-140`：`promptTemplate/lapianOptional/lapianModel/assetSlot*/composerContent/model/size/seconds/vquality`），没有集中声明。
3. 「确认做好」在代码里没有显式标记位——没有"已验收/已发布"状态；唯一近似语义是「这条链跑通过（有终稿/有视频产物）」。

## Q3 批量提交器的承接点（外部如何驱动画布）

### 3.1 画布侧可编程 API（唯一现成驱动通道 = canvas-agent）

| 能力 | 接口 | 位置 |

**这套 API 的能力边界（对批量层至关重要）**：
- ✅ 建节点、连线、写 metadata、切视口、触发单个节点生成；
- ✅ 轮询生成状态（`generation_get_status`，按 nodeIds 批量查，含 error）；
- ⚠️ **没有"完成事件/回调"**，只能轮询；状态是节点 `metadata.status` 的派生视图（不是独立任务队列）；
- ⚠️ 读正文受限：`canvas_get_state` 把 `metadata.content` 截到 240 字符（`canvas/tools.ts:21-24`），长提示词/拉片正文读不全；
- ❌ 没有链路/子图事务（部分失败无回滚）；❌ 没有项目 CRUD（项目只在浏览器存储里；`canvas_list_projects` 读页面内 store）；
- ❌ 没有服务端执行——**所有生成都在页面里由前端 fetch 渠道完成**（`services/api/video.ts:84-96`），因此浏览器必须常驻且带 localStorage 里的渠道配置。

### 3.4 「批量系统自动提交画布工作流」的最小侵入路径

#### 路径 A（推荐，零引擎改动，有人在线）

```
模板(画布项目子图 JSON)  ──►  批量层(新)  ──►  canvas-agent /api/tools
                                              ├─ canvas_get_state        （读模板实例现状）
                                              ├─ canvas_apply_ops        （实例化：add_node/connect_nodes）
                                              ├─ canvas_update_node      （换素材：composerContent / assetSlot / intent / 参数）
                                              └─ canvas_run_generation   （逐节点触发）
                                                    └─ 轮询 canvas_get_state.metadata.status 收结果
```

- **复用**：`/api/tools` 全部写能力（§3.1）、画布节点渲染与门禁、`composerContent` token 参数槽、渠道配置（localStorage）。
- **必须有**：一个常驻浏览器页 + 画布项目打开（`session.ts:441` 硬要求）。
- **缺什么（要新增，属 B0 范围）**：
  1. 「模板」文件格式与抽取器（从项目 JSON 抽子图 + 声明参数白名单）——可基于 `canvas-export` v3 格式（`types/canvas-export.ts:3-19`）；
  2. 实例化器（模板 + 素材 → ops 序列；建议纯函数放 `web/src/lib/canvas/` 供前后端同用）；
  3. 批次实体与状态聚合（建议只做"派生视图"，状态真源仍是节点 `metadata.status`——禁建第二状态源）；
  4. 结果全文读取（`compactNode` 截断 240 字符，`canvas-agent/src/canvas/tools.ts:21-24`）——需要新工具或放宽截断。

#### 路径 B（无人值守，需新增服务端能力）

- 把模板翻译成**引擎任务序列**，直接打 bridge：`/api/lapian/run` → `/api/render/*` → `/api/sdgf/video/run`（或复用 hub 的 `/api/hub/*` 状态机）。
- 优点：无浏览器、可并发、状态机与审批链成熟（`automation/state.py`）。
- 代价：需要"链路解释器"把画布节点图映射到引擎调用序（画布节点与引擎概念不是一一对应：Config 节点既可能是 text 也可能是 video 生成；资产位/挂图是画布独有）。
- 风险：与所有者「画布=主操作面」的方向要划清——**模板仍是画布产物，B 只是另一个执行体**。

**建议（供 B0 拍板）**：双执行体、单合同。模板 JSON 是唯一事实源；首版只做 A（有人在线、可视化、复用画布门禁与审批语义），B 作为后续批次，且必须复用 `automation/state.py` 与付费两段式闸，不新造状态机。

## Q4 待审批包在画布的呈现方案

前提：批量跑完的产物必须能被"人批量看包拍板"，且**UI 原型需另行给所有者审批**（本卡只给文字+草图级骨架，不画高保真）。

### 候选 A（推荐）：画布右侧边栏新增「待审批」页签

- 落点：`canvas-side-panel.tsx:104-106` 现有三页签（画布 / 资产 / 提示词库）后加一页「待审批」，不改画布主视口布局。
- 骨架（文字版）：
  ```
  侧栏 480px
  ┌───────────────────────────────┐
  │ 画布 │ 资产 │ 提示词库 │ 待审批(3) │
  ├───────────────────────────────┤
  │ 批次 B-20261113-01  ▸ 12/12 完成 │
  │ ┌──────────┬──────────────┐   │
  │ │ 成片缩略  │ 任务标题        │   │
  │ │ (静音帧)  │ 素材：香水A→换B  │   │
  │ │          │ 自检：2 项待看   │   │
  │ │          │ [通过][退回][定位]│   │
  │ └──────────┴──────────────┘   │
  │ … 逐条 …                       │
  │ 底部：全选 [批量通过] [批量退回]  │
  └───────────────────────────────┘
  ```
- 「通过/退回」动作复用既有审批语义（`hub_api.do_approve/do_rollback`，`server.py:2462/2584`）；「定位」= `focusNode` 到该实例的结果节点（画布已有 `focusNodeRef`）。
- 优点：零新页面、就在操作面旁边、实例与画布节点一一对应可当场看/改。
- 风险：侧栏宽度有限，成片与长提示词看不全 → 点条目可「在画布中展开」或打开现有任务详情抽屉。

### 候选 B：批次审片全屏页（`/canvas/:id/review?batch=…`，极简）

- 骨架：
  ```
  ┌───────────────────────────────────────────────┐
  │ 批次 B-…｜12 条｜已完成 12｜通过 3｜退回 1        │
  ├───────────────────────┬───────────────────────┤
  │                       │ 任务 7/12  ▲▼ 键盘 j/k │
  │      成片播放器        │ 素材替换前后对照图       │
  │      (带音轨)          │ 自检结论（3 条折叠）     │
  │                       │ 提示词（折叠，可跳画布）  │
  ├───────────────────────┴───────────────────────┤
  │      [退回并写理由]            [通过] [下一条]   │
  └───────────────────────────────────────────────┘
  ```
- 优点：审片效率最高（一屏一条、键盘流水线）；适合"人批量拍板"这个专门动作。
- 风险：脱离画布上下文；需要新路由与新的数据聚合端点。

### 明确不做（避免返工）

- ❌ **不新造「审批包节点」类型**：违反本项目「节点数量最小主义」纪律（结果在产生它的节点内呈现，不造下游展示节点），且审批是流程态不是画布实体。
- ❌ 不在本卡画高保真 UI；候选骨架仅供 B0 合同讨论，UI 原型另行审批。
- ❌ 不把审批状态写进节点 `metadata.status`（该字段语义是生成态：`canvas-node.tsx:476-477` 的 loading/error 通用分支在渲染表 `:491` 之前就拦掉内容渲染），审批态应派生自实例结果 + 后端状态。

## B0 合同建议条款（供主代理汇总）

1. **单一事实源**：工作流模板 = 画布项目 JSON 的一个连通子图（沿用 `types/canvas-export.ts` v3 文件形态）。批量层**不得自造第二套模板格式**；模板必须能在画布上原样打开。
2. **模板参数白名单（可变槽，首批）**：①源视频节点；②意图文本（`lapianIntent` 节点正文）；③资产位挂图（按 `assetSlotOrder`，写 `attachedImageId/assetSlot.attachedImageId`）；④生成参数（`model/size/seconds/vquality`）；⑤可选段（`lapianOptional`）。**冻结项**：指令模板 id、连线拓扑、Config 的 `generationMode/composerContent` 结构。
3. **红线 25 复用条款（写进验收判据）**：模型判定/画幅规约/方言映射/上传承载四类，批量层必须 import 或调用现成实现（路径见 §3.5），审计含「自造轮子扫描」：凡新建同类函数且写不出画布对应物 = BLOCKING。
4. **执行体条款**：首版执行在画布内（canvas-agent `run_generation` + 页面内渠道 fetch），**要求浏览器在线**；无人值守执行列为后续批次，且必须复用 `automation/state.py` 状态机与付费两段式闸（`confirm=false` 预演 → `confirm=true`），禁新造状态机。
5. **状态真源条款**：批次/实例状态一律**派生**自节点 `metadata.status`（生成态）与后端任务状态；禁在画布 metadata 另存"审批状态"字段（`status` 已被生成流占用）。
6. **审批条款**：批量审批只承载"看与拍板"，动作复用既有 approve/rollback 语义；**付费提交仍须人在场确认**（红线不变）。
7. **数据可见条款**：模板与批次数据必须能在界面上走查到（模板→画布实例→节点；实例→成片/提示词/自检），符合「界面可见才算验收」。
8. **缺口前置条款**：状态可查但正文不全——`canvas_get_state` 的 240 字符截断（`canvas-agent/src/canvas/tools.ts:21-24`）必须在本期解决（新工具或放宽截断），否则批量层读不到完整提示词做自动判定/自动修改。
9. **不做清单**：不做新节点类型承载审批；不改引擎口径；不复制模型/画幅/方言/上传实现；不动 hub 现有审批合同（只做消费）。
