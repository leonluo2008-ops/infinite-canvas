## 三、AT-21 B0 合同清单（7 项，冻结后 NO-GO 转 GO）

1. **私有清单副本**（裁决 3，吸收 M-1/A1/A12）：fork 时把 `待确认清单.md` 复制为 fork 任务私有副本，副本内 `local:` 引用重写指 fork 自己的 asset-uploads；此后 hub 链对 fork 的清单/sidecar 读写全部走私有副本，源任务清单永不被 fork 触碰。「继承配对」语义降级为「继承可重绑的起点状态」（fork 在 awaiting_assets 确认置换时自然重绑）。共享拆解产物（九层/资产图/帧图/九宫格）按 bridge_id 只读共享不动。
2. **inbox 复制**（裁决 3，吸收 M-2/A5/A13）：fork 的 inbox 复制同 sha 源视频文件 + `.源视频指纹.json` 同抄；uploads 删除守卫（按各任务 inbox 同 sha 扫描）由此天然覆盖 fork；验收合同补「删除源任务后 fork 源视频可读」断言。
3. **直写提示词**（裁决 2，销 B-1/A7）：手改直接写 `提示词.md`（唯一权威正文）+ `prompt_edited_at` 留痕 + 重算 `approval_snapshot` + 自检/音频门禁重跑；端点 `POST /api/hub/task/{id}/prompt`；方案与子文档中 override 字样全部清除。
4. **守卫语义**（裁决 1，销 B-2；A3 硬守卫路线否决、吸收强制重跑要求）：自检 FAIL 不阻断提交；E3 闭环与手改后自检强制重跑、FAIL 如实显示红条；人工终审所有者做。

6. **删除守卫销项**（m-2，A13 分析产物侧）：`_bridge_still_referenced` 按 bridge_id 扫任务.json 已天然覆盖 fork（fork 写同 bridge_id 即被守卫看到），无需新代码；原方案「删除守卫需核实覆盖 derived 关系」担忧销项；uploads 侧由第 2 项覆盖。
7. **状态守卫顺带**（m-3）：`set_asset` 既有 image_url/clear/text 分支补状态守卫，列为本 B0 合同卡顺带项（decision 分支已有守卫；approved/generating 态可改清单不破坏付费防线——提交只读 `assets_confirmed` 快照——但会漂移自检重放口径）。
