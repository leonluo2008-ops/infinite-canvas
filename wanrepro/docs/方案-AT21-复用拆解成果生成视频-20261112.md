# 方案：AT-21 复用拆解成果生成视频（派生变体）

日期：2026-11-12　分支：feat/automation　状态：双路审计已收敛（NO-GO → B0 冻结后转 GO）
所有者拍板记录：D1–D6 按主代理推荐批准（2026-11-12 夜）；设计卡 t_2040fa4f。
双路审计收敛裁决：见 `docs/审计收敛-AT21-AT22-双路裁决-20261112.md`（裁决 1–6）；本文已按裁决修订，指控编号（B-*/M-*/m-*/A*）对照见收敛文档 §二。

## 一、需求（所有者原话）

「如果我对第一次生成的视频不满意需要做微调，目前是没有办法做微调的。我需要一个"复用"功能：能够复用之前拆解成功的成果，去编辑提示词或者替换某些资产，然后重新提交生成视频。」

场景：任务 done 后不满意 → 不重跑拆解 → 改提示词/换资产 → 重新提交生成（多版本并行对比）。

## 二、现状与缺口（代码级）

- 状态机单向逐级（automation/state.py transition）；done 无**前向**出边——done→failed 引擎层合法但零调用点；受控回退边共三条 + failed→discussing 重试：rollback_to_assets（AT-9，awaiting_approval→awaiting_assets）、reject_back_to_approval（AT-13，approved→awaiting_approval）、recover_orphan_generating（AT-13，generating→awaiting_approval）；
- hub 详情页提示词段纯只读（task-detail-drawer.tsx:2147 起 PromptSection，行号按双路审计核对表更正；空态「提示词尚未生成（确认置换后由后台渲染产出）」），无编辑能力；
- 「用我的描述」在 web/src/pages/hub 无任何入口（grep 零命中），只能改磁盘清单文件；
- 已有近似能力：「重试」产物优先（failed→discussing）；「换模型重批」（awaiting_approval 撤销批准链）；画布 model-script-editor.tsx 为渠道 JS 适配脚本编辑器，与提示词零数据通路（已裁定不复用）。

## 三、设计（拍板结论）

D1 派生新任务：POST /api/hub/task/{id}/fork → 新 local_id（走既有编号+墓碑防复用）；源任务只读不动。fork 落 awaiting_assets 的 bootstrap 合法性（受控初始化 + 完整 history，禁手写 state）随 B0 合同卡冻结。
D2 继承范围：
  - 源视频：**inbox 复制**——fork 的 inbox 复制同 sha 源视频文件 + `.源视频指纹.json` 同抄（uploads 按原名去重非内容寻址；复制后既有 `_uploads_video_shared` 守卫按 inbox 同 sha 天然覆盖 fork，删源任务后 fork 源视频可读）；（裁决 3）
  - 拆解产物：**引用同一 bridge_id，共享只读**（九层/资产图/帧图/九宫格零复制；删除守卫 `_bridge_still_referenced` 按 bridge_id 扫任务.json 已天然覆盖 fork，无需新代码）；（裁决 3）
  - 资产图：**复制文件**到新任务 asset-uploads/（小图成本可忽略；删源任务不影响变体）；**待确认清单.md 复制为 fork 任务私有副本**，副本内 local: 引用重写指 fork 自己的 asset-uploads——此后 hub 链对 fork 的清单读写全部走私有副本，源任务清单永不被 fork 触碰；「继承配对」降级为「**继承可重绑的起点状态**」（fork 在 awaiting_assets 确认置换时自然重绑）；（裁决 3）
  - 意图/渠道配置：继承；模板：hub 链固定 seedance-flow、无任务级模板字段，无「模板选择」可继承（双路审计事实更正）；
  - 不继承：生成历史、云端 taskId、提交状态、自检结果（重跑）。
D3 微调维度 V1：
  - 换资产：fork 落 awaiting_assets，走既有置换流（配对可改、可增删）；
  - 改提示词：**渲染结果手改微调，直写 `提示词.md`**（唯一权威正文：`prompt_edited_at` 留痕 + 重算 `approval_snapshot` + 自检/音频门禁强制重跑；端点 `POST /api/hub/task/{id}/prompt`）。override 文件路线已裁掉（裁决 2：改渲染读取顺序破坏 render.py 字节确定性合同、双真源时审批快照口径未定义）；
  - 编辑承载：**已裁决冻结**——`hub-text-editor.tsx`（doc variant）唯一承载，与 AT-22 E3 行内编辑两处复用（红线 25，谁先落地谁造）；不复用 model-script-editor.tsx（渠道 JS 脚本编辑器，语义/入参/形态三处不合）。
D4 版本关系：任务.json 增 derived_from（源 id）；get_task/_summary 透出；详情页「复用自 auto-XXXX」链接 + 源任务「派生版本」列表（读侧反查）。
D5 审批停点不变：fork 任务走到 awaiting_approval 由所有者亲手批准（付费铁律）。
D6 入口：done 任务详情页主按钮「复用为新版本」+确认弹窗（说明继承范围）；V1 不给 awaiting_approval 态开（用既有撤销重批）。

## 四、批次拆分建议

- B0 合同卡：字段/端点/状态机出边合同定稿，按收敛文档 §三 7 项清单冻结（含 fork bootstrap 合法初始化、双 fork 探针与隔离 fixture 的判据口径）；
- B1 后端：fork 端点（任务目录组装+资产复制+**清单私有副本**+**inbox 复制同 sha 源视频+指纹同抄**+derived_from+墓碑编号）+ `POST /api/hub/task/{id}/prompt` 直写正文 + get_task 透出 + 探针（fork 三种源状态/资产复制完整性/私有副本隔离/派生链透出）；
- B2 前端：详情页按钮+确认弹窗+「复用自」链接+派生版本列表+提示词编辑（hub-text-editor doc variant 直写 提示词.md+快照重算）+自检/音频门禁重跑挂接；
- B3 收口：全族回归+真机动线（done→fork→换资产→改提示词→审批）。**夜班不碰付费：真提交验收由所有者亲自走查，机器验收止步于审批快照断言**（裁决 5）。

## 五、验收合同

- fork 后源任务逐字节不变（含 任务.json/拆解日志/待确认清单.md/清单 sidecar——fork 清单读写走私有副本后此断言可机器判定）；
- fork 任务拆解产物零重跑（不触发 discuss/extract）；
- 手改提示词后：直写 提示词.md 生效、自检**强制重跑**且 FAIL **如实显示红条**（不阻断提交，人工终审由所有者做——裁决 1）；
- 删除源任务不影响已 fork 变体的资产与产物，且删除源任务后 fork 源视频可读（inbox 复制后 uploads 守卫覆盖——裁决 3 断言）；
- 全族回归零红（probe_retry_guard/probe_del_atomic/probe_at19_proc/probe_at16_b4a/b4b/probe_at18_reconcile/probe_hub --isolated；实现前先跑探针存在性断言——裁决 5，exec_judge 探针不存在已从清单删除）；
- 真机：所有者页面检查（见交付后检查指南）。

## 六、边界与风险

- 不做：批量派生、变体 A/B 自动对比、跨任务合并；
- 风险：手改可能破坏 @图片N 发号/锁点语义——手改后自检强制重跑、FAIL 如实显示红条（**不阻断提交**，裁决 1：与 AT-22 E4「让自检可信而非解锁」定位自洽，人工终审只能所有者做）；现状自检仅拦「@图片N 集合不一致」（refs 排序去重），语义级错配不靠机器硬拦，由所有者红条裁量兜底；
- 拆解产物按 bridge_id 共享是既有架构事实，fork 引用不复制（删除守卫已销项：`_bridge_still_referenced` 按 bridge_id 扫任务.json，fork 写同 bridge_id 即天然覆盖，无需新代码——m-2；uploads 侧由 D2 inbox 复制覆盖）。
