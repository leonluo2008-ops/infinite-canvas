## 零、一句话与结论摘要

「绑图行残留」判定误报的根因只有一条：**取词口径**。`entity_noun_core()` 把实体名第一个分句整段当核心词，
`_noun_grams()` 再切 2–3 字组——于是「从右下角入画的第一人称右手」这类**动作/视角描述型实体名**被切成
「右下角/下角入/角入画/第一人称」进了残留词表，把用户合法保留的构图描述判成旧物残留。

本轮在全量历史任务上重放自检②：**232 条命中里 19 条是误报（8.2%），全部落在 5 种可解释的源结构上**
（动作/视角命名、通用占位名、实体自身标签行、品类泛化词——见 §4.2）；
按推荐规则收窄后：**误报 19 → 1（0.5%），真残留 213 条零损失**。

| 决策 | 结论 | 数据依据 |
|---|---|---|
| E1 做不做 | **做** | 34 个有绑图行的任务里 4 个（11.8%）出现误报；其中 **3 个任务的自检「只因误报而红」**（无任何真残留）。默认模板 seedance-flow 下 19 条命中里 3 条是误报（15.8%），且这 3 条正是所有者撞到的那一例 |
| 做到什么程度 | **只动「取词」一步**：`entity_noun_core()` 输出后先删动作/方位/视角词，再交 `_noun_grams()` 切组；外加两条例外（通用占位名不进表、实体自身标签行豁免）。**不重建词表、不引入分词/模型、不动自检四项框架** | 同一语料同口径模拟：误报 19→1，真残留 213→213（零损失） |
| 明确不做 | ① kind 闸门（只对主体建表）② 实物名词白名单闸门 ③ 提高长度阈值 | ① 漏清 1 条真残留（道具行的原物外观仍在正文）② 漏清 **14 条**真残留 ③ 阈值提到 4 字：真残留 213→3（漏清 98%） |
| 残余风险 | 1 条「品类泛化词」误报（「外包装」命中拍摄手法句），靠 E4 白名单兜底 | 见 §七 |
| 与 E4 的关系 | E1 消掉 95% 的误报（结构性），E4 兜剩余（个案性）。**E1 的过滤点必须在取词阶段（进表前）**，否则「证据条数」与「展示条数」会分裂成两套口径 | 与 E4 方案 §一「过滤位置」一致 |

## 一、问题与已核实事实

### 1.1 现场复现（auto-0066，只读）

用现有函数（`selfcheck._prompt_body` + `selfcheck._check_residue` + `render.parse_checklist` +
`replace.load_groups`）在 auto-0066 的真实产物上重放自检②，**与落盘的 `自检.json` 逐字一致**：

```
结论: FAIL
证据: #6 的「右下角」残留于正文: …前景右手持@图片1自右下角入画，无剪切。2-4…；
      #6 的「角入画」残留于正文: …右手持@图片1自右下角入画，无剪切。2-4秒，…；
      #6 的「下角入」残留于正文: …景右手持@图片1自右下角入画，无剪切。2-4秒…
      ｜已传图行词表 3 行（#1→图1(5词)、#5→图1(9词)、#6→图1(12词)），正文 516 字
```

三处命中的**词**（右下角/角入画/下角入）全部来自 `#6 道具：从右下角入画的第一人称右手`，
而正文那句「前景右手持@图片1自右下角入画」是**借创意的构图/动作描述**（原片拍摄手法），
按产品规则必须保留。判定层无法区分「要换掉的原物」与「要保留的拍法」。

### 1.2 误报的两种后果（不只是红字）

1. **阻断与误导**：自检②FAIL → 详情页异常区；处理指引是「去 `analysis/reverse/<桥>/待确认清单.md`
   改『用我的描述』列」——web 用户不可操作（E3 已立项）。用户为了消一条假红，要退回置换 + 手改 markdown + 重渲染。
2. **清扫器会真的吃掉合法词**：`strip_core_residue()` 与自检②共用同一套词表。用真实函数跑合成句
   （词表=该实体，`@图片1` 紧邻）：

   | 原句 | 清扫后 |
   |---|---|
   | `右手持@图片1自右下角入画，无剪切。` | `右手持@图片1自右下角入画，无剪切。`（未动） |
   | `前景右手自右下角入画@图片1，无剪切。` | `前景右手自@图片1，无剪切。` **「右下角入画」被吃** |
   | `手持@图片1自画面右下方边缘斜向伸入。` | 未动 |

   即：只要**构图词恰好紧邻图号**，用户写对的句子会被削掉（`@图片1` 从「入画」处变成「自@图片1」）。
   本条是判定层缺陷，不是呈现层问题——E2/E3 修不了。

### 1.3 取词链路（代码位置，实现批次要改的就是这里）

- `pipeline/reverse/render.py:1218 entity_noun_core()`：命名优先 → 去 `A：` 前缀 → 去 `必须锁住…` 尾巴/括号 →
  取第一个分句 → 只留汉字。**整段当核心词**。
- `pipeline/reverse/render.py:1232 _noun_grams()`：对核心词所有 2 字与 3 字滑窗成组。
- `automation/selfcheck.py:348 _check_residue()`：`words = {core} ∪ _noun_grams(core)`，`len(w) ≥ 3`，
  全文子串匹配、每词报首处。
- `pipeline/reverse/render.py:1260 strip_core_residue()`：同一套词表，按 `@图片N` 左邻 CJK 链从右往左吃。

实测词表规模：**平均 10.1 词/行，最大 16 词**；核心词长度 5–17 字；2 字组已被 ≥3 字阈值挡掉（0%）。

## 六、推荐结论（可直接支撑 E1 的「做/不做/做到什么程度」）

**做，按 R3 落地，范围限定在「取词」一层。** 具体形状（实现批次照此拆，不在本卡改代码）：

```
entity_noun_core(ent)                      # 不动：命名优先 → 首分句 → 只留汉字
  → strip_action_words(core)               # 新增：删动作/方位/视角词（枚举黑名单）
  → if core ∈ GENERIC_NAMES: return ""     # 新增：通用占位名 → 空（不建表）
  → _noun_grams(core)                      # 不动：2–3 字组
  → [w for w in grams if len(w) >= 3]      # 不动：≥3 字阈值
selfcheck._check_residue: 跳过自身标签行（<命名>（<形态>）孤立行）
E4 白名单在「进表后、匹配前」再滤一次（与 E4 方案 §一 一致）
```

必须守住的四条约束（写进 B0 合同卡）：
1. **零漏清**：真残留样本（本轮 213 条）必须继续全部拦住——这是 E1 的验收红线，不是「误报变少」就算过。
2. **单一过滤点**：`render.strip_core_residue()` 与 `selfcheck._check_residue()` 必须共用同一个取词函数，
   否则「清扫吃掉的词」与「自检报出的词」会出现两套口径（现状已是同源，别改散）。
3. **空表 ≠ 跳过检查**：词表为空的行不建表（不报也不吃），这是正确语义（该行没有可替换实物词），
   但要在证据文案里写清「该行无可判词」而不是静默。
4. **黑名单只增不减**：每次新增必须带一条语料回归（本轮 66 任务重放脚本即基线），由方案审计把关。

收益量化（本轮语料）：误报 19 → 1（−94.7%），纯误报文件 3 → 0，**真残留 213 条零损失**。
成本量化：一个纯字符串函数 + 两张小词表（动作词 ~45 条、通用名 ~13 条）+ 一处标签行判断；
无模型调用、无新依赖、无 IO，性能可忽略。

