## 0. TL;DR

| 项 | 结论 |
|---|---|
| 病根 | 一条 finding 在可见区被说 3 遍（结论人话 → 原因 → 发现），第 4 遍在折叠区（证据）；行号/图号重复写 2 遍；用户看到的是字段值（`#6`、`图1`、`词表`、`正文 516 字`）而不是话 |
| 做法 | 生产者（`automation/selfcheck.py`）产出**结构化 finding v2**（行号＋行称呼＋图号＋图引用＋词＋命中片段），可见区**只渲染一次**；`说明.原因` 在 v2 不再产出；内部统计/键值/检查器原文一律进「展开看证据」折叠区 |
| 人话位置 | 「第 6 行「道具B」」（短名与资产置换卡同源，`automation/cards.short_names`）＋该行已传图缩略图，点击定位到置换卡（锚点合同见 §9.2） |
| 图不再叫「图1」 | 显示为「你传的产品图」，并带缩略图；`图1` 只出现在折叠区键值里 |
| 词不再裸奔 | 命中词用『』包住，出现在提示词上下文里并高亮（分段结构，前端不做字符串解析） |
| 影响面 | `selfcheck.py` 文案/结构层；`hub-api.ts` 类型；`task-detail-drawer.tsx` 的 `SelfCheckRow`/`GateBadge`；置换卡加锚点。**不改 `证据` 字段内容**，因此 `probe_at9`／`probe_at15_r2`／`probe_at16_b1b` 的既有证据断言默认仍绿 |
| 会让谁红 | `probe_at16_b2` 的 4 条断言（依赖 `说明.原因` 与 `#12` 写法），清单与改法见 §10.2——这是设计的一部分，不是回归 |

硬规则（照做即可，不再二次判断）：

1. 可见区一条 finding 只说一次；同一行同一句的多个词在**渲染层**并成一张卡（数据层仍一词一条，供 E4 逐词保留）。
2. `#N` 一律改「第 N 行「短名」」；`图M`/`@图片M` 一律改「你传的<实物称>」＋缩略图（提示词原文引用处不改字）。
3. 一切数字统计（词表行数、正文字数、绿项/缺项/告警、重拆轮次、行→图号映射、提交快照）只允许出现在折叠区。
4. 文案全部由生产者产出（红线 25）：前端只按槽位渲染结构化字段，不解析 `证据` 字符串，不拼业务话术。

### 1.1 重复点清单（以 auto-0066「绑图行残留」这一条真实 item 计）

| 同一信息 | 出现次数 | 出现位置 |
|---|---|---|
| 命中句 `…前景右手持@图片1自右下角入画，无剪切。2-4…` | **4 次** | 结论（间接）／原因／发现①～③／原始证据 |
| 命中词本身（右下角/下角入/角入画） | 3 条 × 各 2 处 = 6 处 | 发现列表 3 行、原因串 3 段 |
| 行号 `6` | 3 次 | 结论「涉及行 #6」、发现前缀 `#6`、每条文字内 `#6 的…` |
| 图号 `1` | 4 次 | 发现前缀 `图1`、文字/证据内 `@图片1`（2 处）、词表串 `#6→图1` |
| 内部统计 `已传图行词表 3 行（…），正文 516 字` | 1 次（折叠内，但用户已看到并引用） | 证据尾 |
| 「必换行」这类内部名词 | 结论1＋原因1＋发现1 | 锁点对账条目 |

> 结论：用户抱怨「根本看不懂」不是文案写得差，是**同一条信息在屏幕上出现了 4 次，且 4 次的措辞都是字段值**。E2 的活是把「一次」的信息压到一次，并把这「一次」写成话。

## 2. 目标结构：finding v2（生产者产，前端逐字渲染）

`说明.发现[]` 从「一坨文字 + 两个数字」升级为结构化 finding；`说明.原因` v2 起不再产出（旧数据仍可读，前端兼容分支保留）。

```jsonc
{
  "行号": 6,                          // 必填（无具体行 → 该键缺省，见 §3.3 无行变体）
  "行称呼": "道具B",                   // 短名：cards.short_names 同源，与置换卡标题一字不差
  "类别": "道具",
  "组": [1, 5, 6],                    // 该行所在确认组（无组 → 缺省）
  "图号": 1,
  "图称呼": "你传的产品图",             // 该图号主行类别 → 「你传的产品图/人物图/服装图/道具图/场景图/品牌图」；主行缺 → 「你传的图」
  "图引用": "local:auto-0066/asset-uploads/6a43ec602833b805.png",  // 该行已传图原串（local:… 或 https:…）
  "词": "右下角",                      // 一个 finding 一个词（与 E3/E4 的 word 对齐，见 §9.4）
  "句序": 3,                          // 命中句在提示词正文里的段/句序号（同「行号+句序」= 同一句 → 渲染层合并成一张卡）
  "上下文": "前景右手持@图片1自右下角入画，无剪切。",   // 命中句原文（不改字，供 E3/E4 直接吃）
  "片段": [                           // 同一句的分段高亮（前端按 高亮 上色，不做字符串解析）
    {"文": "前景右手持@图片1自", "高亮": false},
    {"文": "右下角", "高亮": true},
    {"文": "入画，无剪切。", "高亮": false}
  ],
  "原文": "#6 的「右下角」残留于正文: …前景右手持@图片1自右下角入画，无剪切。2-4…",
                                      // 检查器原句（折叠区「检查器原始输出」用；probe 断言改查此键）
  "可修": {"类型": "改描述"}            // 可选，E3 的声明键：仅残留类 finding 带；前端按声明渲染按钮
}
```

> 注意：`发现[]` 仍是**一词一条**（与 E4 的「保留这个词」逐词粒度一致）；「同一句的多条合并成一张卡」是**渲染层按 `行号+句序` 分组**的结果，不需要前端解析文字——分组键是结构化字段。

item 级新增／变更：

| 字段 | 变更 | 说明 |
|---|---|---|
| `项` | 不变（契约键，探针/前端识别用） | **不重命名**，否则 `probe_at9:218` 等会红 |
| `项显示名` | 新增 | 绑图行残留→「提示词里的老词」；次序对账→「图号与提交次序」；锁点对账→「该换的没换」；组绑定一致性→「合并组的图是否一致」；拆解门禁→「拆解产物检查」 |
| `说明.结论人话` | 重写（见 §7 各样例） | 一行说清「几处／哪几行／什么后果」 |
| `说明.原因` | **v2 不写** | 与 `发现` 同义，是最大重复源 |
| `说明.处理` | 保留，措辞按 §6 人话化 | 动作口径归 E3，本卡只定「不得出现路径/字段名」 |
| `说明.统计` | 新增：`{"词表行数":3,"正文字数":516,"组":[[1,5,6]],"行→图号":{"1":1,"5":1,"6":1}}` | 只在折叠区渲染 |
| `证据` | **内容不变**（兼容既有探针与排障） | 仅改为折叠区「检查器原始输出」块，不再与可见区并排 |

## 3. 单条 finding 最终模板（可见区）

### 3.1 布局（自上而下，槽位固定，不新增第三个字段说明）

```
⚠ 提示词里的老词                                         ← ① 项显示名 + 状态图标，一行
提示词里还留着 3 个要换掉的原物词，都在第 6 行「道具B」里   ← ② 结论人话（一条 item 只此一行）
┌────┐ 第 6 行「道具B」· 与第 1、5 行共用 图1（你传的产品图）   ← ③ 位置段（可点击定位）
│缩略图│   [去这一行]                                     ← ③b 定位按钮（E3 落地前置灰）
└────┘
这句里的『右下角』『下角入』『角入画』还在提示词里：        ← ④ 命中段
…前景右手持@图片1自【右下角】入画，无剪切。…              ← ⑤ 上下文（命中高亮，左右各 ≤12 字）
[改这一行的描述]  [保留这个词]                            ← ⑥ 动作位（E3/E4 落地前灰置占位，本卡只定位置）
▸ 展开看证据（内部明细）                                   ← ⑦ 折叠区（内容清单见 §4）
```

### 3.2 槽位来源与规则

| 槽位 | 内容来源（生产者字段／常量） | 规则 |
|---|---|---|
| ① 项显示名 | `项显示名` | 必填；缺失才回落 `项`（旧数据） |
| ② 结论人话 | `说明.结论人话` | ≤ 40 字；只允许出现「第 N 行「短名」」形态的行指代，禁止 `#N`／`图M`／字段名／数字统计 |
| ③ 位置段 | `行号`+`行称呼`+`组`+`图号`+`图称呼` | 模板：`第 {行号} 行「{行称呼}」`；有组 → 追加 `· 与第 {除本行外的组行号} 行共用 图{图号}（{图称呼}）`；`行称呼` 空 → 用 `类别`；`类别` 也空 → 只留 `第 N 行` |
| ③ 缩略图 | `图引用` | 走既有受控出口（`hubAssetRefView` + 资产健康态组件），尺寸 48×48、可点开大图；`图引用` 空 → 不显示缩略图，位置段追加 `（这张图已不在，可能是旧任务）` |
| ③b 定位按钮 | `行号`（锚点合同见 §9.2） | 同屏有该行置换卡 → 滚动＋高亮；没有（审批态不渲染置换区）→ 置灰＋Tooltip「先点『退回置换』回到资产置换区，再点这里」；E3 落地后换成行内编辑入口 |
| ④ 命中段 | `词`（渲染层把同组 finding 的词并起来） | 模板：`这句里的『{词1}』『{词2}』还在提示词里：`；单词 → `第 {行号} 行「{行称呼}」里的『{词}』还在提示词里：`（与位置段合句） |
| ⑤ 上下文 | `片段[]`（分组内按各自命中的词叠加高亮） | 前文/后文各截 ≤12 字（不足则从头/到尾），整体 ≤60 字；命中段高亮＝**下划线＋底色**（不只靠颜色）；原文一字不改（含 `@图片1`） |
| ⑥ 动作位 | E3「改这一行的描述」／E4「保留这个词」（逐词一颗） | 主按钮按**行**出一颗（E3，`可修` 声明在场才出）；次按钮按**词**出一颗（E4，同组多词则多颗，`ml-auto` 右对齐）；未落地时 `disabled` |
| ⑦ 折叠区 | §4 | 默认 `closed`，`<summary>` 文案固定「展开看证据（内部明细）」 |

### 3.3 三种变体

| 变体 | 触发 | 位置段写法 | 其余 |
|---|---|---|---|
| 有行（主例） | 有 `行号` | `第 6 行「道具B」· 与第 1、5 行共用 图1（你传的产品图）` | 全槽位 |
| 无行（整体问题） | 无 `行号`（如「提交张数不对」这类整条链问题） | `这次整体对不上，不是某一行的问题` | 无缩略图/无 ③b；④ 改为 `对不上的是：` + `片段` 里的短句 |
| 行已消失 | `行号` 有、`图引用` 空且清单无该行 | `第 6 行（这行已经不在清单里了）` | 无缩略图；③b 置灰 |

### 3.4 聚合规则（决定「几条」）

分组发生在**渲染层**，分组键是结构化字段 `行号 + 句序`（不解析文字）；生产者仍一词一条。

1. **同一行 + 同一句的多条 finding → 渲染成一张卡**：词并列进 ④（按长度降序），`片段` 里叠加所有命中区间高亮；动作位按 §3.2 ⑥ 出按钮。auto-0066 的 3 条（右下角/下角入/角入画）同属一句 → 现状 3 条卡，改后 1 条。
2. 不同行 → 每行一张卡，按行号升序。
3. 可见区最多 3 张卡；超出 → 第 4 张起写 `还有 N 个词在另外 M 行（展开看证据）`，折叠区给全量。
4. 重叠词（如下角入/角入画 互为子串且同区间）**呈现层不删不并词**（E4 要能逐词保留），但结论人话按「句」计数：`第 6 行「道具B」那句话里还有 3 个老词`——是否该报这些词属 E1，E2 不越界判定。

## 4. 折叠区内容清单（「展开看证据（内部明细）」）

顺序固定，块标题固定；全部默认关闭，任何一块都不出现在可见区。

| # | 块标题 | 内容 | 来源 |
|---|---|---|---|
| 1 | `内部统计` | `已传图行 3 行（第 1、5、6 行）｜提示词正文 516 字` | `说明.统计`（词表行数/正文字数） |
| 2 | `机器键值` | `行→图号：1→1、5→1、6→1｜正文 @图片1｜确认组 [[1,5,6]]｜必换行 1、5` | `说明.统计` 其余键 |
| 3 | `这一行的清单原文` | `| 6 | 道具 | B：从右下角入画的第一人称右手… |  | local:auto-0066/…png | 颜色… | 可沿用 |  |`（整行 md 原文） | 清单行 |
| 4 | `提示词里的原句` | 命中句所在整段（含前后各 1 句），标「第 N 段」 | 提示词正文 |
| 5 | `检查器原始输出` | `证据` 全文原样（含 `#6 的「右下角」残留于正文: …` 与统计串） | `证据` |

取舍说明（需所有者知情的唯一折衷）：第 5 块保留了「检查器原始输出」里的命中原句，即同一句在**折叠区内部**还有一份。理由：① 它是排障与探针的稳定锚点（`probe_at9`／`probe_at15_r2`／`probe_at16_b1b` 现有断言都读它）；② 默认关闭，不与可见区并排。
若所有者要求「连折叠区也只说一次」→ 备选方案 B：删第 5 块，`证据` 只留统计/键值，同时把上述 3 个探针断言迁到 `selfcheck` 单测（成本约半天，改动面 4 个文件）。

## 5. 去重规则（可执行的判定）

- **R1** 可见区不渲染 `说明.原因`；v2 生产者不写该字段。旧任务（有原因无 v2 字段）走 legacy 分支：只渲染 `结论人话 + 证据`，并保留「这条检查早于人话上线」的说明（现状 `drawer:2300-2307` 保留）。
- **R2** 可见区不出现命中原句以外的重复：同一句只在 ⑤ 上下文出现一次；④ 只列词，不复述句子。
- **R3** 行号/图号在一条 finding 里各出现一次：③ 位置段写一次，④/⑤ 不再带 `#N`／`图M` 前缀。

## 8. 文案规范（实现时按此写，评审按此判）

### 8.1 句式与长度

| 项 | 规定 |
|---|---|
| 结论人话 | ≤40 字，主语是「第 N 行「短名」」或「这次整体」；必须点出「几处」与「在哪」 |
| 命中段 | 固定句式 `…里的『词』还在提示词里：`；多词连续排『』，不写「3 个词分别是」 |
| 上下文 | 命中句前后各 ≤12 字，整串 ≤60 字；截断用 `…`；原文一字不改（`@图片1` 照抄） |
| 缺项/告警行 | 一行一个缺陷，句式「哪里 + 什么没对上 + 数量感」；禁止代号开头（`D2 …`） |
| 处理 | 只写 UI 内可点的东西，按钮名用页面原文（「退回置换」/「重试」/「重传（覆盖）」/「移除」/「知道，按原样」） |
| 数字 | 带量词与人话（「3 行」「2 张」「9 行里只标了 2 行」）；裸统计串禁止入可见区 |

### 8.2 可见区禁用（正则级，写进 `probe_at22_e2`）

```
#\d                       → 改「第 N 行」
图\d+(?!（你传的)           → 改「图N（你传的<实物>）」；仅位置段允许带括注写法
@图片\d+                  → 仅允许出现在上下文/原文引用内
已传图行词表|发图单位|提交快照|必换行|empty_confirm|锁点|门禁|绿项|缺项|告警|重拆\s*\d|行→图号|正文\s*\d+\s*字
analysis/reverse|待确认清单\.md   → 处理字段里一律不得出现路径
「原因：」
```

### 8.3 空值/降级

| 情况 | 写法 |
|---|---|
| 无 `行号` | `这次整体对不上，不是某一行的问题` |

## 11. 风险与回滚

| 风险 | 影响 | 处置 |
|---|---|---|
| 短名解析失败（`拆解.md` 缺） | 位置段退化为「第 6 行」 | `行称呼` 空 → 用 `类别`；两者都空仍成立（不阻塞） |

| 旧 `自检.json` 不迁移 | 老任务仍显示旧文案 | 有意为之：不重写历史文件（与既有「读层降级」原则一致），新渲染任务才产 v2 |
