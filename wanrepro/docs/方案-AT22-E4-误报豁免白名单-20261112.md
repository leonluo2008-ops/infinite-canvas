## 零、一句话与结论摘要

给「自检②绑图行残留」加一条**行 × 词**粒度的用户裁量通道：UI 里点「保留这个词」→ 落 `任务.json` 的 `selfcheck_whitelist` → 自检重跑时该词不进本行词表 → 该项转 PASS；可查看、可撤销，撤销后自检立即把同一个 FAIL 原样报回来。

| 决策点 | 结论 | 理由（要点） |
|---|---|---|
| 落盘位置 | `任务.json` → `selfcheck_whitelist`（沿用上级方案冻结的字段名） | 白名单是「这条任务」的裁量，随任务删除/迁移走；不占 sidecar（sidecar 属桥侧清单域） |
| 层级 | 任务级容器 + **行级** + **词级**；图号只作证据快照 | 行号是清单真源；图号是 `assign_numbers` 每渲染重算的派生值，做作用域会在重编号后串到别的实体 |
| 词粒度 | 词表闭包中的**完整词**（`entity_noun_core` 的 core 或 `_noun_grams` 的 2–3 字组，≥3 字） | finding 报的就是这个词；存正文原句会变成「整行免检」，且用户一改描述就失配 |
| 规范化 | `词键 = NFKC + strip + casefold`，比较只认词键 | 现状词表全是汉字（`entity_noun_core` 已 strip 非汉字），词键让未来 E1 放宽到含字母/全角时不需要改数据 |
| 过滤位置 | **进词表后、正文匹配前**（唯一过滤点，与渲染清扫共用同一个 helper） | 命中后再过滤会让「证据条数」与「展示条数」两套口径分裂，且无法解释「豁免了几个词」 |
| 是否重渲染 | **不重渲染，只重跑自检** | 豁免不改任何渲染输入；重渲染会重算审批快照、并把「加一条裁量」耦合到 bridge 可用性上（bridge 挂了就加不了白 = 正被误报卡死时最不该发生） |
| 粒度下限 | schema 里**没有**「整行免检」字段，也没有任务级词 | 防「新的误判放大」；服务端强校验「词必须在该行词表闭包里」 |
| 现状定位 | 自检 FAIL **不阻断**批准（只有音频门禁阻断，见 §1.4） | E4 不是解硬锁，是防止「自检喊狼来了」导致用户/运维习惯性无视自检 |

## 一、现场核实（代码级，实现前必须与这些事实对齐）

### 1.1 判定层：残留项怎么取词、怎么判命中

`automation/selfcheck.py:348 _check_residue()`（现状原文要点）：

```python
for e in ents:
    if e.kind.startswith("品牌视觉"):   continue          # 品牌位不取词（AT-16 B1b）
    if not (e.no and e.has_asset_image): continue        # 只查「已传图行」
    core = render.entity_noun_core(e)
    words = sorted({core} | set(render._noun_grams(core)), key=len, reverse=True)
    words = [w for w in words if len(w) >= 3]            # 口径：2 字组（香水/黑色）不进表
    for w in words:
        for m in re.finditer(re.escape(w), body):        # 子串匹配，无词边界
            hits.append(_finding("残留", …, row=e.row_no, no=e.no))
            break                                        # 每个词只报第一处命中
```

- 词表来源：`pipeline/reverse/render.py:1218 entity_noun_core()`（实体名去前缀 → 去尾注 → 取第一个分句 → 只留汉字）+ `render.py:1232 _noun_grams()`（2–3 字滑窗）。
- finding 结构：`{类型:"残留", 文字, 行号, 图号}`，`文字` 里带 ±10 字上下文；前端只渲染不重判（红线 25）。
- 实测误报形态（auto-0066/0067，#6 行道具实体绑 @图片1）：core=`双耳奖杯造型香水小物体`… grams 里 `右下角/下角入/角入画` 命中用户正文「右手持@图片1自右下角入画」→ 3 处 FAIL。

### 1.2 自检什么时候跑

- `automation/generate.py:185 do_render()` 渲染成功后 `selfcheck.run_selfcheck(task_dir)`（generate.py:213）——渲染与自检同一进程，**任务目录可见，`任务.json` 可读**。
- `generate.py:233 rerender_for_audio_mode()`：三态改选原地重渲染后**自检重跑**（既有先例：换正文必重判）。
- `selfcheck.run_selfcheck()` 落 `自检.json`（tmp+replace 原子写），检查器自身异常也落一条 FAIL，不打断渲染主链。

### 1.3 任务文件的写纪律（白名单必须遵守）

- `automation/state.py load()/save()`：唯一读写原语，`save` 走 `*.json.tmp` + `replace` 原子替换。
- `ui/hub_api.py:227` 注释写明：`任务.json` **只有一个写族**（状态机 + 短持锁的阶段回写），心跳另立 `心跳.json`。→ 白名单写入必须 `task_lock(local_id)` 内 `state.load → 改 → state.save`，**不许自写文件**。

### 1.4 现状：自检 FAIL 不是批准门禁（重要，避免把 E4 说大）

`generate.py:354 do_approve()` 只过**音频门禁**（`run_audio_gate` verdict=FAIL 才拒批准）；`automation/selfcheck.py` 的结论在 UI 里是红条 + 「怎么处理」，前端 `task-detail-drawer.tsx` 的批准按钮不受自检影响。

→ E4 的真实价值不是「解锁」，而是：**自检不许再冤枉用户**，否则用户学会无视红条，真残留（香水瓶/包装类）就没人看了。这一点应写进实现批次的验收口径。

### 1.5 现状的另外两个细节（设计必须解释，不能装作不存在）

- 每个词只报**第一处**命中（`break`），所以 finding 里的上下文可能不是全文里最典型的那处；E4 加白是「按词」生效，等于把该词在本行的**所有**命中一起豁免 → 必须在证据里给出「该词另有 N 处命中」。
- 同一行词表可能重复（core 恰好等于某个 gram），`set` 已去重；白名单也用词键去重。

## 二、数据结构：`任务.json` 的 `selfcheck_whitelist`

### 2.1 Schema 草案（v1）

```json
{
  "selfcheck_whitelist": {
    "版本": 1,
    "更新于": "2026-11-12T23:40:12+08:00",
    "条目": [
      {
        "行": 6,
        "词": "右下角",
        "词键": "右下角",
        "来源": "gram",
        "图号": 1,
        "上下文": "右手持@图片1自右下角入画",
        "加入于": "2026-11-12T23:40:12+08:00",
        "操作人": "owner-hub"
      }
    ]
  }
}
```

| 字段 | 类型 | 必填 | 含义与规则 |
|---|---|---|---|
| `版本` | int | 是 | 结构版本，当前 `1`；将来改词键算法/改层级时按版本分流读 |
| `更新于` | str(ISO) | 是 | 最后一次增删时间（同 `state._now()` 口径，带时区） |
| `条目[]` | list | 是 | 扁平列表，**唯一键 = (`行`, `词键`)**；空列表 = 没豁免 |
| `行` | int | 是 | 待确认清单行号（`replace.parse_rows` 的 `no`），≥1 |
| `词` | str | 是 | 用户点「保留」时 finding 里那个词（原样存，供 UI 展示） |
| `词键` | str | 是 | `NFKC(词).strip().casefold()`；**判定只比这个词**。汉字场景与 `词` 相同，存下来是为了可 diff、可排障 |
| `来源` | `"core"` \| `"gram"` | 是 | 该词是从 core 还是 2–3 字组切出来的（审计用：能看出是不是把整段实体名豁免了） |
| `图号` | int\|null | 否 | 加白当时的图号，**仅证据快照**，不参与判定 |
| `上下文` | str | 否 | 加白当时正文命中片段（≤40 字），**仅证据**，不参与判定 |
| `加入于` | str(ISO) | 是 | 该条加入时间 |
| `操作人` | str | 是 | `owner-hub`（UI）/ `owner-cli`；不记 IP、不记账号 |

### 2.2 为什么是这个层级（四个被否掉的选项）

| 候选层级 | 结论 | 否决理由 |
|---|---|---|
| 按任务（一个词全局生效） | ✗ | 同一词在不同行可能一处合法一处是真残留（「透明」）。任务级 = 全域免检，正是「误判放大」 |
| 按绑定图（图号作用域） | ✗ | 图号由 `render.assign_numbers()` 每次渲染重算（组/行决策都会改号）；按号存会在重编号后把裁量挪到别的实体上 |
| 按行免检（"这行别查了"） | ✗ | 卡片验收明令禁止：豁免粒度不可粗到整行免检 |
| 按正文原句（存那句话） | ✗ | 用户一改描述（E3）就失配；且等价于整行免检；还会把用户正文搬进任务文件，产生第二份真源 |
| **行 × 词（选中）** | ✓ | 与 finding 的粒度同构（finding 自带 行号+词）；E1 改口径后仍按「这次词表里有没有这个词」判定，不串行 |

**关键性质：豁免 `core` 不等于整行免检。** 现有词表 = `{core} ∪ 2–3 字组`，每项独立匹配；豁免 core 只去掉「整段实体名」这一个匹配项，2–3 字组仍逐条判。所以最粗的一档也仍然小于一行。

### 2.3 写入与服务端校验（全部 400/409，不静默）

| 编号 | 校验 | 不通过时 |
|---|---|---|
| V1 | `行` 是 int≥1 且存在于当前清单（`replace.parse_rows`） | 400「清单里没有第 N 行」 |
| V2 | `词` 规范化后非空、汉字计数 3–20 | 400「词长不合法（3–20 字）；残留词表只收 ≥3 字的词」 |
| V3 | **词键 ∈ 该行本次词表闭包**（`entity_noun_core` + `_noun_grams`，≥3 字过滤后） | 400「『X』不在第 N 行的残留词表里（词表口径可能已变，刷新详情后重试）」——这条是防「整句/任意词」混进来的硬闸 |
| V4 | 该行当前**已传图**（`e.no and e.has_asset_image`） | 409「第 N 行现在没有绑图，没有残留可豁免」 |
| V5 | 本任务条目数 ≤ 50（单次批量也计数） | 409「本任务已豁免 50 个词——先查词表口径（E1）是不是有问题，别用白名单兜底」 |
| V6 | 任务状态 == `awaiting_approval` | 409「已批准的任务先『撤销批准』再改豁免」（与 `hub_api.set_audio_mode` 同守卫） |
| V7 | 同一 (`行`,`词键`) 已存在 → 幂等（返回 `已存在:1`，不重复写） | — |

## 三、透传链路（伪代码级）

### 3.1 过滤顺序（一句话版）

**实体筛选（kind/已传图）→ 取 core → 词表闭包（core ∪ 2–3 字组）→ ≥3 字过滤 → 豁免过滤 → 正文正则匹配 → 结论装配（含豁免台账）**

过滤点唯一，位于「词表已成型、尚未与正文比对」处：既不是「进词表前」（那时还没有词，无法按词豁免），也不是「命中后」（那时已产生 finding，过滤会让证据计数与展示计数分家）。

### 3.2 判定层伪代码（改 `_check_residue`）

```python
def _word_key(word: str) -> str:
    return unicodedata.normalize("NFKC", word or "").strip().casefold()

def _word_table(render, ent, exempt: set[tuple[int, str]]) -> tuple[list[str], list[str]]:
    """一行原物词表 → (保留待查的, 被豁免的)。口径与渲染清扫同源（core + 2-3 字组）。"""
    core = render.entity_noun_core(ent)
    words = sorted({core} | set(render._noun_grams(core)), key=len, reverse=True)
    words = [w for w in words if len(w) >= 3]                     # 口径①：≥3 字（现状不动）
    kept, dropped = [], []
    for w in words:
        (dropped if (ent.row_no, _word_key(w)) in exempt else kept).append(w)
    return kept, dropped                                          # 口径②：豁免（唯一过滤点）

def _check_residue(body, ents, render, bridge_id="", whitelist=None):
    entries = list((whitelist or {}).get("条目") or [])
    exempt = {(int(it["行"]), str(it["词键"])) for it in entries
              if isinstance(it, dict) and it.get("行") and it.get("词键")}
    used: set[tuple[int, str]] = set()      # 本次真正生效的条目
    hits, scanned = [], []
    for e in ents:
        if e.kind.startswith("品牌视觉"):   continue              # 现状：品牌位不取词
        if not (e.no and e.has_asset_image): continue             # 现状：只查已传图行
        kept, dropped = _word_table(render, e, exempt)
        used |= {(e.row_no, _word_key(w)) for w in dropped}
        scanned.append(f"#{e.row_no}→图{e.no}({len(kept)}词)")
        for w in kept:
            ms = list(re.finditer(re.escape(w), body))
            if ms:
                hits.append(_finding("残留", f"#{e.row_no} 的「{w}」残留于正文: …{ctx}…",
                                     row=e.row_no, no=e.no, count=len(ms)))
    ledger = _exempt_ledger(entries, ents, body)   # 生效 / 失效（正文无此词）/ 失效（行不绑图）/ 未参与（不在词表）
    # 白名单来自 _check_all 顶部已有的那一次 state.load(task_dir).get("selfcheck_whitelist")，
    # 判定层不新增读盘（同一份任务快照，避免自检过程中任务文件被改导致的半新半旧）。
    if not hits:
        # PASS 证据必须把豁免写出来（不许静默通过）：证据 + 「已按你的裁量保留 N 词：…」
        return {"项": "绑图行残留", "结论": PASS, "证据": …, "豁免": ledger, "说明": _say(…)}
    # FAIL：证据只列**未豁免**命中；豁免部分另起一句「另有 N 个词按你的裁量保留」，不混进原因串
    return {"项": "绑图行残留", "结论": FAIL, "证据": …, "豁免": ledger, "说明": _say(…, findings=hits)}
```

### 3.3 豁免台账（`自检.json` item② 的新字段 `豁免`）

| 台账状态 | 判定条件 | UI 表现 |
|---|---|---|
| `生效` | 该条目的词键在本次词表中、且被过滤掉 | 正常行：`#6 · 「右下角」· 生效 · 上下文…` + 撤销 |
| `失效-正文无此词` | 词在词表闭包里，但正文已不含它（用户按 E3 改过描述） | 灰显 + 原因 + 撤销 |
| `失效-行没绑图` | 该行本次不再 `has_asset_image`（改绑/撤销图） | 灰显 + 原因 + 撤销 |
| `失效-行不存在` | 清单里没有这个行号（清单重生成） | 灰显 + 撤销 |
| `未参与-不在词表` | 词不在该行本次闭包里（E1 收词后常见） | 灰显 + 「词表口径已不含这个词，条目无害」+ 撤销 |

设计取向：**失效条目一律不自动删**。自动删会在「用户改回去」时静默丢掉裁量；灰显 + 可撤销把决定权留在人手里。撤销全部 = 批量 DELETE。

配套的小改动（同批落地，不另立合同）：`_finding(kind, text, row, no, count=None)` 增一个可选 `count`（该词在正文的命中处数，现状 `break` 只报第一处）；`_shown()` 仅在 `count > 1` 时透出，旧格式（无 count）逐字不变——所以 E2 的前端渲染对老数据仍是零改动。

### 3.4 写路径伪代码（`POST/DELETE /api/hub/task/<id>/residue-exempt`）

```python
def set_residue_exempt(local_id, rows, word, remove=False):
    w = _word_key(word)
    with task_lock(local_id):                       # 任务文件只有一个写族
        task = state.load(task_dir)
        if task["state"] != "awaiting_approval":    # V6
            raise HubError("已批准的任务先「撤销批准」再改豁免（当前 %s）" % task["state"])
        closure = _row_word_closure(task.get("bridge_id"))   # render 同源：parse_checklist + entity_noun_core + _noun_grams
        for r in rows:                              # V1/V3/V4
            if r not in closure:            raise HubInputError("清单里没有第 %d 行" % r)
            if not closure[r]["已传图"]:      raise HubError("第 %d 行现在没有绑图，没有残留可豁免" % r)
            if not remove and w not in closure[r]["词键"]:
                raise HubInputError("「%s」不在第 %d 行的残留词表里（词表口径可能已变）" % (word, r))
        entries = _upsert_or_remove(task, rows, w, remove)   # 唯一键 (行, 词键)，幂等
        if len(entries) > 50: raise HubError("本任务已豁免 50 个词——先查词表口径（E1）")  # V5
        task["selfcheck_whitelist"] = {"版本": 1, "更新于": state._now(), "条目": entries}
        state.save(task_dir, task)                  # 原子写
        items = selfcheck.run_selfcheck(task_dir)   # 只重跑自检，不重渲染
    return {"ok": True, "selfcheck_whitelist": task["selfcheck_whitelist"], "自检": items}
```

- 路由命名对齐既有：`ui/server.py` 里 `re.fullmatch(r"/api/hub/task/([^/]+)/audio-mode")` 同款 → 新增 `…/residue-exempt`（POST 加、DELETE 撤；body `{"行": 6 | [5,6], "词": "右下角"}`，撤销全部 body `{"全部": true}`）。
- 返回体**自带重跑后的自检束**，前端不必二次拉详情（同 `set_audio_mode` 回 `prompt_md`+`audio_gate` 的做法）。
- `get_task` 增一个平铺键 `selfcheck_whitelist`（原样透出），用途：详情页「已保留的词」面板不依赖 `自检.json` 是否最新；老任务无此键 → 前端视为空。

### 3.5 为什么不重渲染（三条，逐条可核）

1. **无输入变化**：渲染输入 = 清单（资产图/命名/描述）+ 意图 + 三态 + 模板，豁免一个都不改 → 重渲染得到的正文与上次逐字节相同（真差异只会来自别处改动，那属于另一件事）。
2. **会动审批快照**：`rerender_for_audio_mode` 每次重算 `approval_snapshot`；为一个纯判定动作引入快照变化，等于给「批准后输入变了」的守卫制造噪声。
3. **引入失败面**：渲染走 bridge `fetch_prompt`（跨进程/HTTP）。加白是本地判定动作；bridge 掉线时加不了白，正是「被误报卡死」的最坏时刻。自检重跑纯本地、毫秒级。

### 3.6 重渲染 / 自检重跑时白名单怎么不丢

| 场景 | 机制 | 结果 |
|---|---|---|
| E3 行内改描述 → 重渲染 → 自检重跑 | 白名单在 `任务.json`，自检每次 `state.load` 现读；条目按 (`行`,`词键`) 匹配 | 词还在 → 继续 `生效`；词被改掉 → `失效-正文无此词`（可见、可撤） |
| 三态改选重渲染（B3 既有链路） | 同上（`rerender_for_audio_mode` 内 `run_selfcheck`） | 不受影响 |
| 关闭 Drawer / 刷新页面 / 重启服务 | 只在任务文件里，进程内存零依赖 | 不丢 |
| 重试拆解（`discussing` 重跑，清单可能重生成） | 行号若变化 → `失效-行不存在`；行号不变 → 继续生效 | 用户可见，不静默 |
| 删除任务（`projects/.trash` 改名提交点） | `任务.json` 随目录走 | 随任务消失（正确） |

**渲染侧（`render.py:1260 strip_core_residue`）阶段一不读白名单** —— 边界与理由见 §5 B9。

## 四、UI 设计

### 4.1 入口位置（与 E3 同一动作组）

自检面板 `SelfCheckPanel`（`web/src/pages/hub/task-detail-drawer.tsx:2191`）→ item②「绑图行残留」→「发现」列表（`data-hub-selfcheck-findings`，当前是无动作的 `<li>`）。改造：

```
[#6 图1] 「右下角」残留于正文: …右手持@图片1自右下角入画…      [改第 6 行描述] [保留这个词]
```

- 动作位：每个 finding 行尾 `ml-auto flex gap-1` 动作组；**左主右次**——`改第 6 行描述`（E3 主路径，写清单→确认→重渲染）在前，`保留这个词`（E4 次路径）在后，样式为次级按钮/文字链，避免用户把豁免当默认动作。
- 同一动作组契约（给 E3 交底）：两个按钮同容器、同尺寸、同 busy 语义；E3 未上线前 E4 只渲染自己的按钮，不占位、不伪造 E3 文案。
- 红线 25：按钮只发 API，不在前端判「这个词该不该豁免」；finding 是否消失由重跑后的 `自检` 束决定。

### 4.2 交互细节

- 点击 `保留这个词` → 若同词在其他行也有命中（前端只比 `发现[].行号`，不改判定）弹二次确认：「『右下角』在第 6、11 行都还在正文里。保留第 6 行这一个，还是这几行一起保留？」→ 选项：`只保留第 6 行`（默认）/ `一起保留（2 行）` / `取消`。**存储永远是行级多条**，批量只是 UI 便利。
- 请求进行中：按钮 loading、面板只读（沿用 `busy !== null` 禁用纪律）。
- 成功后：该 finding 从列表消失；若 item② 无剩余命中 → 整项转 PASS 并保留在通过区（`X 项通过`），红条计数 `自检 ⚠ n/4` 相应减一。
- 失败（400/409）：toast 原文（服务端人话），面板不乐观更新。

### 4.3 「已保留的词」面板（可查看 + 一键撤销）

自检面板尾部新增折叠条（有条目才渲染）：

```
⌄ 已按你的裁量保留 2 个词                                    [全部撤销]
   #6  ·「右下角」· 生效 · …右手持@图片1自右下角入画…                [撤销]
   #11 ·「透明」 · 失效：正文已无此词 · （改过描述后会失效）          [撤销]
```

- 数据源：`自检[项=绑图行残留].豁免`（结构见 §3.3），空则回落 `get_task.selfcheck_whitelist`（老/异常态）。
- 失效行灰显 + 原因人话；`未参与-不在词表` 追加一句「词表口径已不含这个词，条目无害」。
- `全部撤销`：≥2 条时显示，二次确认列出将撤销的条数。

### 4.4 撤销后自检重跑的表现

- 流程：确认 → `DELETE` → 服务端删条目 + `run_selfcheck` → 响应回新自检束 → 面板就地刷新。
- 表现：同一 finding **原样复现**（同行号、同词、同上下文），item② 从 PASS 回 FAIL，红条计数 +1；「怎么处理」文案仍是 E2/E3 那套（改描述 / 退回置换），不出现新的内部术语。
- 提示：toast「已撤销：这个词重新计入自检」；撤销全部 → 「已撤销 N 个词，自检已重跑」。
- **不重渲染**：正文、审批快照、`approved`/`generating` 状态一律不动（V6 已挡掉已批准任务）。

### 4.5 状态守卫与只读态

| 任务状态 | 面板 | 按钮 |
|---|---|---|
| `awaiting_approval` | 可写 | 可用 |
| `approved` / `generating` | 只读（灰显条目，可展开看） | disabled + tooltip「已批准：先『撤销批准』再改豁免」 |
| `awaiting_assets` / `rendering` / `discussing` | 不渲染（无 `提示词.md` / 自检未跑） | — |
| `failed` | 只读回显（若 `自检.json` 仍在） | disabled |

### 4.6 生产者话术（红线 25：人话在 selfcheck 侧产出，前端逐字渲染）

- item② 加白后转 PASS：「已传图的每一行，原物的名字和特征词都没残留在提示词正文里（其中 2 个词按你的裁量保留）」；证据追加 `已豁免：#6「右下角」、#11「透明」`。
- 仍有其它词残留（FAIL）：「提示词正文还留着我方要换掉的原物描述词：1 处（涉及行 #5）；另有 2 个词按你的裁量保留」。
- 存在失效条目：PASS/FAIL 证据都追加 `1 个豁免条目已失效（正文已无此词）`——不允许静默。
- 自检整体证据里的内部统计（「已传图行词表 3 行…」）沿用 E2 的处理（收进「展开看证据」），E4 不另造一套。

## 五、边界情况处理表

| 编号 | 场景 | 判定规则 | 系统行为 | 用户可见 |
|---|---|---|---|---|
| B1 | 同一个词在多行命中（#6、#11） | 条目是 (`行`,`词`) | 默认只豁免点击那一行；UI 二次确认可选多行，落多条行级条目 | 另一行仍红，红条计数不骗人 |
| B2 | 同一个词在多图/多实体（组） | 图号不参与判定 | 每行各自成条；组的其它成员行不受影响 | 面板逐行列出 |
| B3 | 豁免后原词被改掉（E3 改描述） | 词在闭包但正文没有 | 台账 `失效-正文无此词`；**不自动删** | 灰显 + 原因 + 撤销 |
| B4 | 词表规则变更（E1 收词）后旧白名单 | 只看「本次词表里有没有这个词」；`版本` 不参与失效判断 | 仍在表 → 继续 `生效`；不在表 → `未参与-不在词表`（无害） | 灰显说明，可批量清理 |
| B5 | 与「退回置换」兜底的关系 | 两条互不替代 | 顺序建议：先豁免（零成本、不动数据）→ 仍不行按 E3 改描述重渲染 → 最后退回置换重绑图。退回置换**不清**豁免（行号+词仍有效；该行不再绑图则自动 `失效-行没绑图`） | 处理文案按此顺序给 |
| B6 | 撤销后自检重跑 | 条目删 → `run_selfcheck` | 同一 FAIL 原样复现；不重渲染、快照不动、已批准不受影响 | toast + 面板回红 |
| B7 | 想「整行免检」/ 想豁免整句 | 无此字段；V2/V3 拦 | 400 人话；用户只能逐词裁量（或按 E3 改描述） | 明确报错原因 |
| B8 | 豁免 `core`（长实体名整段） | core 只是词表一项 | 2–3 字组仍逐条判 → 不是整行免检 | 面板显示 `来源=core`，一眼看出粒度 |

| B10 | 同一词在正文出现多次，其中一处是真残留 | 行×词级别，不做位置区分 | 一次豁免会压掉该行全部命中；证据里显式给「该词另有 N 处命中」 | 证据可见，撤销可复现（B6） |
| B11 | 词是子串（豁免「下角入」不影响「右下角」「角入画」） | 词键精确相等，不按前缀/子串传播 | 三个词要分别豁免（UI 会分别列出三条 finding） | 面板三条 |

## 六、与 E1 / E2 / E3 的关系

### 6.1 E1 收词后，白名单还剩哪些正当覆盖（职责不重叠）

E1 = 「**默认口径**：不该报的不报」（作用于所有任务，靠 kind + 实体名文本特征识别动作/构图/拍摄手法类实体）。E1 落地后仍会剩下的残余误报：

| # | 残余场景 | 为什么 E1 收不干净 |
|---|---|---|
| R1 | 同品类换同品类（香水换香水） | 实物名词必然合法出现在用户正文里（描述新产品形状/材质），词表无法区分「原物」与「新物」的同一名词 |
| R2 | 客户产品外观特征词与实体名 grams 重叠（「双耳奖杯造型」） | 特征词是实物描述的一部分，删了就漏真残留；不删就误报 |
| R3 | 动作-实物复合实体名（「入画式香水瓶」） | 实物部分必须进词表（真残留要拦），动作部分合法 → 同一 core 里两类词共存 |
| R4 | 跨行共享中性词（「透明」「第一视角」） | 中性词在别行是合法描述，在本行是原物特征 |
| R5 | 品牌/命名位取词未覆盖的 kind | 现有 skip 只挡 `kind.startswith("品牌视觉")`；命名里带客户字样出现在其它 kind 时仍会被取词 |

→ E4 覆盖 R1–R5：**口径没法在默认层判的，交给所有者当场裁量**（作用域 行×词，随任务）。

### 6.2 边界纪律（防止 E4 变成 E1 的替代品）

- 白名单**只解决这一次、这一行、这一个词**；不提供任务级/全局豁免，不提供「同实体所有行」一键（UI 批量仍落多条行级）。
- 可观测：自检证据常显「本任务已豁免 N 词」；N > 5 时 UI 追加一句「多个词被保留，可能是词表口径（E1）没收干净，值得回头收口径」。
- B1 批次（E1 实现）的实测报告必须**统计豁免需求量**（跑误报样本集，看有多少词仍要靠白名单）——这是判断 E1 口径是否到位的量化口径，也是 E4 不能用来掩盖 E1 未完成的证据。

### 6.3 与 E2 / E3 的接口

| 依赖 | 契约 |
|---|---|
| E2（呈现重构） | finding 必须有结构化字段 `row_no` / `no` / `word` / `context`——E4 的「保留这个词」按钮直接吃 `word`+`row_no`，禁止前端从证据文字里抠词（红线 25）；`normalizeSelfCheck` 对 item 上的新字段 `豁免` 必须原样透传（不许重算/裁剪），前端只渲染 |
| E3（操作闭环） | 同一动作组：`改描述`(主) + `保留这个词`(次)；E3 的重渲染链路触发自检重跑时，白名单按 §3.6 自动续命 |
| 复用功能卡 t_2040fa4f | 不新增第二个编辑承载：豁免按钮不打开编辑器，只发一次 API |

## 七、这个机制不会引入新的误判放大（逐条论证）

| 放大路径 | 为什么堵住 |
|---|---|
| 粗到整行/整任务 | schema 无整行字段、无任务级词；唯一键是 (`行`,`词键`)；V3 只接受该行词表闭包里的词 |
| 用户随手把真残留豁免掉 | ① 只能逐词点（finding 里的词才能点，服务端再校验一次）；② `来源`/`上下文`/`图号` 留证；③ 面板常显 + 一次撤销即复现 FAIL；④ 单任务上限 50 + 超阈值提示收口径 |
| 豁免静默生效 | PASS 证据必须写「已按你的裁量保留 N 词：…」；失效条目也要写进证据——豁免永远是可见状态，不是隐形通过 |
| 跨行/跨任务泄漏 | 条目绑 (`行`,`词`)，不按图号、不按前缀、不按实体；任务文件随任务走 |
| 改坏渲染 | 阶段一**不碰渲染**（`strip_core_residue`、发号、清扫一字不改）→ 真残留的清扫/拦截行为零变化，回归面为零 |
| 让自检变成橡皮图章 | 自检四项框架不动；②的判据仍机械可判，只是把「所有者已裁量的词」记为已知项并显式列账；B1 批次的真残留样本回归必须仍全红 |

**反向风险（如实写）**：真残留恰与合法描述同词时，一次豁免会同时放过该行全部命中（B10）——这是粒度代价，用「证据显式计数 + 可撤销」换取；不做自动判定「这处是真残留那处不是」，那会把可解释性做没。
