# 方案：AT-22 自检质检三层重构（判定精度/呈现人话/UI 操作闭环）

日期：2026-11-12　分支：feat/automation　状态：待双路审计
所有者拍板记录：E1–E4 按主代理推荐批准（2026-11-12 夜）；设计卡 t_e7964ded。

## 一、需求（所有者原话）

「这是质检的一个提示，我根本就看不懂，操作一点都不便捷。」——自检异常提示（绑图行残留）三处重复拼接内部术语，处理指引让用户去磁盘改 markdown 文件，在 web UI 语境完全不可操作。

## 二、现场核实（三层问题，代码/数据级）

### 第一层：判定误报（冤枉用户）
- 实测（auto-0066/0067 动线）：#6 行实体=「B：从右下角入画的第一人称右手，浅肤色…握持喷雾小物体」（kind=道具，绑 @图片1 产品图）；
- `entity_noun_core`（pipeline/reverse/render.py:1218）取实体名第一个分句整段 → `_noun_grams` 2-3 字组 → 「右下角/下角入/角入画」进残留词表；
- 用户正文「右手持@图片1自右下角入画」是合法保留的构图动作描述（借创意保留原片拍摄手法）→ 误报 3 处 FAIL。
- 本质：词表无法区分「要换掉的实物原物」与「要保留的构图/动作/拍摄手法」；手持/入画/运镜类实体行整段进词表必误红。

### 第二层：呈现不可读
- 同一 finding 三处重复（原因串+明细行+原始证据全文互相重复）；内部术语直出（「#6图1」「已传图行词表 3 行（#1→图1(5词)…），正文 516 字」）。

### 第三层：操作断裂
- 处理指引=「去清单 analysis/reverse/3/待确认清单.md 改『用我的描述』列」——磁盘路径对 web 用户不可操作；「用我的描述」在 hub UI 无入口（grep 零命中）。

## 三、设计（拍板结论）

E1 判定精度：残留词表只收「可替换实物」的词。动作/构图/拍摄手法类实体（手持、入画、第一人称、运镜、视角）**不进词表**；实现时先全量实测误报样本（跑既有任务自检对比新旧口径），阈值与识别规则（kind+实体名文本特征）由实现批次实测后冻结，经审计把关。红线：不得为消误报而放过真残留——真残留样本（香水/瓶/包装类行）必须继续拦住。
E2 呈现重构：自检 finding 结构化（row_no/no/word/context 字段）落 自检.json；前端一次说清「第 N 行（绑 图M）的『词』还在提示词里：…上下文高亮…」；同一证据不重复三处；内部统计收进「展开看证据」。红线 25：人话在生产者侧（selfcheck.py）同源产出，前端 normalizeSelfCheck 只透传不重判。
　→ 呈现规范（模板/折叠区/术语对照/4 个真实 before-after）见 `docs/方案-AT22-E2-自检findings呈现重构-20261112.md`；字段键以该文 §2 为准（`行号/图号/词/上下文/片段`，即 row_no/no/word/context 的中文键）。
E3 操作闭环：自检异常区「怎么处理」必须是 UI 内动作——行内直接编辑「用我的描述」→ 保存（写清单）→ 确认置换（复用既有确认链）→ 重渲染 → 自检自动重跑。废除磁盘路径类指引。「退回置换」保留为兜底入口。
E4 误报豁免：finding 卡片一键「保留这个词」→ 词进本任务白名单（任务.json selfcheck_whitelist，get_task 透传）→ 自检扫描跳过白名单词。判定层不完美时的用户最终裁量权，防卡死。

## 四、批次拆分建议

- B0 合同卡：finding 结构化 schema、动作实体识别规则口径、白名单字段合同冻结；
- B1 判定层：selfcheck 词表口径改造+白名单跳过+结构化 finding 落盘；误报/真残留双样本集实测报告（新旧口径对比：误报清零且真残留全拦）；
- B2 呈现+操作：前端 finding 渲染重构（人话单源透传）+ 行内「用我的描述」编辑→保存→确认→重渲染→自检重跑闭环 + 「保留这个词」豁免按钮；
- B3 收口：全族回归+真机（auto-0067 动线复测：#6 行不再误红或可一键豁免；真残留任务仍正确拦红）。

## 五、验收合同

- 误报样本（auto-0066/0067 动线）：#6 类动作实体不再误报（或豁免后不再报）；
- 真残留样本（构造：正文含「香水瓶」类实物词、已绑图行）：仍 FAIL 且可经 E3 闭环修复通过；
- 白名单：加白后自检重跑该项转 PASS，白名单随任务持久；
- 回归零红：probe_at9 系自检探针 + probe_at15（门禁）+ probe_retry_guard + probe_del_atomic + probe_at19_proc + probe_hub --isolated；
- 真机：所有者页面检查（见交付后检查指南）。

## 六、边界与风险

- 不改自检四项框架本身（次序对账/锁点/组绑定不动，只动残留项口径+呈现+操作）；
- 风险：词表收窄可能漏掉「实物名恰好含动作词」的真残留（如实体名「入画式香水瓶」）——靠「白名单+真残留样本回归」双保险；方案审计必须覆盖该反例；
- E3 编辑保存写清单（待确认清单.md/json）——与画布侧清单写路径的一致性需核实（谁生产谁写：hub 直写 vs 走置换链），避免双写源。
