## 「实例 → hub 身份」绑定说明（B2/P1c）

**同一条身份链，四件套都挂在同一实例同一修订上**：

```
实例 instanceId/templateId/instanceIndex（P3 确定性 id）
  → 画布：nodeIds[] + outputNodeId（本次产物，执行期回填）+ retiredPlaceholderNodeIds[] + lapianTaskId/jobId + runToken
  → hub ：localId + bridgeId（ingest 回执，视频 sha 幂等）+ revision{digest, chars, approvalSnapshot, promptEditedAt}
          + assets[{slotNodeId, imageNodeId, ref, source}]（按槽序，可复核挂图改序）
  → 落点：CanvasProject.workflowInstances（导入/导出显式透传，不进节点 metadata）
```

- **入口只有桥侧 ingest**：`bindInstanceToHub` 先取源视频字节（取不回直接 `hub_bind` 失败，不建影子壳）→
  `POST /api/hub/ingest`，回执缺 `local_id`/`bridge_id` 即失败（「建到任务」≠「可审批」的前半段）。
- **正文只在 `awaiting_approval` 落**：保存前现查 `getTask().state`，不是待审批就交给 `waitForApproval`
  （生产轮询 hub 真实状态，超时/`failed` 如实抛错）；没有等待器就失败，**绝不硬写正文**。
- **自检是 hub 的真源**：`saveRevision` 调 `POST /api/hub/task/{id}/prompt`，hub 自己写正文 → 重算审批快照 →
  重跑自检；画布侧只回传 `自检` 数组并统计未通过项（`selfcheckFailures`），**不另写评分器**（G16）。
- **审批不新造状态机**：只用既有 `approve` / `revoke` / `rollback`。身份记录只回答「谁是谁」，
  「现在能不能批」一律现查 hub（§5.3）。
- **「编辑/换图/参数变化须撤销旧批准」的挂钩点**：`planRevisionChange({record, nextTextDigest, hubState})`
  → `none`（同修订，不重写）/ `rewrite`（未批，可直接写并重算快照）/ `revoke_required`
  （`approved|generating|done`：必须先 revoke）。真实端点验证：已批准后改正文被 **409** 拒且盘上字节不变。

## G18 输出身份（审计判据落地）

- 生成链在**建节点那一刻**回调 `onChildNodeCreated(childNodeId)` 回报产物 id（`project.tsx` 四处新建分支：
  image/video/audio/text），编排器拿不到就 `failed(product_binding)`——**禁止按「最新节点/最大 id」反猜**。
- `buildProductBindingOps` 把「模板占位产物」的三条消费路径一次换干净：下游 `composerContent`/`prompt`/`content`
  里的 `@[node:旧id]` → `@[node:本次id]`；原「占位→下游」连线改成「本次产物→下游」（确定性 id，重放幂等）；
  最后删除占位产物节点。旧产物零残留，下游**只可能**消费本次新产物。
- 复核（不是只改完就算）：绑定后按既有 `buildNodeGenerationContext` 重新展开下游正文，断言含本次产物正文；
  再断言全实例零悬空引用（token 与连线端点都落在画布上）。
- 探针实证：本次产物带唯一标识串 `P4TOKENA-…`；下游 token 指本次 id；下游展开正文含该串；模板占位产物已退役。
