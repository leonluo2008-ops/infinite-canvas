## 一、冻结拓扑精确定义（Codex §11.1 / B4）

### 1.1 裁决

**模板子图 = 结构骨架，不是整条跑通链的全部节点。** 首批 Wan 拉片链的骨架成员（8 类角色）：

| 角色 | 节点类型 | 进模板 | 依据 |
|---|---|---|---|
| 源视频节点 | Video | ✅（骨架成员，媒体字段是槽①待注入位） | 槽①（合同 C2） |
| 拉片节点 | Lapian | ✅（骨架成员，taskId/jobId 剥离） | 链路根，`project.tsx:1010-1023` |
| 指令节点 | Text（`promptTemplate` 有值） | ✅ | `project.tsx:1204-1211` |
| 意图节点 | Text（`lapianIntent:true`） | ✅ | `project.tsx:1212-1219` |
| 提示词生成配置 | Config（`generationMode:"text"`） | ✅ | `project.tsx:1223-1236` |
| 终稿节点 | Text | ✅（**壳**：content 剥离，`lapianIntent` 等标记不适用） | `project.tsx:1518-1520` 终稿判定=Text+content 非空 |
| 视频生成配置 | Config（`generationMode:"video"`） | ✅ | `project.tsx:1571-1590` |
| 视频结果节点 | Video | ❌ **不进模板**（实例执行时新建，见 1.4） | G18：Config 生成新 rootId（`project.tsx:3476/3560`），模板内旧结果节点 id 无绑定力 |
| 资产位节点 | Image/Text（`assetSlotSourceId` 有值） | ❌ **不进模板**（实例期从新拉片派生，数量随源片内容变） | `project.tsx:1267-1357` 资产位由 IR 投影派生，`lapian-assets.ts:152-164` |
| 挂图 Image / graft 对照节点 | Image（挂图源/`assetGraftForSlotId` 有值） | ❌ **不进模板**（实例期素材置换产物） | `project.tsx:1363-1439` 挂图全套是运行态动作 |
| 固定素材节点 | Image/Audio（模板成员且**不是**资产位派生物） | ✅（字节进 files，id 重绑定） | 模板必须有可携带的固定参考图（Codex §3.2 媒体可携带性） |

理由：
1. 资产位数量由源片 IR 内容决定（`lapian-assets.ts:152-164`：blocks→条目，逐片不同），把它们当模板成员必然撞上「新素材资产位数量与模板不同」无解——**不进模板，问题消解为实例期按新拉片重新派生**。
2. Config 输出节点每次生成都新建 rootId（`project.tsx:3476` `videoId = reuseVideoNode ? nodeId : nanoid()`、`:3560` 同型；reuse 仅当源节点类型恰为 Video/Text 且为空或 overwrite），且新增「Config→新输出」连线（`:3504/:3588`）不迁移旧输出下游引用——模板里保留旧结果节点只会制造「实例归属靠猜」的陷阱（Codex G18）。**实例化器不预建结果节点**，产物归属由批次身份记录（§五）登记执行期新建的输出节点 id。

### 1.4 新素材资产位数量与模板不同时的处理规则

**不存在该问题**（因为资产位/挂图不进模板，见 1.1）。落到实例执行序列：

1. 新源视频上传 → `/api/lapian/run` 新拉片任务（`project.tsx:990-1005`）→ 拉片投影出新 taskId；
2. 实例化器调**受控业务入口**派生资产位（等价 `createLapianAssetSlots`，`project.tsx:1267-1357`：幂等键=「类型\|名」，按新 IR 投影出一套数量任意的资产位）；
3. 挂图走等价 `attachLapianAssetImage` 的副作用集（写扁平+镜像、建/换 graft、重算 manifest、补图→Config 连线，`project.tsx:1363-1439`）——**必须复用这套副作用实现，禁裸写 attachedImageId**（红线 25：挂图清单/图号/引用排序复用 `lapian-assets.ts:393-447`，Codex §7 表）。

### 1.5 与合同的关系

C2 冻结「连线拓扑」未定义冻结对象的粒度。本节将其细化为「**骨架边同构冻结，槽③伴生边豁免**」。这是对 C2 的解释性细化而非变更：C2 同一条内既冻结拓扑又把「资产位挂图」列为可变槽③，两者只有按本粒度切分才能同时成立。**建议随 P2 实现时把 1.1/1.2/1.3 的清单写进合同附录升 v1.2**（见 §七.1）。

## 二、id 重绑定策略（审计坑A / Claude G13 / Codex §3.4）

### 2.1 映射表建立（时机与确定性）

- **时机**：实例化器在生成任何 op 之前，先遍历模板骨架节点构建**全量映射表** `oldId → newId`（含连线端点、metadata 内全部 7 类引用）。先映射、后出 ops，禁止边建边改。
- **确定性 id**：新 id 必须可由（模板 id、批次 id、实例序号、旧 id）**确定性推导**（如 `t<模板短id>-<实例序>-<旧id>` 或其短 hash）。理由：`add_node` 无查重直接 append（`canvas-agent-ops.ts:45-59`；对比 `connect_nodes` 有 exists 查重 `:76-78`），确定性 id 是重试场景下唯一的幂等锚（Claude G10）；同 id add_node 二次执行时实例化器应以「节点已存在且形态一致→跳过」自守（该去重属 P3 实现项，本裁决冻结策略）。
- **跨实例隔离**：不同实例的 id 集合交集必须为空（Codex 风险表「模板/实例引用串线」验收项）。

### 2.2 七类引用字段重写总表

| # | 字段（引用形态） | 所在节点 | 真源/角色 | 重写规则 | 漏写后果 |
|---|---|---|---|---|---|
| 1 | `composerContent` 内 `@[node:id]` token（文本内嵌） | Config(text/video) | 组装串引用（拉片/指令/意图 token + 资产清单 token） | 对整串按映射表做正则全文替换：`/@\[node:([^\]]+)\]/g`，**仅替换命中映射表的 id**；命中不了映射表也命中不了图内节点的 id → 判「图外引用」拒绝实例化（Codex §3.1 引用闭包） | 清单/参考图断裂：连线在、token 指旧 id，生成时参考图为空、图号错序（Claude 坑A） |
| 2 | `attachedImageId`（扁平，节点 id 直引） | 资产位节点 | **唯一真源**（清单/请求只认它，`lapian-assets.ts:390-395` `attachedImageIdOf` 扁平优先） | 按映射表改写（若模板残留旧值；正常剥离后为空，见 §三） | 挂图不进请求/清单 |
| 3 | `assetSlot.attachedImageId`（嵌套镜像） | 资产位节点 | 展示镜像 | **与 #2 同一次 update 双写**；浅合并下更新 assetSlot 必须整体携带 desc/span 等保留字段（`canvas-agent-ops.ts:62` metadata 浅合并；Codex §4 槽③） | 功能不断裂但 UI 展示漂移（Claude C2 槽③双写坑） |
| 4 | `assetSlotSourceId` | 资产位节点 | 资产位→来源拉片（槽收集依据，`lapian-assets.ts:405`） | 按映射表改写 | 资产位脱离新拉片：`collectLapianAssetReferences` 按 sourceId 过滤（`:405`），漏写=清单收集不到本实例资产位 |
| 5 | `lapianSourceId` | Config(text) | Config→来源拉片（挂图副作用定位配置节点的依据，`project.tsx:1420/1430`） | 按映射表改写 | 挂图后 manifest 刷不到本实例的 Config（副作用按 `lapianSourceId===lapianId` 匹配，`project.tsx:1420`） |
| 6 | `assetGraftOfImageId` / `assetGraftForSlotId` | graft 对照节点 | 对照图↔资产位双向引用 | graft 节点不进模板（§一.1），无重写；若实例执行期新建 graft 则由挂图副作用自身写入 | —（模板侧剥离后无残留即可） |
| 7 | 连线 `fromNodeId`/`toNodeId`；`groupId` | connections / Group 成员 | 图结构引用 | 端点按映射表改写；`groupId` 同表改写 | 断线/组员脱组，骨架同构校验（F1）直接拦截 |

- `primaryTextId`/`texts[].id`/`primaryImageId`/`images[].id`：旧实例生成产物的内部引用，属运行态，**剥离**不重绑定（§三）。

### 2.3 遍历顺序（ops 生成序）

```
① 建映射表（全量、确定性）
② add_node ×N：骨架节点按依赖无关序加入，metadata 已完成 #1-#7 重写 + 运行态剥离（§三）
③ connect_nodes ×E：映射后端点；既有 exists 查重天然幂等（canvas-agent-ops.ts:76-78）
④ 槽值代入 update_node ×K：五槽白名单字段（含 #2/#3 双写同 patch）
⑤ 校验：骨架同构（F1）+ 冻结字段一致（F2-F4）+ 无图外引用 + 跨实例 id 零交集
```

中途失败的语义：已加入的部分节点**不得被误认成完整实例**——批次身份记录（§五）只在 ⑤ 通过后登记实例，失败前不入册（Codex §9.2 P3 验收「中途失败不留下半条链被误认」）。每实例的 ops 建议一次打包提交（Claude G12：Agent 撤销栈单值快照 `use-agent-bridge.ts:39,56`——亲验，逐实例打包=撤销粒度对齐实例）。

**通用规则：`metadata.status` 与 `errorDetails` 一律剥离。** 理由：status 是生成执行态（`canvas-node.tsx:476-477` 通用 loading/error 分支先于内容渲染拦截；`agent-site-tools.ts:119-124` 派生映射），新实例落地即带 success 会被 C5 派生误判已完成（Claude 坑B）；且「链路推进到哪步」不得写回节点 metadata（Claude C5 边界，合同 C5）。

**自检结果剥离**：自检绑定 hub 任务磁盘提示词与任务资产（`hub_api.py:3492-3501/3542-3550`，Codex G16 转述），模板抽取时旧实例自检痕迹（如 hub 侧 finding）不随模板走；实例自检在实例执行期对新正文新跑（§四.4）。

### 3.2 files 字段的剔除声明（Claude 坑C）

v3 的 files 按 (storageKey, path, mimeType, bytes) 携带 blob（`types/canvas-export.ts:15-19`；`canvas-export.ts:16-23`）。模板 files 规则：

| 类别 | 处理 | 声明 |
|---|---|---|
| 固定素材节点字节 | **保留**（storageKey 必须能取回字节；取不回=导出器直接跳过 `canvas-export.ts:19`，须在校验步明示报错，不许静默） | 模板自足素材 |
| 源视频字节 | **剔除** | 槽①待注入：模板记录槽位路径（源视频节点 id），不记旧 storageKey |
| 旧实例生成产物（拉片正文无字节、终稿无字节、视频结果 blob、资产位截帧） | **剔除** | 节点不入模板（§一.1），自然无 files 项 |

声明落点：**沿用 v3 外壳，不造第二套格式**（C1）。模板参数/槽声明作为 `CanvasProject` 的显式扩展字段随项目 JSON 走，声明只引用节点 id/槽路径，不复制第二份图 DSL（Codex §3.3）；因导入逐字段构造、未知顶层字段会丢（Codex §3.3 转述 `use-canvas-store.ts:94-108`），**导入/持久化必须同步认识新字段**——这是 P2 实现项，本裁决冻结原则与清单。

### 3.3 与 B3 的关系（run_generation 是否覆盖拉片链）

本裁决静态点验结论：**不覆盖**。证据链：`run_generation` op 由 `use-agent-bridge.ts:63-68` 分发到 `generateNodeRef.current(nodeId, mode, prompt)`=页面 `handleGenerateNode`（`project.tsx:3258`）；`handleGenerateNode` 全体（`project.tsx:3258-3342` 亲读）只有 `isAiConfigReady` 门禁 + `buildGenerationConfig` + 四种 mode 生成分支，**无视频上传、无 `/api/lapian/run` 调用**；拉片唯一执行入口是 `handleLapianExecute`（`project.tsx:977-1034`：`/api/video/upload` → `/api/lapian/run`），由意图弹层触发，不在生成分发链上。因此**实例化器必须新增受控业务入口**承接「新视频→上传→拉片→正文回填」（P3 范围；S4/B-3 要求的动态点验仍保留为 P3 开工判据）。

## 四、hub 只消费落地方式（Codex §11.2 / S1 / B2）

### 4.1 裁决：入口=桥侧 ingest，但「建到任务」≠「可审批」

- **身份获取**：画布实例经既有 `/api/hub/ingest`（`do_ingest(video_path, intent)`，`hub_api.py:712-717`；幂等键=视频内容 sha）获得 hub `local_id`（auto-*）。`_task_dir` 只认带 `任务.json` 的 auto-* 目录（`hub_api.py:163-168`）——这是 approve/rollback 的硬前提。
- **必要但不充分**：ingest 只建立「视频+意图→任务」，画布链的**正文、资产、自检**不随之进入 hub 任务。只造一个 auto-id 影子壳不满足审批语义（Codex §11.2 明言）。所以 P1c 探针（收敛裁决 §3）是 P8 前置：单实例走通 ingest → 资产上传（带 `X-Task-Id` 走本地引用，勘察 §3.5）→ 正文保存 → approve/rollback 消费。
- **不修 hub**：不动 hub 现有审批合同（合同 C9），闭合不了就停在设计审议（Codex §9.2 P1c）。

### 4.2 审批对象绑定规则（冻结）

审批对象 = hub 任务（同一 `local_id`）上绑定的四件套，画布实例经批次身份记录（§五）与之关联：

1. **同一实例**：批次身份记录登记 实例id ↔ hub local_id ↔ 画布节点集（骨架节点新 id）↔ 后端任务号（拉片 taskId/jobId、视频 videoTaskId）；
2. **同一修订**：画布终稿正文保存进 hub 后以 hub 侧修订为准；画布再编辑 → 产生新修订，旧批准对旧修订不失效、但对新提交输入必须重批；
3. **同一正文/资产**：approve 固化的是 hub 磁盘上的提示词文件与参数（`do_approve`，`hub_api.py:3255-3280`：校验→写 gen_params/gen_channel→v2 快照→approved）；**提交时消费的是快照冻结的那份**，不是画布上可能又改过的另一份（消解 Codex 风险表「审批对象与发出对象不同」：画布编辑使快照 stale → 必须重批，禁止拿旧批准发新正文）；
4. **同一自检/审批快照**：自检绑定本次正文修订（改画布正文 → 重跑自检，消费既有保存/重检入口 `hub_api.py:3492-3501/3542-3550`，Codex G16 转述）；审批快照 v2 = prompt+params+渠道身份三键+model+mode（`state.py:98-104` 亲读），key 不进快照（只轮换 key 不作废批准）。

### 4.3 approve/rollback 语义对画布产物是否成立

**成立，附两条边界**：
- `approve`（`hub_api.py:3255-3280`）：固化配置+快照+进 approved——对画布场景语义=「冻结本次生成输入」，与 D9「批准后批量付费生成」一致：批准即固化，付费提交（`start_submit`，`hub_api.py:3283-3292`：守卫 dispatch 未完结/submit_unknown 阻断 409、generating+有回执走续查不创建）消费冻结快照。
- `rollback`（`hub_api.py:1591-1599`）：awaiting_approval → awaiting_assets，**丢弃当前提示词**——对画布场景语义成立（画布正文本就从置换态改来，退回=回置换态重改），边界一：回退后画布终稿节点与 hub 修订的对应要重新走查（旧修订已丢弃，画布侧需同步感知，P1c 验证项）；边界二：rollback 连根清 `ROLLBACK_CLEARED_KEYS`（`state.py:74-75` 亲读：approval/snapshot/gen_params/gen_channel/SUBMIT_RUNTIME_KEYS）——画布侧不得另存一份「已批准」标记与之抗衡（C5/C9）。

### 4.4 P1b/P1c 探针必须验什么（最小前置，冻结为验收判据）

| # | 探针项 | 通过判据 |
|---|---|---|
| 1 | 身份闭合 | 单实例：ingest → 资产(带 X-Task-Id) → 正文保存 → approve，全程同一 local_id；非法 local_id 被拒（`hub_api.py:163-168`） |
| 2 | 正文一致性 | approve 时 v2 快照哈希输入的 prompt 与画布终稿正文**逐字节一致**；generation_get_status/全文读取（C8 修复后）读回同一份 |
| 3 | 失效与重批 | 画布改正文 → 旧快照 stale → 再提交被拒须重批；rollback 后再改再批走通 |
| 4 | 自检绑定 | 自检 findings 对应**本次**正文修订；改画布正文后重检产生新结果，不残留旧判读 |

P1b 付费闸探针（未确认零次付费创建）另属 P0b 卡（收敛裁决 §3），不在本裁决范围。

## 五、批次身份数据模型（C5 相容性）

### 5.1 裁决

**batchId ↔ 实例 ↔ 节点 ↔ 后端任务的持久关联存画布项目内的「批次身份记录」，随项目持久化（IndexedDB）并随 v3 导出携带；不进节点 metadata、不建仓外独立 JSON 文件。**

### 5.2 理由（排除法 + 正面依据）

| 候选 | 裁决 | 理由 |
|---|---|---|
| 节点 metadata 身份字段 | ❌ | C5 禁在画布 metadata 另存审批字段；且 metadata 被通用 ops 浅合并（`canvas-agent-ops.ts:60-62`）无白名单保护，身份字段会被任意 update 污染 |
| 独立 JSON 文件（浏览器外/仓内） | ❌ | 项目数据在浏览器 IndexedDB（`use-canvas-store.ts:42-66`），独立文件必然与项目本体分叉（导出/WebDAV 不带它）；G8 的教训是「无可脱离浏览器的权威持久服务」，不是再造一个第二存储 |
| hub 侧存画布批次 | ❌ | 违反「hub 只消费」（C4/C9）；hub 状态机语义是任务级（`state.py:35-36`），不认识画布节点 |
| **画布项目内身份记录** | ✅ | 单一事实源随项目走：持久化与导出同路（C1 v3 外壳）；刷新/导出/同步后身份可重建（Codex §9.2 P5「刷新可恢复成员」） |

### 5.3 「身份」与「状态」的界线（C5 相容判据）

- **身份（可存）**：membership 与外键——batchId、批次创建参数摘要、实例 id、骨架节点 id 清单（含输出节点 id，执行期回填）、hub local_id、拉片 taskId/jobId、视频 videoTaskId/provider（**这正是 S2 的解**：Wan job→成片 taskId 映射只落 localStorage 仅留 200 条、导出不带——`video.ts:302-327` 亲读；批次身份记录成为该映射的持久归属，随项目走）。合同 C5 原文：「批次成员关系是持久身份数据可存（Codex 审计澄清：身份≠第二状态源）」。
- **状态（禁存，一律派生）**：实例跑到哪步/成功失败/是否已批——派生自节点 `metadata.status`（生成态）+ `generation_get_status`（`agent-site-tools.ts:82-113`）+ hub 任务态 + 后端 job；编排进度（「拆解完→置换待做」这类无状态位的步骤）从节点存在性+连线+内容推断（Claude C5 边界），推断规则随 P5 写卡。
- 判据：身份记录里**任何字段都不回答「现在怎么样」，只回答「谁是谁/哪个属于哪个」**。审批真源在 hub（§四），生成真源在节点/后端。

### 5.4 落点与实现边界

具体字段名/schema 随 P2（模板声明）/P5（批次成员+状态派生）拍板，本裁决冻结四条原则：①身份与状态分离（上文判据）；②随项目持久化并进 v3 导出（导入不丢，同步改导入构造——Codex §3.3）；③写盘节奏受 G14 约束（400ms 防抖全量序列化，`use-canvas-store.ts:56-64`；flush API 属 P5 卡）；④批次身份记录不复制第二份图/正文 DSL（C1 精神）。

## 六、自修与队列边界细化（D11 细化）

### 6.1 自修 2 轮的计数口径

**口径=每实例计「修改→重检」完整闭环轮次，与 finding 数量无关。**

- 1 轮 = 对某实例执行一次「汇总全部 findings → 限定范围修改（正文/挂图等非冻结项）→ 经既有保存/重检入口重跑自检 → 得到新结果」。
- 同一实例不管本轮修了几个 finding、动了正文还是挂图，都只消耗 1 轮；**不按每 finding 计数**（防 finding 多的实例隐性获得无限自修预算——Codex 风险表「自动自修消耗与无限循环」）。
- 上限 2 轮（D11）；轮次计入批次报告（D12 费用透明同路）。

### 6.2 升级给人的判定条件（任一即升）

| # | 条件 | 理由 |
|---|---|---|
| U1 | 2 轮耗尽仍有 finding | D11 字面 |
| U2 | 修复需触碰冻结项（指令模板 id/generationMode/composerContent 骨架/骨架拓扑） | 自修不豁免不改冻结项（收敛裁决 P7b 验收；C2） |
| U3 | 修复动作是付费类操作（视频生成/付费重跑） | 自修只允许非付费自动段（正文改写/挂图调整/重检）；付费一律人在场（C6/红线 1，P0b 闸） |
| U4 | 同一 finding 连续两轮采用相同修法仍复现 | 防等价修法死循环空耗轮次与费用 |
| U5 | 自检/重检通路本身失败（读不到全文、保存被拒） | 基础设施异常不是可自修对象，升级给人排查 |

### 6.3 并发 3 的作用域

**渠道级**（同一渠道的在途生成请求 ≤3），非实例级：

- 实例内部节点天然有依赖序（拉片→正文→挂图→自检→待批），并行主体是**实例之间**；限流的真正目标是渠道侧（G5 纠正：现状无队列无上限并发，`project.tsx:376-381` 按 node 键控、不同节点并发直打渠道——Claude 维度 2 G5 亲验转述）。
- 渠道级生效示例：**Wan 单槽=1**（bridge `WAN_BUSY.acquire(blocking=False)` 第二条直接 409，`server.py:3138-3139` 亲读）——并发 3 对 Wan 实际收敛为 1，队列须按 409 退避重排不视作失败；SDGF 等多任务渠道用满 3。前置自动段（拉片）共用 bridge 同一把拆解槽（409 排队语义，勘察 §3.3），天然串行，不占渠道并发额度（推测（未验）：拉片槽与生成槽互不占用——未读 `server.py:3670` 区段，P6 验）。
- D10 渠道跟随模板：批量层不重新选渠道；首批 Wan 端到端深验、其余渠道跑通即可（D10 字面）。

### 6.4 未知提交对账流程（D11「禁止自动重试」的落地）

```
提交回执超时/断线/丢失
  → 标记该实例提交态=unknown（进批次报告，可见）
  → 用已知任务号续查：画布视频节点 videoTaskId/videoTaskProvider + generation_get_status；hub 侧 generating+有确定回执走续查不创建（hub_api.py:3290-3291 既有守卫，语义照搬）
  → 查得在途/完成 → 接续收敛，不重复创建
  → 查无且证据确凿未创建（如 409 槽占用可证） → 交人决定是否重建
  → 永不：自动层按超时重发付费提交（A2/Codex B6：30s 超时不取消页面动作，晚回执≠未执行）
```

对账范围含 Wan 成片映射（S2）：unknown 期间 job→taskId 若已回填须先 `recallWanFileTask` 续查（`video.ts:316-327`）再下结论。
