## 1. 事实校正（必须先摆出来：现有侧栏在「左」，不在「右」）

卡面写「画布右侧栏新增待审批页签」。真机与代码一致地表明：**现有 `canvas-side-panel` 是左侧面板**。

| 事实 | 证据 |
|---|---|
| 左栏在 `<main className="flex">` 里排在画布 `<section>` **之前** → 物理在左 | `web/src/pages/canvas/project.tsx:4114-4115` |
| 动画从 `x:-48 → 0`、边框 `border-r`、resize 手柄贴在 `right-0` → 左栏语义 | `canvas-side-panel.tsx:96-100,117` |
| i18n 文案自己写着「调整左侧面板宽度」 | `i18n/locales/zh-CN.ts:277`（`sidePanel.resize`） |
| 画布页右侧**没有任何常驻面板**（全页搜 `right-0` 只命中节点内小按钮与 resize 手柄） | `grep -rn "inset-y-0 right" pages/canvas components/canvas` 0 命中页面级面板 |

所以有两种落法，请所有者拍板：

| 落法 | 做法 | 代价 | 建议 |
|---|---|---|---|
| **A1（推荐）** | 现有左栏加第 4 页签 `待审批`；点实例 → **右侧滑出 760px 抽屉**（可关、非常驻） | 需要新增一个抽屉容器（前端组件，非新页面、非新路由） | ✅ 与三页签同构、复用现有 TabButton/宽度/resize store；「右侧」由抽屉实现，视觉上仍在画布右侧 |
| A2 | 新建**右侧常驻**面板（新宽度 store + 新 resize + 新 z 层） | 第二套常驻面板 = 第二套宽度/拖拽/开合逻辑，画布可用宽度再被吃掉一条；违背「零新容器」倾向 | ❌ 不建议 |

> 一句话：**页签放左边（跟现有页签一起），详情放右边（抽屉）**。这样既不改现有侧栏的物理位置，也满足「详情在画布右侧」的直觉。

### 2.2 hub 详情抽屉（现有呈现，供复用而不是重造）

`pages/hub/task-detail-drawer.tsx`（4233 行）是**全屏 Drawer**，结构注释写得很清楚：

```
头部 → Agent 建议 → 资产置换 → 提示词 → 审批 / 生成 / 成片
```
（`task-detail-drawer.tsx:125-127`）

其中两段是本卡要**原样复用**的：

| 段 | 说明 | 位置 |
|---|---|---|
| 提示词段 | 标题一行 + 正文默认展开可收起 + **自检/门禁独立整宽区** | `:444`、`:2264-2290` |
| 自检面板 | 「有异常默认展开」；卡片按 `行号` 分组；每卡含 项/结论/证据/说明＋折叠块（内部统计 / 机器键值 / 这一行的清单原文 / 提示词里的原句 / 切法 / 检查器原始输出） | 注释 `:2451`、卡片组装 `:2471-2484`、折叠块 `:2613-2618` |

真实自检数据（`auto-0066/自检.json`，真机读数）字段就是：
`项 / 项显示名 / 结论(PASS|FAIL|WARN) / 证据 / 说明{结论人话, 处理, 统计} / 切片`。
→ 待审批页签的自检区**直接搬这组字段与卡片样式**，不发明第二套「自检说法」。

### 2.3 状态机 9 态 → 列表徽标映射（禁新造第二状态源）

`automation/state.py:35`：

```
ingested → discussing → awaiting_assets → rendering → awaiting_approval → approved → generating → done / failed
```

| 列表徽标 | 真实来源 | 说明 |
|---|---|---|
| 待审批 | `awaiting_approval` | 提示词已出、还没批；**这就是「包」的成态** |
| 已批准 | `approved` | 已固化配置+快照，**还没花钱** |
| 生成中 | `generating` | 付费已提交，`gen_progress` 给百分比 |
| 已完成 | `done` | 有成片（`has_output`） |
| 失败 | `failed` | 带原文错误/证据，禁静默降级 |
| **已退回** | `awaiting_assets` + `history` 里有 `退回置换` 记账 | **没有独立状态**——退回就是受控回退到 `awaiting_assets`（`state.py:245-267`）。徽标由「当前态 + 最近一次 history」派生，不新增 state |

> 这条直接照 `勘察-画布工作流批量承接-20261113.md` §3.4 建议 3：**批次/审批状态只做派生视图，状态真源仍是任务状态机**。

### 2.4 「退回」到底丢了什么（原型里必须说出来）

`automation/state.py:245 rollback_to_assets()`：

1. 删 `提示词.md`（本次这版正文**没了**）；
2. 删 `自检.json`（那代结论一起作废）；
3. 清 `ROLLBACK_CLEARED_KEYS` = `approval / approval_snapshot / gen_params / …`（`state.py:74`）；
4. `state = awaiting_assets`，`history` 追加一条 `退回置换`。

UI 里写的就是这句人话：**「退回 = 丢弃本次提示词、回置换区重做，这版正文不保留」**（图 3 动作位旁、图 2 行徽标处）。

## 5. 两个布局候选 + 推荐

### 候选 A（推荐）：左栏列表常驻 + 右侧 760 抽屉详情

- 左栏（280）永远只放**列表**；点实例 → 右侧抽屉 760 滑出，关掉回到列表。
- 抽屉内容 = 图 3 / 图 4：两态条 → 提示词全文 → 挂图位 → 置换摘要 → 自检 → 自修痕迹 → 批准/退回。

**推荐理由（按权重排）**：

1. **批量看包的本质是「对照」**：A 里列表始终在原地，看完第 1 条直接点第 2 条，不必收/展、不必滚回顶；B 每次展开都挤走其余实例。
2. **详情需要宽度**：760 下提示词可读、挂图位「换图/否决」能并排；480（B 的上限）只够 2-3 行摘要，看全文要滚，读起来比 hub 抽屉更憋。
3. **零新常驻容器**：抽屉是**临时层**，关闭即释放；左栏仍是单一面板，宽度 store 不动，画布可用宽度只在看详情时临时让出。
4. **与既有习惯一致**：hub 的详情就是抽屉（全屏），所有者已经熟；这里只是把它收窄成 760 并允许左侧列表共存。
5. **反人类风险最低**：所有动作位（批准/退回/付费）都在抽屉底部的固定位置，滚动长正文也不会把按钮推走。

**代价（如实）**：抽屉占掉画布右侧 760px，看详情时画布只剩约 880px 可见；需要「关抽屉 / 在画布中定位」两个出口把用户送回去。

### 候选 B：左栏就地展开（栏宽 220→480）

- 点行即在原位展开详情，手风琴式；不加任何新容器。

**优点**：零新面板、零遮挡画布、实现量最小（只改一个文件 + 一个展开态）。
**代价**：① 展开挤走列表（图 5 ②）；② 480 宽下详情被迫摘要化（图 5 ③）；③ 长正文滚动时动作位离视口远。

### 对照

| 维度 | 候选 A（列表+抽屉） | 候选 B（就地展开） |
|---|---|---|
| 批量对照能力 | ✅ 列表常驻 | ❌ 展开即挤走 |
| 详情可读性 | ✅ 760 宽，全文+并排按钮 | ⚠️ 480 上限，摘要化 |
| 新增容器 | 一个抽屉（临时层） | 零 |
| 画布遮挡 | 看详情时遮挡右侧 760 | 不遮挡（但永久占宽 480） |
| 实现成本 | 中（抽屉 + 两个视图） | 低（单文件） |
| 反人类风险 | 低 | 中（滚动/收起反复） |
| 结论 | **推荐** | 备选；若所有者更看重「不遮画布」再选它 |

## 6. 与 hub 详情抽屉的区别（别把两件事混成一个）

| 维度 | 本页签（待审批） | hub 详情抽屉（现状，不改） |
|---|---|---|
| 目的 | **批量看包拍板**：一批 N 条，快速过、批量批/退 | **逐任务编辑**：深改一条 |
| 入口 | 画布左栏第 4 页签 | `/hub` 表格行「打开」 |
| 布局 | 列表 280 常驻 + 右侧 760 抽屉 | 全屏 Drawer（1920 全宽） |
| 动作 | 批准 / 退回 / 跳画布定位 / 批量付费确认 | Agent 建议、资产置换、手改正文、重试、强制结束、删除、fork… |
| 编辑职责 | **零编辑**：正文只读、置换只读；要改回画布或置换区 | 全部编辑都在这里 |
| 生命周期 | 包被批完/退完即清空 | 任务全生命周期 |
| 复用关系 | 只借 `SelfCheckPanel` 与字段口径 | 不被替代、不被删减 |

一句话：**页签是「看包、拍板、付钱」；抽屉仍是「改任务」。两套并存，谁都不吞谁。**

## 7. 数据与合同缺口（需 B0 / P0b 拍板，首版不造假）

> 对齐声明：批次身份与自修口径**照抄同批兄弟交付 `docs/设计-P0a批量代办设计裁决-20261113.md` §五 / §六 的裁决**（该文件撰写时未提交，作者=同批卡；本卡不另立一套）。凡与 P0a 冲突，以 P0a 为准。

### 7.1 批次身份（P0a §5 已裁决，照用）
- **身份记录存画布项目内**（IndexedDB，随 v3 导出携带），**不进节点 metadata、不建仓外 JSON、不进 hub**。
- 身份字段（可存）：`batchId`、批次创建参数摘要、实例 id、骨架节点 id 清单（含输出节点 id，执行期回填）、hub `local_id`、拉片 `taskId/jobId`、视频 `videoTaskId/provider`。
- **状态一律派生**（禁止存第二状态源）：实例跑到哪一步 = 节点 `metadata.status` + `generation_get_status` + hub 任务态聚合。
- 判据（P0a 原文）：身份记录里**任何字段都不回答「现在怎么样」，只回答「谁是谁 / 哪个属于哪个」**。
- → 本页签列表要的「批次头 + N 个实例 + 聚合计数」全部是这张身份记录的**只读派生视图**。

### 7.2 实例 ↔ 画布节点映射（P0a §5.3 已含）
定位跳转要的正是身份记录里的「骨架节点 id 清单 + 输出节点 id」。
建议取序：**结果节点 → 终稿槽 → 源视频**，取第一个仍在画布上的节点调 `onFocusNode`；都找不到时按钮置灰并说明「节点已被删除」（不静默失败）。

### 7.3 Agent 自修痕迹（字段新增 + 口径已冻结）
全仓 `grep 自修|修复轮|revision_round` → **0 命中**，所以是纯新增字段；但**口径已由 P0a §6 冻结**，UI 只读不推断：

| 项 | 口径（P0a §6.1 / §6.2） |
|---|---|
| 轮次计数 | **每实例**一轮 = 一次「汇总全部 findings → 限定范围改（正文/挂图等非冻结项）→ 走既有保存/重检入口重跑自检」，**与 finding 数无关**；上限 **2 轮** |
| 徽标写法 | `自修 n/2`（如 `自修 1/2`）；无自修显示 `无自修`，**不显示 `0 轮` 假装有数据** |
| 升级给人 | 任一命中即升：**U1** 2 轮耗尽仍有 finding；**U2** 要动冻结项（指令模板 id / generationMode / composerContent 骨架 / 拓扑）；**U3** 修法是付费动作；**U4** 同一 finding 两轮同修法仍复现；**U5** 自检/重检通路本身失败 |
| UI 呈现 | 红标 `2/2·升级 U<原因>`，展开逐轮看「改了什么 / 结果」；失败轮次**不隐藏** |
| 谁写 | **批处理执行器**写（它才知道自己改了几轮）；前端不按 diff 推断 |

### 7.4 付费预估（P0b）
停点条要显示「待付费 N 条 · 预估合计 ¥X」。金额**只能来自 P0b 报价接口**（模型/画幅/时长决定单价），前端不自算，缺报价时显示 `¥ —（待报价）` 而不是 0 或猜数。

### 7.5 页签角标 N 的口径（需定）
建议 `N = 待审批 + 已退回`（两者都需要人看）；`已批准未付费` 不进 N（那是付费停点的事，另有计数）。
