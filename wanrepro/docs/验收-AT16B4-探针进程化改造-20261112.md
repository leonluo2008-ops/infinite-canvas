# 验收-AT16B4 探针进程化改造-20261112

任务卡：t_d8231455（修复 AT-16 回归探针 b4a/b4b：进程内 monkeypatch 驱动已失效）
基线：feat/automation @ 42e3c11 → 本次单 commit **9efc43a**（见 §5 交付清单；实测与回归均在该 commit 上复跑）

## 1. 根因与改法

AT-19 把拆解执行体搬进独立子进程（`automation/discuss_runner.py`，`ui/hub_api.py:_spawn_process`）
后，两个 AT-16 探针的驱动方式失效：

| 探针 | 旧驱动（失效） | 新驱动（本次改造） |
|---|---|---|
| b4a | 探针进程内 `hub_api.discuss.run_discuss = fake_run`（:164/:223/:259） | **零补丁**：夹具桥按轮询次数编排「阶段A→阶段B→done/error」，执行体跑真代码；写路径走隔离实例 HTTP（`POST /api/hub/discuss/<id>`、`POST /api/hub/task/<id>/retry`） |
| b4b | 探针进程内调小 `POLL_INTERVAL`/`HEARTBEAT_INTERVAL` | 端到端段零补丁：hub 起真子进程，加速只走环境变量（`_spawn_process` 透传）；[5][6] 保留为**单元级**（直接对 `discuss.start_and_wait` 验回调分离，锁的是模块合同不是进程链路） |

新增**执行体加速位**（`automation/discuss.py`）：

- `_env_seconds(name, default)`：`WANREPRO_POLL_INTERVAL` / `WANREPRO_HEARTBEAT_INTERVAL`，
  **不设 = 现常量**（3s / 60s）；空串/非法/非正数一律回落默认 → 生产行为逐字不变。
- 读取点在 `start_and_wait` 调用时（非 import 期），模块常量本身一字未动 →
  `tests/test_state_lostrun.py` 的冻结常量断言照过（实测 ALL PASS）。
- `ui/hub_api.py:_spawn_process` env dict **显式**透传这两个变量（不设 = 空串 = 子进程用默认），
  写在派发点是合同可审：加速只能走 env，进程内 monkeypatch 对子进程无效。
- 优先级：显式 `heartbeat_interval` 参数 > env > 模块常量。
