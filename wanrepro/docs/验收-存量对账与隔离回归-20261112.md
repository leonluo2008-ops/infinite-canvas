## 3. 隔离探针（`probe_at18_reconcile.py`）

```
$ python automation/probe_at18_reconcile.py
[probe-at18-reconcile] 65/65 PASS
[probe-at18-reconcile] 已清理隔离根：C:\Users\leon3\AppData\Local\Temp\probe-at18-reconcile-…
```

隔离手法：`WANREPRO_AUTO_DIR` → 临时根；`WANREPRO_BRIDGE` → 自起的黑洞 TCP 端口（接受连接不回包，
让重试拉起的拆解 job 停在 running）；夹具一律 `auto-97xx`、桥 id 一律 `probe-at18-*`。
**看门狗故意开着**——本探针要证明的就是自动扫描。阈值不改、也不真等 15 分钟：夹具的持久时间戳
（`history.at` / 心跳时刻 / `inbox/*` 的 mtime）直接做旧到 `now-1200s`（判定是时间戳证据的函数，
做旧时间戳与真等 900s 在判定上等价，方案 §2.2）。

四件事的落点：

| 卡片要求 | 探针断言（节选） |
|---|---|
| 自动扫描把它降为 failed | `[3]` auto-0052 同构夹具（只有 `inbox/` + `任务.json`、无心跳、零产物、无进程）由**看门狗**在 90s 内降为 failed；`failed_reason` 逐字、`failed_evidence.trigger=auto_scan`、降级发生在首跑延迟之后（≥25s，不是伪造的瞬时写）、目录与 inbox 一个文件不少 |
| 此前被拒的删除在 failed 后可成功（墓碑） | `[4]` 同一根里 `discussing` 删除仍 409 原文「任务运行中（discussing），删除拒绝」；自动降级后的 failed 删除 200、`state_was=failed`、`tombstone=true`、目录消失、墓碑出现该 id |
| 重试通道可把它重新跑起来 | `[5]` `failed → retry` 200、`heartbeat_reset=true`、`previous_reason` 回显原失败原因、`心跳.json.run_id` 已整体重建、状态回到 discussing、旧原因仍在 history；在跑 job 时再重试 409「已有拆解任务在跑」 |
| 强制结束在误判场景可作人工兜底 | `[6]` generating 被扫描判 `in_flight_cloud`（自动通道永不降级）但可人工强制结束 → 200 `manual_force`；「看着还活着」的 discussing 扫描不误杀、强制结束仍 200；两者都不删任何文件；缺 `confirm_name` → 400；重复调用 200 `already=true`；强制结束后的任务可重试（兜底不是死路） |

另含：对账脚本以**子进程**方式跑（证明交付件本身可用），dry-run 中文报告四段齐全且任务文件字节不变
（零写入）；`--apply` 降级 + 连跑幂等；`generating` 不自动降级；坏任务不影响整轮（脚本层 errors + 退出码 1，
`--root` 实测）；真实 `projects/` 目录集与各 `任务.json` 哈希、`analysis/reverse/`、`uploads/` 集合前后一致。

## 6. 边界（如实登记）

1. **降级文案 vs 真实错因**：`auto-0053` 的真错因是 runner 退出码 3（`analysis/reverse/<bid>/进度.json`），
   但状态机从未收到失败回写，对账只能按冻结口径写「拆解进程失联，可重试或删除」。要保留原文，得修
   runner 的失败回写（不属本批）。降级不丢证据：`failed_evidence` + 原 `进度.json` 都在。
2. **`generating` 不自动降级**（方案 §3.2 划界）：扫描只报 `in_flight_cloud` / `manual_only_state`，
   出清只能走人工强制结束。本批不新开自动通道。
3. **跨进程 TOCTOU**：`fail_orphan_task` 的并发保护是本进程内 `threading.Lock` + 写盘前重读；
   独立进程同时扫描同一任务仍有微秒级窗口（状态机 `transition` 同样不持跨进程锁）。watchdog 与手动
   扫描同进程，实际路径不触发。
4. **看门狗周期 300s**：自动清出最长滞后 300s + 首跑 30s；前端用 `lost_run.suspect` 提前红字，不必等降级。
5. **`auto-0053` 未删**：只降级。删除是所有者动作（墓碑不可恢复），探针已在隔离环境证明 failed 后可删。
6. **本批不动**：`automation/render.py`、`pipeline/**`、`templates/**`、`prompts/**`、`automation/discuss.py`、
   既有 `probe_at9`–`probe_at18_hubexit` 探针；真实任务内容只读（唯一写动作是 5 个键的降级）。
