# 验收 · 强制结束「已提交远程拆解」的任务后重试引导（auto-0067 现场）

- 日期：2026-11-12
- 卡：t_3dfbd769（缺陷：强制结束后重试陷入「拆解槽忙」无限排队，且终止语义对用户不透明）
- 分支：`feat/automation` ｜ 单 commit

## TL;DR

| 项 | 结论 |
|---|---|
| 根因 | 桥端「拆解槽」（`ANALYZE_BUSY`）是**进程内锁**，hub 侧看不见持有者；强制结束只终止本地，远程照跑、槽仍被第一轮的等待循环占着。新 run 一起来就撞 409，界面只剩「第 N 次失败」计数 |
| 修法 | 把槽真相接出来（`GET /api/lapian/slot`）→ 一个文案源（`automation/remote_wait.py`）→ 四处出口说同一句话：桥端 409 自述、discuss 排队日志、重试入口前置拒绝、强制结束回执/详情页 |
| 方案取舍 | 取**方案 a（明确禁止 + 说清还要等多久）**：本任务上一轮远程还在跑时重试直接 409 拒绝，不让人点进排队死循环；别的任务占槽仍走排队（文案指名持有者） |
| 探针 | 新探针 `probe_force_remote_busy` **43/43 PASS**；卡面要求回归 **7 份全绿**（见下表） |
| 真机 | 只剩所有者的「强制结束 → 立即重试」复测（需一次真实远程拆解在跑，属于付费/现场动作，Agent 不代跑） |

## 三条产品语义（所有者裁定，已落到界面人话）

1. **已提交到远程的拆解无法取消**，只能等它返回——强制结束的确认文案、回执、详情页都明说；
2. **再提交同一条任务只能等上一个结果返回**——重试撞上「本任务远程还在跑」时直接拒绝，给出「已跑多久 / 预计还需多久 / 返回后槽自动释放」；
3. **结果返回后按作废丢弃**，不覆盖 failed——回执与详情页同一句；作废栅栏本身没动。

## 真机验收步骤（所有者）

前置：桥已用新代码重启（本次已重启 8776/8779，`GET /api/lapian/slot` 均 200）。

1. 建一条任务并正常发起拆解，等到「已提交拆解（job=…）」出现在拆解日志（远程确实在跑）；
2. 点「强制结束」→ 确认弹层里应看到新增的那句「已经提交到远程（聚鑫）的拆解无法取消…」；
3. 确认后 toast/行内应出现三分回执：本地已终止 / 远程仍在跑（已跑 X 分 Y 秒，预计还需约 Z 分钟）/ 结果按作废丢弃；
4. 打开详情（抽屉）→ 顶部同样一行「远程半边」说明，且 5 秒轮询后会随远程进度更新；
5. 立刻点「重试」→ 按钮呈禁用态、文案变「等远程返回后重试」；若接口被调（键盘/脚本），返回 409 人话：**在等什么、预计还需多久、为什么只能等**，不再是「第 N 次失败」；
6. 等远程返回（槽释放）→ 刷新详情，远程那行变「已不在跑（若已返回，结果按作废丢弃）」，重试按钮恢复；点重试应正常进入拆解。
