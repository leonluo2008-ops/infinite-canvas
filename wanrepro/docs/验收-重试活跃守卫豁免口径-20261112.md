# 验收：start_retry 活跃守卫改用带豁免的统一存活判定（方案 B）

日期：2026-11-12　｜　范围：`ui/hub_api.py` start_retry 第一关守卫 + 判据抽层　｜　提交：`ab3e2dc`（与方案 A 同 commit，见「交付位置说明」）

## TL;DR

| 项 | 结论 |
|---|---|
| 缺陷 | 重试守卫用 `_job_running_records`（纯 `status=="running"`，零豁免），与看门狗/删除合同的 `_job_alive`（60s/900s 心跳豁免）两套口径并存 → 人工强制结束后的残留记录把重试永久挡死 |
| 修法 | 判据上收为**一份** `_job_blocks_retry(rec, heartbeat_at)`（返回「命中的存活依据」人话，空串=不阻断），`_job_alive` 改成它的布尔投影；start_retry 的新守卫 `_retry_guard` 与删除合同/held_job 同源 |
| 守卫保留 | 启动 ≤60s 或心跳 ≤900s 的真 running 仍 409，不起第二个拆解 |
| 可解释 | 拒绝文案带 `job=<id>`、`status`、`started`（+距今时长）、命中依据；放行回执带 `ignored_stale_jobs` 逐条说明被豁免的记录 |
| 验证 | 新探针 37/37；`probe_at19_proc` 36/36（真子进程 + 真 HTTP 重试）；`probe_at18_reconcile` 65/65（真机重试 & 在跑再重试 409）；`tests/test_at19_exec_judge.py` 35/35 |

## 改了什么

1. `_job_blocks_retry(rec, *, heartbeat_at) -> str`（新增，:293）：唯一判据。只认
   `status=="running" ∧（启动 ≤ HEARTBEAT_SECONDS(60) ∨ 心跳距今 ≤ STALE_JOB_SECONDS(900)）`；
   命中时返回依据文案（`启动至今 Ns ≤ 60s 启动宽限期内` / `心跳距今 Ns ≤ 900s（执行体仍在打心跳）`）。
   `force_finished`、`failed`、`done`、无心跳孤儿一律返回空串 = 不阻断。
2. `_job_alive()` 改为 `bool(_job_blocks_retry(...))`（:316）——看门狗、`delete_task`、`_held_job`
   与 retry 守卫从此共用同一份判据，放宽/收紧两侧同时生效，不会再有「看门狗认死、重试认活」。
3. `_retry_guard(local_id, task_dir) -> (阻断记录, 命中依据, 被豁免清单)`（:924）：读任务心跳侧车
   作为第二证据源（与 `delete_task` 同法），逐个记录判定；阻断取第一条，其余陈旧记录登记成
   `kind:job_id（status=…，started=…，已运行 Ns，未达存活判据，已豁免）`。
4. `start_retry`（:949）：守卫换成 `_retry_guard`，顺序仍是**先 job 后状态**；拒绝文案带上
   `job/status/started(距今)/命中依据` 与「另有陈旧记录未阻断」；成功回执新增
   `ignored_stale_jobs`（与删除合同同名字段，前端只多一个可选键）。
