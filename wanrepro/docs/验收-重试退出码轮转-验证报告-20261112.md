并在派发 T0（换 run 时）作废上一轮的退出码文件。结果是：**新 run 写得进自己的死证，旧 run 迟到写仍被拒**。

## 根因

`automation/state.py` `exec_write()`（42e3c11 引入）用**文件里的 run_id** 做栅栏：

```python
if current.get("exists") and str(current.get("run_id") or "") not in ("", str(run_id)):
    return current     # 新 run 也被挡
```

第一个 run 的凭证成了不可变单槽：之后每个新 run（含 retry 派发的新 run）都写不进去。
`judge_exec_dead` 的 E1（要求 `exit_run == 本次 run`）对重试后的 run 永不命中，死亡判定退化到 E2。

## 修法（两处，语义互补）

1. **栅栏换锚**（`automation/state.py`）
   - `exec_owner(task_dir)`：读 `任务.json.exec_run_id`（当前 run 所有者令牌）。
   - `exec_write`：`run_id != 所有者` → 拒（旧执行体迟到写）；`run_id == 所有者` → 放行（新 run 能覆盖旧死证）；
     所有者缺失（旧任务/坏任务文件）→ 退回文件级保守栅栏，行为不削弱。
2. **换 run 即作废旧死证**（`automation/state.py` `exec_rotate` + `ui/hub_api.py` `_spawn_process` T0）
   - T0 写序变成 `heartbeat_begin → stamp_exec_run → exec_rotate`，再 Popen。
   - 删文件而不是写空值：`exists=False` 才是「本次 run 还没写退出码」的语义，任务目录不会在整个新 run 期间挂着上一轮的 `exit=3`。
   - 作废后旧执行体的补写由上面的所有者栅栏拒掉，所以「作废了又被旧 run 写回来」不可能发生。
