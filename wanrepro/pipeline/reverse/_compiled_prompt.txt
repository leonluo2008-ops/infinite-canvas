# 视频逆向拆解提示（v2 · 正向指令版）

> 产出：一份可直接驱动视频生成模型的 JSON 规格。
> v2 修掉 v1 的三处毛病：删掉"不是影评人"这类负向角色设定、删掉"禁用氛围感/电影感"（与官方示范相反）、把禁令改写成正向填写要求。

---

分析这段视频，按下面的 JSON 结构输出**一个 ```json 代码块**，不要任何解释文字。

## 填写要求

1. **每镜必须给出景别、机位、焦段观感、运镜、速度**，取值来自下方受控词表；表里没有的写最接近项。
2. **动作写成物理步骤**：谁、用哪只手、抓住什么位置、朝哪个方向、移动多少；一条动作一个 `t_s`。
3. **时间首尾相接**：所有镜头的 `start_s` / `end_s` 连续，不重叠不留空；有剪辑点就拆镜。
4. **产品出现过的每一镜**都要给 `bbox_rel`（0~1 相对坐标，原点左上）和 `screen_share_pct`（整数百分比）。
5. **声音分三层**：BGM 风格、有无人声（有则逐字转录）、音效及其秒点。
6. **屏幕文字逐字记录**，含出现与消失秒点；平台尾卡（TikTok/Reels 搜索页）单独作为最后一镜。
7. **看不清、听不清、判断不了** → 写 `"uncertain"`。
8. **`absent` 写 3 条以上**：这类视频通常会有、但本条画面里没有出现的元素，可直接用作负向清单。
9. 风格/情绪词照常用（电影感、胶片颗粒、质感这类），**同时给出对应参数**（焦段、景深、颗粒、色温、光位、画幅）。

## 受控词表

- `shot_size`: ECU / CU / MCU / MS / MWS / WS / EWS / TOPDOWN_FLATLAY
- `camera_angle`: eye_level / high_angle / low_angle / overhead / dutch / over_shoulder
- `camera_move`: static / push_in / pull_back / pan_left / pan_right / tilt_up / tilt_down / truck_left / truck_right / pedestal_up / pedestal_down / orbit / handheld_drift / zoom_in / zoom_out / rack_focus / whip_pan
- `move_speed`: none / slow / medium / fast
- `focal_feel`: 14 / 24 / 35 / 50 / 85 / 100 / macro / uncertain
- `light_direction`: top / top_left / top_right / left / right / front / back / bottom / ambient
- `light_quality`: hard / soft / diffuse
- `transition`: none / hard_cut / dissolve / match_cut / whip / platform_card
