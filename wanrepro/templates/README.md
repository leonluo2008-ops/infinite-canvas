# templates/ · 模板格式规范

> 模板 = 一段提示词的**骨架**。九层拆解是中性 IR，与模板解耦；换模板不改引擎，只换本目录下的一个 `.md`。
> 硬规矩：**段落结构只能从范例提炼**，每段定义必须能在 `library/examples/` 里找到原文实例。凭训练知识发明的段落结构一律不收。

## 1. 文件与命名

- 一个模板一个文件，放在 `templates/` 下，文件名 = frontmatter 的 `name`，小写 + 连字符，如 `lumi-4section.md`、`employee-checklist.md`。
- 只放模板，不放代码、不放产物。渲染器读的是正文里的固定字段，不是自然语言段落。
- 现有五套（按出处分，都可选）：
  - `lumi-4section.md` — 模板 A · Lumi 四段。**17 条飞书范例逐条计数归纳**，可信度最高。
  - `employee-checklist.md` — 模板 B · 甲方清单式（✅ 条目）。**来自 `docs/需求溯源-20261029.md` §3**（需求录屏 320s 帧抄录，部分字迹标 □）。
  - `seven-section.md` — 模板 C · 七段。**我方早期拟制，无甲方成品依据**，仅作备选。
  - `timeline-narrative.md` — 模板 D · 时段叙事体。**来自甲方一手件**（`docs/原提示词-抄录.md`，该片所用的成品提示词）：
    一句一条、图号在句内、不写列名。用 `- 分镜列：` 指令挑列（见 §4.1）。
  - `seedance-flow.md` — 模板 E · 单段流式。**来自甲方一手件**（`人工目录-AI勿删/即梦画布/视频生成提示词.txt`，逐字抄录见 `docs/原提示词-单段流式.md`）：
    正文只有一段、`N-M秒` 推进、末尾一致性句，**无标题无附注**（frontmatter `正文模式: 流式`）。

## 2. frontmatter

```yaml
---
name: lumi-4section          # 必填，与文件名一致
来源: library/examples/ 17 条飞书范例   # 必填，写清归纳自哪批范例
段落数: 4                    # 必填，主序列段数（不含可选段）
可选段: 前置总述（2/17）、全程约束（1/17）  # 可选，列出可选段及出现频次
版本: 1                      # 可选，模板语义变化时 +1
废弃: false                  # 可选，true 时渲染器拒绝选中
---

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 与文件名一致；渲染器按它选择模板 |
| `来源` | 是 | 范例批次路径 + 条数，用于追溯 |
| `可信度` | 否 | `有据（…）` / `无…依据，仅作备选`。有依据的模板必须写明依据在哪；无依据的必须写明「无」，不得含糊 |
| `段落数` | 是 | 主序列段数，必须等于正文 `### 第 N 段：`（清单式模板用 `### 第 N 行：`）的条数 |
| `可选段` | 否 | 逗号/顿号分隔，只做说明；可选段正文另起标题 |
| `版本` | 否 | 整数，缺省视为 1 |
| `废弃` | 否 | `true` 时不参与选择 |

## 3. 正文结构

```markdown
# 模板 A · <短名>

## 适用场景
<什么片子选它 / 什么片子不选它，2–5 条>

## 段落定义

### 第 1 段：<段标题>
- 写什么：<内容清单，可含编号子项>
- 数据来源：`九层 六（意境）` → 氛围；`九层 四（光影）` → 光线
- 口吻：<陈述式 / 指令式 / 名词短语…，并说明限制>
- 范例证据：
  - **Part.1**：「<原文片段>」
  - **Part.2**：「<原文片段>」
  - **Part.19**：「<原文片段>」

### 第 2 段：...
```

### 每个段落的四要素（全部必填）

| 要素 | 行首标记 | 说明 |
|---|---|---|
| 标题 | `### 第 N 段：` | N 从 1 连续递增，冒号用全角 `：` |
| 写什么 | `- 写什么：` | 该段要产出的内容清单；渲染器据此判断“这层数据够不够写这一段” |
| 数据来源 | `- 数据来源：` | 声明取九层的哪几层；渲染器**只校验、只取数**，不替模板组织语言 |
| 口吻 | `- 口吻：` | 陈述式 / 指令式 / 名词短语；给生成侧作句式约束 |
| 证据 | `- 范例证据：` 或 `- 原文依据：` | **二选一，必填其一**：<br>① `范例证据`：≥ 3 条，格式 `**Part.N**：「原文」`，原文必须能在 `library/examples/` grep 到。<br>② `原文依据`：引 `docs/` 下某份抄录件（写清文件名与章节），适用于依据不是范例库的模板（如甲方成品抄录）。<br>**两样都没有的段落不收**；有依据但拿不出依据的，视同造假 |

### 可选要素

| 要素 | 行首标记 | 说明 |
|---|---|---|
| 命名变体 | `- 命名变体：` | 同一段在 17 条里的不同叫法与条数，供渲染时选标签 |
| 渲染建议 | `- 渲染建议：` | 开/不开这一段的判断条件，如“约束条数 > 5 时开” |
| 反面证据 | `- 反面证据：` | 说明哪些范例**没有**这样做，防止把少数派当通例 |

### 可选段

可选段另起标题，**不参与编号**，不占 `段落数`：

```markdown
## 可选段
### 可选段 A：前置总述（2/17）
- 写什么：… - 数据来源：… - 口吻：… - 范例证据：…
```

渲染器只有在开关打开（如 `--optional preamble`）时才输出可选段。

## 4. 渲染器怎么读

1. **切段**：按行正则 `^### 第 (\d+) 段：(.+)$` 切主序列，按 N 升序排；不按出现顺序、不依赖 `##` 层级。
2. **取字段**：段内按 `^- 写什么：`、`^- 数据来源：`、`^- 口吻：`、`^- 范例证据：` 取四要素；`- ` 后的续行（缩进子项）并入上一字段。
3. **取数**：`数据来源` 里的 `九层 <中文数字>（<层名>）`（或等价的 `十层 <中文数字>（<层名>）`）是本项目唯一认的引用语法，多层用 `；` 或 `、` 分隔。渲染器只把这几个层的数据塞进上下文，**不生成段落文字**——文字由模型按「写什么 + 口吻」生成。
4. **取标签**：段落标题取 `### 第 N 段：` 冒号右侧；若某条范例的标签与模板标题不同（见 `命名变体`），以模板标题为准。
5. **可选段**：以 `^### 可选段 ` 开头，不入主序列；`frontmatter.可选段` 只用于展示。

### 4.1 `分镜列` 指令（可选，叙事体用）

模板某一段写一行 `- 分镜列：时段,景别,运动主体,运动形态,情绪/表演?,站位,朝向,视线,镜头运动,画面内容`，该段就**不再逐列倒出表格行**，
而是按声明顺序取值、用中文逗号「，」连成**一句一条**（每个镜号一行）：

- 列名按声明顺序取，一列不多一列不少；空值 / `—` / `无人物` 的列直接跳过。
- 「速度」列不单独占位：渲染器把它并进紧邻的「运动形态」子句，读成这一镜动作的收束。
- 列名末尾带 `?` 是**可选列**（如 `情绪/表演?`）：旧拆解没有这一列就跳过，不判缺列；新拆解有就取。
- 取到 `运动主体` 那一列时，该镜的 `@图片N` **紧跟在主体值后面**（句内，不是行首前缀）。
- 列名可写 `时段`（对到表头 `起秒-止秒`）、`镜号`（对到 `镜号` / `#` / `序号`）；其余写表头原字。
- 声明的列名在表头里不存在 → **exit 3**（「模板要的列 X 拆解里没有」），不静默跳过。
- 没写 `分镜列` 的模板完全走原路径，旧三套模板产物一字不变。

### 4.2 `声音段` / `台词渲染` 指令（可选，音频三态用）

「八 声音」不再是「逐块倒出字段名」的一层，而是按**音频三态**渲染的声音段（AT-17 B2a）：

| 段字段 | 值 | 渲染行为 |
|---|---|---|
| `- 声音段：` | `是` | 该段正文接一段声音段：BGM + 音效点（+ 台词，若没有别的段认领台词） |
| `- 声音段：` | `行内` | 同上，但压成**一行流水句**（清单式口播行用；标点只剩一个句号） |
| `- 台词渲染：` | `说话人` | 该段另起台词行，一句一行：清单式 `[画外音] \| 画外音：原文`；说话人只认 `画外音` / `出镜者` 两类，没标就写「（说话人未标）」，不猜 |

三态规则（纯字符串，禁新增模型调用）：

- `沿用原片`：BGM 四字段原值、音效点逐条、台词逐句原样进声音段；
- `按新主体调整`：只留主体无关的**骨架**（情绪 / 节奏 / 织体 / 强弱走向），音效点整类不沿用（它们由原片主体的动作产生），BGM 值里点名旧实体的名词一并剥掉；
- `不要`：官方三档式「无 BGM，仅保留环境声」，原片 BGM 词一个不带；
- 无音轨片：只写一行「无音轨」，不写 BGM / 音效点 / 台词（省内容不省层）。

取值顺序：请求参数（`--audio-mode` / `/api/render?audio_mode=`）→ 任务目录 `audio_mode.json` → 按拆解推导（`intent.audio_mode`）。三档都没有时八 声音 走**原路径**，老产物一字不变。没标这两个字段的模板段完全不受影响。

## 5. 校验（渲染前跑，失败即失败）

- `段落数` == 主序列条数（`### 第 N 段：` 或清单式的 `### 第 N 行：`），且 N 连续。编号从 1 起；**仅当模板首段语义就是「总述」时允许从 0 起**，且须在 frontmatter 用 `首段编号: 0` 显式声明。
- 每段四要素齐全；缺一项报错，**不静默补空**。
- 每段有证据：`范例证据` ≥ 3 条且形如 `**Part.N**：「…」`，**或** `原文依据` 指明 `docs/` 抄录件与章节。**两者皆无 = 报错**。
- `范例证据` 的每条引文必须在 `library/examples/` 下命中（`grep -F` 精确子串）；0 命中 = 引用造假，报错。
- `原文依据` 指到的 `docs/` 文件必须存在且章节可定位；指不到 = 报错。
- frontmatter 有 `可信度` 且以 `无` 开头的模板，渲染器默认不选（需显式 `--template` 指定）。
- `数据来源` 里的层名必须在层清单内：一 场景 / 二 产品 / 三 运动 / 四 光影 / 五 镜头 / 六 意境 / 七 分镜表 / 八 声音 / 九 资产 / 十 图文与收束。
- 模板正文不得出现产品名 / 品牌 / 颜色 / 瓶型（项目硬约束 7）；产品数据只在 `projects/<id>/`。范例证据与 `原文依据` 里的甲方原件引文不在此列（抄录件怎么写就怎么引，一字不改）。
- 第十层「图文与收束」的收束段（2026-11 T6 起）：五套模板各有一个引用 `十层 十（图文与收束）` 的**可选段**（旧九层拆解没有这一层，默认关闭；开法 `--optional <段字母>`）。段里写 `- 字样置换：是` 时，渲染器把该段引用的第十层行里照抄的 `「…」` 字样统一换成 `「客户品牌字样」` 占位（借创意不复刻品牌）；模板不得写参考片原字。

## 6. 反例（这些不算模板）

- 只有自然语言描述、没有 `### 第 N 段：` 和四要素字段的文件。
- 段落来自模型经验而非范例：只要有一段拿不出 3 条带 Part 号的原文，就不收。
- 把九层 IR 直接当模板：九层是中性中间表示，模板是“怎么把它讲成一段提示词”，两者不能合并。
- 用 JSON/YAML 描述段落的模板：结构由固定标题承担（项目硬约束 2）。
